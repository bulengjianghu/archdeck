# ADR-0050：面板信息骨架——五段通用骨架、视角敏感段、异常段与头部槽位

- 状态：已采纳，已实现（波 0b 原型：模块面板与系统面板；其余面板波 2 铺开）
- 日期：2026-10-28
- 决策人：项目负责人（2026-10-28 指令立项「面板与显示面板呈现治理」并给出六项审核意见；G11 原型规格由负责人逐条审定）
- 关联：[ADR-0031](./0031-three-views-and-structure-view.md)（三视图与结构视角，本 ADR 归位其插节）、[ADR-0032](./0032-module-surface-and-carrier-chain.md)（表面）、[ADR-0037](./0037-select-focus-and-impact-query.md)（影响面查询）、[ADR-0042](./0042-principles-three-levels.md)（说明 = 职责 + 原则）；`docs/system/seeing.md` §4；规则 V15、V15a、V15b、V15c（新增）、V6（修订）、V13（不变）（02）；需求 01 §4 面板表（修订）；第十五轮候选 G11、G12、G15（00-candidates §4）

## 背景

 seeing.md 四定律作用于画布侧已拿齐治理（F16 注记位置表、F11 线的预算、L26 标签位），面板侧只有 V13 / F15「说明」置顶一条排序纪律。实测问题：

- 模块面板常显节 14–17 个，首屏读不到「有什么不对」——违规、环、未证实散在「架构治理」「交互图互查」等深处，要滚动、要展开才能发现。
- 结构视角把「结构」「表面」「相关决策」插在「说明」与「对外接口」之间（出自 ADR-0031/0032「指标紧跟职责」的动机），seeing.md §4 的模块行没有视角维度，表与实现分歧；②④ 两段在不同视角下应该装什么没有规则。
- 模块头部徽标 7 类（ID、类别、状态、核心、标签、变更、确认）没有槽位表与静息态上限。
- 出边 / 入边逐条平铺，一条方向十几行才读完类型构成。

审核修订的主线：**按架构师的问题序列拆项，不按组件位置拆项**——选中任何对象，问题串相同：这是什么 → 做什么 / 为什么 → 有什么不对 → 和谁交互、对外暴露什么 → 证据与细节；位置记忆（稳）要跨对象类型成立，故一个通用骨架、不做 12 张表。SP1 的「建立或纠正」：② 段建立心智模型，③ 段纠正心智模型。

## 裁决

1. **五段通用骨架**（V15）：① 头部 → ② 作用 → ③ 需要注意 → ④ 边界 → ⑤ 证据与细节；段序对所有对象一致，不适用的段不出现；同类节跨面板同位。
2. **视角敏感段**：② 与 ④ 随视角装内容。结构视角 ④ 依次为对外接口、子模块、出边 / 入边、端口、结构指标与影响面、表面——原先插在「说明」与「对外接口」之间的节归位到 ④；ADR-0031「指标紧跟职责」的动机以「指标贴 ④ 段内结构块首」（先于表面）保留。交互视角 ④ 为对外接口、子模块、出入边、端口。运行视角 ② 为「在这次流程中做了什么」、模块信息整体折叠在下——V6 由运行视角特例推广为三视角共用规则的运行视角实例，运行视角呈现不变。
3. **③ 异常段**（V15b）：每类异常一行、带计数，全部无异常整段不出现；单击跳到对应节（折叠节自动展开并滚动到位）；清单与计数全部来自现有派生、不新算——违规、模块环（Y 系列）、本层环（Y4 / Y5，与模块环各自一行、各自计数）、未解释的交互、未证实（K6）、确认过期、拆分信号、逆稳定、表面提示（越过入口 / 热表面未声明）；系统面板为确认过期与治理类计数（G22 的源码落后提醒留在页面级信息条，不进面板，两者不重复）。严重度排序：**违规、环 > 未解释、未证实 > 确认过期 > 拆分信号、逆稳定、表面提示**（排序为「议」，出图后负责人定稿）。为 F6 所有权信号预留行位。这是画布不变式「例外照画、成组带计数」的面板版。
4. **④ 出入边汇总**（V15c）：每方向先一行按类型汇总（如「查询 5 · 委托 2 · 通知 1」，只列非零类型），展开才逐条；保留跨层定位（N3，画布一跳给不了的）。
5. **⑤ 折叠带计数**（V15c）：证据与细节默认折叠、折叠必有计数（O11 的面板版），count 为 0 的节不出现；入口文件并入「源代码文件」节；出处 footer 常显在最底。
6. **① 头部槽位表**（V15a）：次序 ID → 类别 → 状态 → 核心 → 标签 → 变更 → 确认（系统面板 ID → 系统 → 确认）；每槽至多一项；标签槽静息态至多 2 个，其余收「+N」（悬停看全量、单击展开）。仿 F16 的办法定槽与上限；槽位与上限为「议」，出图后负责人定稿。
7. **原型先行**：先在 ModulePanel 与 SystemPanel 出图复核（本 ADR），定稿后再铺开其余面板；StepPanel（D-5 的「作用 → 输入 → 输出」）是骨架的现行实例，铺开时以它校准。健康度指标的分组裁剪、拦截记录 / 外部依赖折叠、ModuleStructure / ModuleSurface / ModuleSource 内部的二级折叠属波 2（G12），本波不动。

## 实现要点

- ③ 段是独立组件（NoticeSection）：面板从现有派生（facts.moduleDetail、isolatedOf、againstOf、splitOf、surfaceMetricsOf、review.of）取数，给出 `{ key, label, count, target, to }`，组件统一过滤零计数并按严重度排序；跳转经 `panelNotices.ts` 的目标记录完成「展开折叠节 + scrollIntoView + 闪一次」，换选中即失效。
- ⑤ 段各子组件（相关决策、知识、治理、拆分信号、演化、源代码文件、入口导出、确认的 diff 与表单）加 `fold` 透传；演化只在有统计且修改次数非 0 时出现。运行视角下 ⑤ 的折叠由「模块信息」外层 details 代行（V6）：内层不再叠加一层折叠，外层展开即 ⑤ 全展开（评审轮 1 B1）。
- ③ 的环计数拆为两行（评审轮 1 A2）：模块环（`facts.moduleDetail().cycles`，Y 系列）与本层环（`facts.selectedCycle`，Y5）各自计数、各自跳「架构治理」，两类同时存在时 ③ 出两行。
- L30 计数回归注意：面板新增跨子系统的 import 会新增代码事实的束、把 present.panel 层的重合数推高 1——新增内容块归 `present.panel.content`（类型汇总的标签表经它转出），不在面板本体直连呈现共用件之外的新子系统。

## 代价与未决

- ③ 的严重度排序、① 的标签上限（2）为「议」，随波 0b 截图交负责人定稿。
- 「相关决策」归 ⑤（本 ADR 采用）还是 ④，与 ④ 段内部次序（指标贴结构块首）一起在出图复核时确认（00-candidates §6 第 1、2 项）。
- 常显行数上限数值未定：G15 已立基线测量（e2e/panel-metrics.spec.ts），波 2 铺开后由负责人定上限、此后行数只许从常显挪进折叠、不许净增。
