# ADR-0019：只读原则放宽——页面可追加人拥有的文件

- 状态：已采纳（已实现）
- 日期：2026-10-22
- 决策人：项目负责人（裁决 D，2026-10-22）；写入细则（B2–B5，来源「议」）由实现者提出
- 关联：规则 B1–B5、G8、U5；需求 SR-4、DV-2、GV-11、01 §5「写入范围」；修订 [ADR-0007](./0007-source-files.md) 结论 3；[ADR-0020](./0020-local-workbench.md)

## 背景

ADR-0007 结论 3 选了「页面不写任何文件」：处理未归属文件、加例外、写评审意见都要离开工具去改 YAML。审查发现这是闭环在工具外断开的地方之一：工具已经把问题列清楚（未归属文件、违规、待评审的设计轮次），但最后一步——由人做出的判断——仍要换到编辑器里完成。而这三类判断的结果都写在**人拥有的文件**里，不会与 AI 重新生成冲突。

## 结论

1. **按拥有者划分**（B1）：AI 生成的部分（`modules/`、`scenarios/`、`actors.yaml`、`system.yaml`、设计各轮快照）页面仍只读；人拥有的三类内容页面可以**追加**：
   - 设计某一轮的评审意见：`design.yaml` 的 `feedback`（设计面板「记录评审意见」，B2）；
   - 架构规则的例外：`rules.yaml` 的 `rules.allow`（违规详情「加例外（写理由）」，理由必填，B3）；
   - 源码忽略项：`source-ignore.yaml` 的 `sourceIgnore`（文件面板「加入忽略」，B4）。
2. **只追加，不删改**：页面不提供删除、修改；删例外、收窄忽略仍由人编辑文件。
3. **写后不改视图状态**：开发服务器的文件监听推送变化，页面按 N5 重新加载，与 AI 改描述同一条路径。
4. **安全边界**（B5）：端点只收同源 JSON POST；ID 校验后拼路径；用 YAML 文档模型修改，保留注释；文件解析失败时拒绝写。

## 选项

| 选项 | 内容 | 结论 |
|---|---|---|
| A | 维持只读，只提供「复制 YAML 片段」 | 未选：仍要离开工具；返工清单已提供片段给 AI，人的判断仍断在工具外 |
| **B** | **按拥有者放宽：只追加人拥有的三类内容** | **采纳** |
| C | 全面可写（含画布内编辑模块与关系） | 未选：与 AI 生成的描述冲突，属于后续方向 C-12 |

## 后果

1. 接入层新增「描述写入」（`vite/writeModel.ts`），ModelSource 插件挂载 `POST /write/<项目>/feedback | allow | ignore`；视图状态层新增同步适配器「描述写入同步」（`ModelWriter`，项目视图注入 HTTP 实现）。
2. 04 §1 列出每个文件的拥有者；ADR-0007 结论 3 的原选择与理由作为历史保留。
3. 本工具只在本地开发服务器上运行（ADR-0020），写端点不会暴露到部署环境。
