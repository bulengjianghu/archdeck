## 背景

第十八轮走查第三条：系统与模块的核对卡治理后，理解卡成了新的重点。以 media-web-player「自建时钟族」为例：

1. **视觉层级倒置**：问题标题「怎么分 / 对外表面 / 协作 / 守住什么」11px 浅灰、正文 12.5–14px 深色，「原则」标签比正文还小——五问的结构看不出来。
2. **到处截字**：一张卡 8 处省略——原则收成两行（关键半句被吃掉）、6 条子模块一句话 5 条截断、子模块名与接口名截断、9 行协作目的 6 行截断。文字在、读不到。
3. **子模块的一句话是第三份拷贝**：画布节点上写了、子模块自己的卡也有，父模块面板再列 8 行，把「怎么分」挤满。
4. **分层说不清**：画布按值依赖算出 4 个深度带并标明「是证据，不是分层（ADR-0052）」「本层未声明分层」，面板对此一字不提——原则是什么（这个模块没声明，ST-1 说 >7 应当处理）、新模块归哪（归属判定 admits 只在悬停）都看不到。
5. **没有「最先看什么」**：五问平铺、等权、全截断。

## 结论

### 0. 理解卡的准入三问（PC-13 的理解卡面）

1. **画布上已经有了吗？** 节点上写了子模块的一句话、线画了协作、记号画了端口——不复述（C2 从位置扩到文字）；面板只给画布没有的：原则、层的问题与归属判定、不变式、协作的目的、接口名。
2. **这句话决定判断吗？** 决定「是什么 / 不是什么 / 归哪 / 不能破」的全文显示、不截字（L46 的口径：超出的是描述写长了，按 04 改描述）；不决定的进悬停或折叠。
3. **是结论还是清单？** 结论直接写；清单按层分组、只写名字、长了折叠。

不变式：标题的视觉权重 ≥ 正文——问题标题 12px 半粗与正文同色，正文 12.5px，职责 14px 粗；`Section` 的节标题同步改为与正文同色。

### 1. 五问改写（PC-3 修订）：意图在先、边在后

| 问 | 内容 |
|---|---|
| ① 是什么 | 一句话职责（粗体）+「全文 ▸」 |
| ② 不是什么 | **否定边界**（M33）：`excludes` ≤ 3 条「不负责什么 → 去向模块」，去向是链接（单击选中）；单成员层的「不包含」同一字段同一行 |
| ③ 怎么分 | 原则全文（不收行、不截断、不带标签）；声明了分层时每层「层名 · 层的问题」加「归属：admits」一句与成员名；未声明时写明「未声明分层 · N 个子模块」，≥ 7 个子模块且 ≥ 3 档时按画布同一套依赖深度（`levelTiers`）分组列成员名，不足时平铺——都只列名字，一句话在悬停 |
| ④ 守住什么 | 不变式 ≤ 3 条，带 ADR 链接（原 ⑤ 上移） |
| ⑤ 对外表面 | 接口名全文一行（端口小徽标），用途进悬停，单击展开签名与说明；> 5 收「+N」 |
| ⑥ 协作 | 缺省折叠为一行「▸ 协作 N ← a · → b」；展开后每行「← / → 对端 ×N 目的」，目的全文换行、类型与条数在悬停（PC-4、PC-5 不变） |

单成员层的「包含 / 不包含」折叠块只留层的问题、归属判定与包含（不包含已在 ②）。

### 2. 否定边界（M33，round19 V3）

…（字段已有，ADR-0052 给层的「不包含」同一字段）：≤ 3 条「短语」或「短语 → 模块 ID」，写「别人容易以为是它的」，不写显然无关的；进确认指纹（Z2 已含）。
- lint：核心模块缺失给 info `module.excludes-missing`；超过条数 `module.excludes-many`；去向不是模块 `module.excludes-target`（都不计入提醒数）。
- `arch place` / MCP `place` 扩到**未分层**的父模块（ST-2 扩展）：已分层的照旧按各层的 admits；未分层的按子模块一句话职责的字面重合度排序，父模块 excludes 写了去向且与职责文字重合的直接给出去向（`excluded`）。
- 内容：自项目先补（`present.canvas`、`state.desk`、`model.governance` 三个核心模块示范），其余核心模块的 excludes 按项目补（info 提示驱动）。

### 3. 三卡一屏（PC-7 修订、CD-2 间距）

- 核对卡：条目的全卡预算——每行至多 5 条不变，全卡缺省至多 8 条（按行序分配），其余一键「+N 全部条目」展开；底部清单整块收进「证据与清单 · N」（details，缺省折叠），条目跳转时自动打开祖先（V15c 的折叠清单不变、计数不变）。
- 相关资料卡：条目多于 3 份时缺省收起、卡头给「N 份」（PC-9 修订）；≤ 3 份展开。
- CD-2 间距收紧：卡内行高与内边距按一屏目标微调（列表项 22 → 20px 行距等）。
- 实测（1440×900，19 个模块样本，走查分支）：理解卡 283–793px 全部一屏内；三卡合计 7/19 一屏放下——超屏的量与条目数（真实问题数，PC-2 让问题优先）与描述长度（原则超一句、成员多）成正比，属内容问题不是版式问题；核对卡收起（全 ✓）或手动收起时全部一屏。

## 否决的方案

| 方案 | 为什么不 |
|---|---|
| 保留子模块一句话、只把字号调大 | 8 行截断依旧，第三份拷贝还在；「压缩」靠少而准的名字加结构 |
| 原则仍收两行 | 它是「凭什么这样分」的裁决依据，正是第 4 点缺的东西；长了按 04 改描述 |
| 「不负责」等 round19 整轮再做 | 字段、指纹、schema 都已在（ADR-0052 给层做的），差的只有取值、lint、place 与卡上一行；它是第 4 点「归哪」的另一半 |
| 协作不折叠、只截短目的 | 与画布完全重复的 9 行是卡里最长的一段；缺省一行加展开已经把「要用时一步到」保住 |

## 后果

- 理解卡 0 处截断；每问有标题、标题不小于正文；「是什么 / 不是什么 / 怎么分 / 守住什么」一屏内读完。
- 「新模块归哪」在卡上可答：分层的看每层的归属，未分层的看「未声明分层」与深度分组，核对卡的拆分行给 ST-1 提示，`arch place` 对未分层父模块也能给建议。
- 组件：`ModuleUnderstand.vue`、`ModuleCollab.vue`、`CheckCard.vue`（条目预算、证据与清单折叠）、`RelatedCard.vue`（缺省收起）、`Section.vue`（标题层级）、`ModuleCheck.vue`（拆分行 ST-1）；模型层 `contract.excludesOf`、`governance.placeSuggestion`（children 模式）、`validate` 三条 info、`state.desk.facts.childTiers`；`tierBandLabel` 上收到模型层（画布与理解卡同一句，C1）。
- E2E：`openCheckList` 打开「证据与清单」；新增 `openPanelLists`、`openRelated`；cards CD-4 改用内容长的 DeskState 面板。
- 描述：自项目三个核心模块补 `excludes` 示范；其余核心模块由 excludes-missing 的 info 驱动逐项目补。

## 待裁（「议」规则）

- 五问次序（② 不是什么在 ③ 怎么分前、④ 守住什么上移）——原 PC-3 为 ①–⑤ 固定次序。
- 条目全卡预算 8、相关资料卡的 3 份阈值、成员名单的 12 个上限。
- 协作折叠为缺省态（展开记住到换选中为止）。
- excludes 条数 3 与「去向必不强制」沿用 round19 D3 的推荐。
