# ADR-0008：运行视角聚焦端到端——泳道按层次、焦点突出、分支直选、静态关系按需、面板浮动

- 状态：已采纳；结论 5 的浮动面板与信息卡（及结论 1 中泳道的信息卡）已被 [ADR-0009](./0009-sequence-readability.md) 取消
- 日期：2026-10-21
- 决策人：项目负责人（五项方向与三处裁决，见「结论」）；实现者提出的细化规则（来源「议」）列在下文，负责人已全部确认（2026-10-21）
- 关联：需求 D-2、D-5、D-17–D-19、W-1、W-8、W-9，验收标准 §6.5；领域模型 §2（L4、V5、V8、V9、P9、P13、R15、F6e、F6f、F7）；ADR-0003、ADR-0006

## 背景

二期上线后，负责人对运行视角提了五条意见：

1. 时序图的泳道按结构图的横坐标排，和模块所在的层次对不上，也看不到泳道属于哪个父模块、哪一层。
2. 当前步骤只是换了颜色，其他步骤仍是彩色，区分不明显；面板没有先回答「这一步做什么、输入什么、输出什么」。
3. `alt` 的未选分支虽然淡化画出，但切换入口分散（停在分支点时的选择器、数字键、步骤树、点未选分支上的消息），也看不到整条路线选了什么。
4. 运行视角关心的是场景的端到端链路，结构图上不相关的模块和静态关系是噪音，应在需要时再看。
5. 屏幕空间有限，属性面板常驻一栏挤占画布。

## 结论

负责人在讨论中做了三处裁决：

- 运行视角下，不参与场景的节点和静态边一起隐藏。
- 面板采用「信息卡 + 浮动模式」，不做在点击位置展开完整面板。
- 泳道顺序以层次为准，结构图的边界节点也按同一顺序排。

### 1. 泳道按层次排序并显示所属（P9、P13、L4）

- **排序**：参与者固定在最左。其余泳道从模块树的根开始，逐级比较各自的祖先：
  - 同一父模块下，层按 `order` 排；
  - 本层子模块按结构图中的横坐标排（同一父模块内没有层次差别，横坐标能让两张图左右一致）；
  - 其他情况按描述顺序排。

  这样排的结果是：同一父模块的泳道相邻，上层（`order` 小）的排在前面。
- **分组框**：同一父模块的相邻泳道，头部上方画一个分组框，标父模块名。
- **信息卡**：悬停泳道头显示信息卡，内容为完整路径、所属层、类别和职责摘要。
- **结构图对齐**：边界节点行原来按所连内部模块的平均横坐标排，改为与泳道相同的层次顺序（L4），两张图的外部模块顺序因此一致。代价是边界边可能多一些交叉，但边界边默认不画，影响小。
- **按知识划分层次**：「模块在层次中的先后」是关于被描述系统的知识，由模型层算出排序键（`hierarchyKey`），Projector 与时序模型共用。「本层子模块用横坐标」只与这次排布有关，留在时序图排布里。

### 2. 焦点突出与步骤面板（R15、F7、D-5）

- **焦点突出**：运行视角下，时序图与结构图跟着焦点（V2）突出相关内容：
  - 跟随时，突出当前可见消息，以及与它配对的调用或返回；
  - 钉住时，突出焦点参与的可见消息（参与查询，V6）。

  其余消息与走过的边统一淡成灰色，未选分支和未到达的更淡。停在开头时没有要突出的消息，不淡化。
- **调用与返回配对**（F7，模型层）：显式 `return` 与它回应的 `call` 配对。步骤面板据此给出「输出」，时序图据此同时突出一对消息。
- **步骤面板重排**，先回答「这一步做什么」，顺序为：
  1. 作用：标签与说明；
  2. 输入：本步携带的数据；
  3. 输出：配对返回的数据；异步写「不等待返回」；没写显式返回时，指向接口签名；
  4. 数据结构：可展开看定义；
  5. 经由接口；
  6. 端点与本层投影；
  7. 结构关系：默认折叠，见结论 4；
  8. 出处。

### 3. 分支直选与路线总览（F6e、F6f）

- **在时序图上直接选分支**：`alt` 组合框的每个分支条件都是可单击的页签，单击即改走这一支。任何 `alt` 都可以这样选，不管它是否在当前路径上：
  - 不在路径上时，按 R13 的方式补齐到达它所需的选择，再选这一支。
  - 播放头仍在新路径上时不动；不在时，退到该分支点之前，下一步就进入新分支。
- **路线总览**：回放控制条常驻显示当前路线，即路径上依次经过的分支点及所选条件，也包括截止处待选的分支点。每一项都可下拉改选。改选丢弃了其后的选择时，提示丢弃了几个（F6b 原来是静默丢弃）。
- 停在分支点时展开全部选项的选择器保留（F6）。路线总览与它是同一套操作，只是常驻。

### 4. 运行视角下静态关系按需呈现（V5、V8、V9）

- **舞台默认只显示参与本场景的内容**：节点为本层全部分支的帧端点，边为走过的、当前的、预览的边。其余节点与静态边隐藏，布局不变（隐藏是渲染层面的，不重新排布），适应画布时只按可见内容取外框。
- **静态关系的显示方式**分三档：隐藏（默认）、淡显（原 V5 的效果）、全显。在画布上切换，按项目记在本地，不进视图状态与 URL，与分屏方向同类。
- **从面板引用静态关系**：步骤面板与钉住对象面板的「结构关系」默认折叠，展开后可以「在画布上显示」：
  - 步骤：显示当前消息两端节点的全部静态边及对端节点；
  - 钉住的模块或参与者：显示它在本层节点的全部静态边。

  移动播放头、焦点改变或切换层次后自动收回。

### 5. 属性面板可浮动、信息卡、专注（W-1、W-8、W-9）

- 属性面板有两种形态：
  - **固定**（默认）：占一栏，与现在相同；
  - **浮动**：叠在画布区右侧，不挤占画布宽度，宽度仍可拖动。

  形态与收起状态记在本地（收起状态原来不保存）。
- **专注**：一键收起导航树与属性面板，再按一次恢复。
- **信息卡**：悬停时序图的泳道头或消息片刻后弹出，移开即消失，不改变焦点。内容只是摘要，完整内容仍在面板：
  - 泳道：名称、类别、完整路径、所属层、职责摘要；
  - 消息：类型、两端、作用、输入与输出摘要。
- 未采纳的做法是在点击位置展开完整面板：会挡住刚点的内容，位置每次都变，长内容（Markdown、数据结构、源码）也放不下。

## 实现者提出的细化（来源「议」，负责人已确认）

| 规则 | 细化 | 理由 | 被否决的选项 |
|---|---|---|---|
| P13 | 分组框按「泳道模块的父模块」分组，只给连续的泳道画；参与者不分组；所属层取模块自身或最近的 `kind: layer` 祖先 | 泳道已按层次排序，同一父模块必然相邻；连续分组不会出现交叠的框 | 按所属层分组（同一层下可能隔着多级父模块，分组太粗） |
| V5 | 分层总览中带（层）始终显示，只隐藏不参与的核心模块；当前父模块的边界框与内部结构框保留 | 带是分层总览的骨架，隐藏后看不出层次；边界框说明了舞台的范围 | 带也按参与隐藏 |
| V5 | 只出现在未选分支或未到达部分的节点照常显示，但淡化 | 节点集合不随分支切换变化（与 P12 一致），切换分支时画面不跳 | 只显示当前路径的端点 |
| V9 | 「在画布上显示」是临时的，播放头、焦点、层次任一变化即收回；不进 URL | 它服务于「看一眼这一步在结构上连着谁」，长期显示用 V8 的淡显 / 全显 | 一直保留到用户手动关闭 |
| F7 | 配对按书写顺序以栈匹配：`call` 入栈；显式 `return`（X → Y）匹配栈中最近的「Y → X」调用，并弹出它之上的调用（它们没有显式返回）；`alt` 各分支从进入分支点时的栈开始，分支内未配对的调用在分支结束时丢弃；`async` 不配对 | 与时序图的嵌套书写习惯一致；描述中的显式返回多跨越 `alt`（如「命令执行」），按栈匹配能配上 | 只与紧邻的上一条调用配对（跨 `alt` 时配不上） |
| R15 | 钉住文件时不突出任何消息（文件没有参与查询）；突出时未选分支、未到达的消息仍按原样更淡 | 文件不是帧端点；未选分支的淡化要与路径上的淡化区分开 | — |
| F6e | 改走另一支后播放头不在新路径上时，停在该分支点之前的最后一帧（落在其可见消息的第一帧）；分支点之前没有帧时回到开头。原来是一律回到开头 | 用户刚表达了「要走这一支」，下一步就该进入它，而不是从头再来 | 回到开头（原行为）；跳到新分支的第一帧（空分支时无处可跳） |

## 后果

1. P9（泳道按横坐标排序）与 V5（其余变淡不隐藏）被改写；L4 中边界节点的排序方式被改写；F6b 的「改选丢弃其后的选择」不变，但会给出提示（F6f）。
2. 需求、领域模型、架构按最终态改写。本项目的架构描述 `model/h5p-arch-desk/` 按代码重新生成。
3. 以后的自由分屏（§7 后续方向）可以把浮动面板也纳入布局树；本轮浮动面板仍由项目视图单独管理。
