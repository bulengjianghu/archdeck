# ADR-0009：时序图可读性——泳道互不包含、头尾固定、按需滚动、步骤继承接口与数据、取消悬停弹出与浮动面板

- 状态：已采纳
- 日期：2026-10-21
- 决策人：项目负责人（五项方向）；实现者提出的细化规则（来源「议」）列在下文，负责人已全部确认（2026-10-21）
- 关联：需求 D-2、D-5、D-7、W-1，删除 W-8、W-9；领域模型 §2（P3、P7、P13、P14、S14）；描述格式 §消息步骤；ADR-0008（部分取消）

## 背景

ADR-0008 上线后，负责人在使用中提出五条意见：

1. **父模块和子模块并列成泳道**。分层总览下，「视图状态层」和它的核心模块 DeskState、视图状态转移各占一条泳道。原因有两个：
   - 落点规则先判「两端在同一个层内」，再判「是否落在核心模块」。所以同一层内两个核心模块之间的调用，被画成了层的内部活动。
   - 结果是同一个模块有两条泳道：跨层消息画在它自己的泳道上，层内消息画在层的泳道上。
2. **泳道头随内容一起滚走**。滚到下面就不知道每一列是谁。
3. **时序图频繁自动滚回当前步骤**。正在滚动查看时也会被拉回去。根因是悬停会改视图状态，而层次视图的派生直接读整个视图状态，于是时序模型和坐标整条链重算，触发「当前步骤滚到可见」。
4. **步骤面板缺少参数和数据**。例如「openScenario(id)」带了参数，面板上却什么都没有。核查本项目的描述，场景「打开场景并回放」的全部步骤都没写 `interface` 和 `payload`；而它们对应的关系大多写了。
5. **悬停弹出体验不好**：时序图的信息卡、结构图节点的原生提示框都是。属性面板的浮动形态也用不上，展开收起已经够用。

## 结论

### 1. 泳道互不包含（P14，改 P3、P7、P13）

- **不变式**：同一张时序图中，任意两条泳道互不包含，一个模块只对应一条泳道。
- **分层总览的落点先看核心模块，再判内部活动**：
  - 两端落在同一个核心模块，是该核心模块的内部活动。
  - 两端落在同一层的不同泳道（核心模块之间、核心模块与层内其他模块之间）：时序图上画成这两条泳道之间的消息，结构图上仍按层的内部活动高亮这条带。分层总览不画层内关系，所以不判为「结构中未建模」。
- **「其他」泳道**：层有核心模块时，层自身的泳道只代表层内的非核心模块，名称为「<层名> · 其他」，放进该层的分组框，排在核心模块之后，对应结构图上的「+N」。层没有核心模块时，泳道就是层本身。

### 2. 泳道头固定，首尾各一份（D-2）

- 泳道头固定在时序图顶部，不随内容纵向滚动；底部再放一份泳道头，消息区夹在两者之间滚动。
- 横向滚动时，头尾与消息区一起移动。分组框只画在顶部。

### 3. 只在用户移动播放头时滚动（D-7）

- 单步、指向某一步（单击消息、步骤树、结构图上的步骤序号、运行信息中的步骤）、拖动进度、回到开头之后，当前步骤滚到时序图的纵向中间。
- 其余变化不自动滚动：悬停、切换层次、选中、重新加载、改选分支（播放头不动时）。
- 信息条上加「定位」按钮，把当前步骤滚到中间，作用同结构图的「适应」。
- 同时修掉根因：层次视图只依赖层次、显示开关与场景，悬停与选中不再引起重新投影与重新排布。

### 4. 步骤继承对应关系的接口与数据（S14，D-5）

- **能推出来的不让人写**：消息步骤没写 `interface` 时，取对应关系（显式引用或推断的）的 `interface`；没写 `payload` 时，取对应关系的 `payload`。显式返回不继承 `payload`，因为关系上的数据描述的是调用方向。面板标注「取自关系」。
- **步骤面板的输入**：经由接口时，先显示接口签名中与步骤标签同名的那一行（如 `openScenario(id: string): void`），再列携带的数据。
- **描述**：本项目接口 `DeskState 操作` 的签名改为每个操作一行、带参数类型。场景中对应关系没有接口或数据、而步骤确实交换了数据的，在步骤上补写。

### 5. 取消悬停弹出与浮动面板（删除 W-8、W-9，改 W-1）

- 删除时序图的信息卡（W-9），删除结构图与时序图元素上的原生提示框（节点职责、外部模块路径、步骤序号说明、分支条件说明等）。这些内容都在属性面板上，单击即可查看。
- 删除属性面板的浮动形态（W-8）；保留收起 / 展开与「专注」。
- 泳道的所属父模块由分组框表达（P13 保留分组框，删除其中的信息卡）。

## 实现者提出的细化（来源「议」，负责人已确认）

| 规则 | 细化 | 理由 | 被否决的选项 |
|---|---|---|---|
| P7 | 分层总览中同一层不同泳道之间的消息，结构图上按层的内部活动高亮这条带；两端各自的核心模块小块同时标为活动 | 分层总览不画层内关系，没有边可落；高亮带与小块，能看出是哪两个模块在交互 | 画一条临时连线（与「未建模」临时线混淆） |
| P13 | 「其他」泳道的名称为「<层名> · 其他」，排序键为层的排序键之后接一项最大值，即排在该层全部核心模块之后 | 与结构图「核心模块在前、+N 在后」一致 | 排在核心模块之前 |
| S14 | 继承的只是缺省值：步骤写了就用步骤的；返回步骤只继承接口；继承来的标「取自关系」 | 关系上的数据描述调用方向，返回携带的是结果；标注来源，避免读者以为是步骤自己写的 | 返回也继承数据 |
| D-5 | 签名行按「标签开头的标识符 + `(`」在接口签名中匹配第一处；签名一行写多个操作时，以 `·` 分段取匹配的那一段 | 标签通常以调用名开头（如 `openScenario(id)`），不需要描述里另写字段 | 在描述格式中新增 `operation` 字段 |
| D-7 | 改选分支使播放头移动时（F6e）同样滚到中间；只改选、播放头不动时不滚动 | 播放头移动属于「用户移动播放头」 | 改选分支一律不滚动 |

## 后果

1. ADR-0008 结论 5 中的「浮动」与「信息卡」被本 ADR 取消；ADR-0008 结论 1 中泳道信息卡的部分随之取消，分组框保留。
2. 需求、领域模型、架构、描述格式按最终态改写，W-8、W-9 保留空号。
3. 本项目的架构描述按代码重新生成，并补写接口签名与步骤数据。
