# ADR-0022：关系语义——结构与运行时

- 状态：已采纳（已实现）
- 日期：2026-10-22
- 决策人：项目负责人（关系语义按第一性原理重整，2026-10-22）；实现细化（来源「推」）列在「实现细化」
- 关联：需求 C-7、D-6、GV-2、GV-7；领域模型 §1.1 关系、M7、M11–M13、S5a、S12、S13、K5、K5b、K6、K7、K11、L10、P10、Q7、Q8；[04 §3.4](../04-description-format.md)；ADR-0016（只引类型）、ADR-0018（通道分配）、ADR-0020（K6 分档）；原则上溯：[ADR-0028](./0028-positioning-and-principles.md)（产品定位与原则）

## 背景

一次运行时交互可以从五个互相独立的维度描述：

| 维度 | 问题 | 取值 |
|---|---|---|
| A 控制流方向 | 谁发起 | 发起方 → 接收方 |
| B 知识方向 | 谁知道谁（编译期） | 导入方 → 被导入方 |
| C 交互语义 | 期待什么 | 命令（要结果）/ 通知（不要结果、一对多）/ 流（连续数据项） |
| D 同步性 | 发起方等不等 | 同步 / 异步 |
| E 平面 | 传的是什么 | 控制面 / 数据面 |

A 与 B 可以相反：事件的控制流是发布者 → 订阅者，知识却是订阅者 → 发布者（订阅者导入发布者的事件定义，发布者不知道谁订阅了它）。

旧的类型集合把几个维度混在一起：

| 问题 | 表现 |
|---|---|
| 箭头一半按知识、一半按控制流 | `event` 的箭头画知识方向（订阅方 → 发布方），`calls` 与场景消息按控制流；S12 / S5a 不得不规定「event 的消息方向与关系相反属正常」，结构图与时序图两套读法 |
| 按载荷定义类型 | `dataflow` 用「帧、分片、样本」定义，不是结构属性；什么时候是 dataflow、什么时候是异步 calls 说不清 |
| import 与主张混用 | `implements` 的证实只看有没有依赖，对 B 函数的一次值导入也能证实「实现 B 的契约」 |

## 结论

### 1. 结构图上运行时边的箭头 = 控制流方向

与场景消息同向；知识方向是代码事实，由 `depends` 与面板的「知识」一行表达，不再借箭头。

### 2. 关系类型

| type | 语义 | 方向（箭头） | 运行时 | 平面 |
|---|---|---|---|---|
| `depends` | 编译期知道：导入、引用类型或值 | 依赖方 → 被依赖方 | 否 | — |
| `implements` | 实现契约（端口、接口） | 实现方 → 契约所在模块 | 否 | — |
| `calls` | 命令：请求并期待结果（同步返回或异步回调） | 发起方 → 接收方 | 是 | 控制 |
| `notifies` | 通知：不期待结果、一对多、发布者不知道订阅者 | 发布者 → 订阅者 | 是 | 控制 |
| `streams` | 流：同一通道上连续的数据项，关注吞吐与背压；两端只知道端口、由第三方接线 | 推送方 → 接收方（`pull: true` 为拉取型，箭头仍指数据去向） | 是 | 数据 |

- `notifies` 原名 `event`，**from / to 翻转**；`streams` 原名 `dataflow`。旧名保留为别名：加载时映射（`event` 同时翻转两端）并逐条提醒「请迁移」（M12），一轮后删除。
- 经端口接线的关系可写 `via: port`（K5b 的 `via` 枚举扩展）：两端只知道端口，由组装者接线，静态导入证实不了。

### 3. import 是证据，depends / implements 是主张

一条导入只说明「A 知道 B 的某个名字」。知识有三级阶梯：

| 阶梯 | 代码里看到的 | 对应的主张 |
|---|---|---|
| 只引数据类型 | 只导入 B 的类型（数据结构） | `depends`（K7 不算未描述，ADR-0016） |
| 实现契约 | 导入 B 声明的接口，或类的 `implements` / `extends` 指向 B | `implements` |
| 使用实现 | 导入 B 的函数、类等值并调用 | `depends`（或运行时的 `calls` 等） |

- **K5 对 `implements` 的证据收窄**：依据的文件依赖中至少一条引用了 B 声明的接口名（`interfaces[].owner` 在 B 的子树内，或 B 的 `provides`），或 A 的类声明 `implements` / `extends` 解析到 B 的文件，为已证实；只有别的导入时按导入分档（修订，见下）。
- **`implements` 的目标须声明接口**（M11，与 M7 同级的提醒）：没有声明任何接口的模块无「契约」可实现。
- **端口三角**（K11）：选中声明了接口的模块时，面板列出定义（本模块的接口）· 实现者（入边 `implements`）· 使用者（入边 `depends` / `calls` / `streams`，含经 `via` 的）。

### 4. 呈现

- 色相仍按类型（ADR-0018）：`--rel-event` → `--rel-notifies`、`--rel-dataflow` → `--rel-streams`，色值不变。
- 图例三句话：命令 = 要结果；通知 = 不要结果、一对多、箭头指向被通知方；流 = 连续数据、箭头指向数据去向。
- 关系面板「关系」一节按五个维度各一行：控制流、知识（由代码事实给出：同向 / 反向 / 经端口 / 不判定）、语义、同步性、平面。
- 回放与时序图的箭头样式（D-6）不变；消息与关系同向，P10 的「可与边的箭头相反」只剩 `return`。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 只改定义文字，保留 `event` / `dataflow` 的名字与 event 的箭头方向 | 结构图与时序图仍是两套读法，S12 的特例留着；名字不说语义（dataflow 仍按载荷理解） |
| 把通知、流并入 `calls`，只用 `mode` 区分 | 丢掉 C、E 两个维度：一对多与「不要结果」、数据面的吞吐与背压在图上不可见；`calls` 的箭头对事件仍要么指错控制流、要么指错知识 |

## 实现细化（来源「推」）

1. K5：`notifies` 与 `streams` 两个方向的依赖都算证实（通知的知识方向通常与箭头相反；流由第三方接线，谁导入谁不定）；K7 的覆盖同理不论方向。
2. 面板「知识」一行由证实依据的模块依赖方向给出：与箭头同向 / 反向 / 两个方向都有；未证实但两端之间有依赖时按 K6 给「反向或经组装」；写了 `via` 时为「经端口」（`port`）或「不判定：经 …」；概念拆分、目标态、参与者、没有代码事实时为「不判定」。
3. `pull` 只对 `streams` 有意义，写在其他类型上提醒并去掉（M13）。
4. 文件依赖记录落到该目标的导入名与是否被类的 `implements` / `extends` 引用（K1），供 K5 的 implements 证据使用；违规键、环与基线不受影响。
5. 描述迁移用一次性脚本完成（YAML 文档模型只替换类型与两端的值、保留注释），含设计版本各轮——它们要在别名删除后仍能打开；`description` 里有方向字样的条目列出后人工核对。此后残留的旧名由 M12 在加载时映射并提醒，按提醒手工改。

## 后果

- 描述迁移：h5player 40 条 `event` 中 28 条按「订阅方 → 发布方」写的翻转为 `notifies`，12 条原本就按控制流写的只改类型，10 条既订阅又发布的另拆出发布关系；31 条 `dataflow` 改为 `streams`；h5p-arch-desk 当前版本 2 + 6 条，设计版本 phase2-dynamic 各轮 8 + 16 条。迁移由一次性脚本完成后即删除，不是产品能力。
- S12 / S5a 的 event 特例删除，`bindRelation` 只为 `return` 反向比对；S13 推断只看三类运行时关系。
- 原本被一次值导入「证实」的 `implements` 变为「证据像 depends」或「结构性实现」，前者需要逐条按代码改为 `depends` 或补接口声明。
- 违规键不含关系类型，h5player 的基线不变。

## 修订：implements 的证据三档（负责人 2026-10-22）

负责人核实了 h5player 三条「证据像 depends」（rel.sd.stat-impl、rel.factories.base-ports、rel.strategies.vod-load-contracts）：都是真正的结构性实现，只是 TS 不要求写 implements 子句、代码只引了对方的数据类型。描述不改，改 K5 的分档：

| 档 | 代码里看到的 | 结论 | 严重度与建议 |
|---|---|---|---|
| ① | A 引用了 B 声明的接口名，或类 `implements` / `extends` 解析到 B | 已证实 | — |
| ② | A 对 B 只引数据类型（类型、枚举），没有引用函数、类或变量 | 结构性实现（代码未显式声明），`fact.structural` | info，不报 lint 问题、不进角标；返工清单建议「在类上加 implements <接口>」，列出 B 声明的接口候选 |
| ③ | A 引用了 B 的函数、类或变量（或不按名称穿透的值导入） | 证据像 depends，`fact.like-depends` | warning，建议「改为 depends」或补接口声明 |

实现细化（来源「推」）：枚举虽是值，但属于数据类型，归 ②（Statistic 只引了 model.ts 的枚举与类型）；文件依赖为此记 `uses`（落到目标的值导入名声明为函数、类或变量）。h5player 三条落到 ②，lint:model 提醒 316 → 313。
