## 背景

负责人 2026-10-25 的两轮讨论提出三点：

1. **结构图展开表面，不展开内部。** 一条依赖边到底依赖了被依赖方的什么？第七轮只到模块对，要知道得翻面板里的文件依赖清单。架构师的心智模型是「块与把手」：块是模块，把手是它对外露出的东西——入口导出的符号与声明的接口。把手在图上，块的内部（类、函数体、私有数据结构）不在。
2. **每条交互必有承载，承载是路径，不是直接依赖。** 第七轮的包含链「交互 ⊂ 依赖」只认「发起方 → 接收方」的直接依赖（K5）；经端口的交互背后是「发起方 → 端口定义模块」加「接收方实现端口」加「组装者组装接收方」，经总线的是「两端各自依赖总线」，回调注册的依赖方向与控制流相反。这些都被标成「不判定」或「有依赖可解释」，包含链在最有架构含义的地方断了。
3. **交互按种类成束，但束要能打开。** 一对模块之间可以有多条委托（「委托做任务一」与「委托做任务二」是两个通路），画布按种类成一条束；束必须能散开到各自的接口，否则两条通路在图上永远分不开。

第七轮的事实已经足够：入口（G10）、导出（G11）、导出与接口的对应（G12 `matchExports`）、每条文件依赖的导入名 `names`（K1）与再导出穿透（K3）。缺的是把它们接成「依赖 → 表面元素」与「交互 → 承载路径」两层。

## 裁决

### C. 模块表面

| # | 裁决 |
|---|---|
| C1 | **表面元素**：模块入口（G10）导出的符号（G11 `ExportedSymbol`，再导出按 K1 / K3 穿透到声明文件）与描述声明的接口（04 §3.3 `if.*`）。两者按现有 `matchExports` 匹配：已声明且导出 / 导出未声明 / 声明未导出 |
| C2 | 元素四类：**端口**（声明的接口，含 `implementedBy` 或被 `via: port:` 引用的）、**操作**（函数、可调用常量、类）、**类型**（interface / type）、**数据**（枚举、纯数据常量）。namespace 导入与 `*` 视为「整模块」，不接到元素 |
| C3 | **依赖接到元素**：文件依赖的 `names` 与被依赖方入口导出匹配 → 每个匹配的元素一条元素级边（ADR-0031 修订 A1）；`to` 文件不是入口（深层导入）→ 记为**越过入口**，接到模块本体、带记号。同一文件依赖可以同时产生元素级边与越过入口边 |
| C4 | **事实上的表面** = 被其他模块实际依赖的元素集合；**声明的表面** = 接口。差集给三种信号：越过入口（U18）、热表面未声明（导出未声明且被 ≥ 3 个模块使用，建议声明接口，U19）、声明无人用（沿用 U14 `port.no-user`）。U18 / U19 为 info，不进门禁，进问题页签；阈值常量 `HOT_SURFACE_MODULES = 3` |
| C5 | **指标**：表面宽度 W = 被外部引用的不同元素数；越过入口数 B = 越过入口的文件依赖条数；每个元素的扇入 = 使用它的模块数。与 Ca / Ce / I 并列进 `structureMetrics`、面板与 `arch metrics`。新增 `arch surface <module>`（Q16）与同名 MCP 工具 |
| C6 | **画布**（只在结构视角）：节点缺省不画元素，只在角标里加「表面 W」（与「入 · 出」同一行），入边以束画。展开时元素作为 elk 端口排在节点入边一侧，束散开为元素级边接到各自元素，越过入口的边接到节点本体并带记号。展开触发：选中模块 → 展开它；选中结构边 → 展开两端中被依赖方的相关元素；显示偏好「总是展开表面」（`surfaceAlways`，缺省关）。展开改变节点尺寸，本层重新布局，等同下钻，不算违反 V12（V12 约束的是视角切换） |
| C7 | **面板**：模块「表面」一节（结构视角，在「结构」之后）：W / B，元素清单（种类 · 声明状态 · 扇入 · 使用它的模块），越过入口清单（依赖方文件:行 → 符号），建议（提升到入口 / 声明接口 / 改经入口）。「端口」一节（K11）保留，端口类元素在两节之间可互相定位 |
| C8 | 设计版本与无代码事实（K8）：表面只有声明的接口，W / B 不给。交互视角不画表面；`via: port:` 的端口记号（L13）不变 |
| C9 | 不新增选中种类：元素可悬停（名字、种类、扇入），单击 = 选中其模块并把面板「表面」一节滚到该元素。URL 不变 |

### D. 交互的承载链

| # | 裁决 |
|---|---|
| D1 | 一对模块之间可以有多条交互（单位：发起方、接收方、种类、接口）；画布按种类成束、线宽计条数（现状，ADR-0018）。不合并 |
| D2 | 每条交互必有**承载**：结构图上的一条路径，由元素级结构边组成，按交互方式有**模板**——**直接**：A → B 的操作元素；**经端口**：A → 端口元素（定义模块 P）+ B 实现该端口 + 组装者组装 B；**经总线**：A → 总线的发布操作 + B → 总线的订阅操作（B → A 的事件类型可选）；**直接通知**（回调注册）：B → A 的注册操作（依赖方向与控制流相反）；**经通道**：两端各自依赖通道契约。模板是推断，架构师可在关系上写明承载元素覆盖推断 |
| D3 | 承载判定三档：**齐全**（模板各段都有元素级边）、**缺段**（列出缺的段，如声明 `via: bus` 但接收方没依赖订阅操作）、**无承载**。替代 K5 的模块级「有依赖即证实」作为更细的一档，K5 仍是回退（元素匹配不上但模块依赖存在时按 K5 给「已证实（模块级）」）。通道未声明契约模块时标「外部承载，不判定」；`via: channel:<名>` 可加契约模块（`channel:<名>@<模块 ID>`），声明了才核（K6 跨进程缺口的出路） |
| D4 | 呈现用**叠加**，不并排：交互视角选中一条交互（或束中一条）时，承载边临时画在同一画布上并高亮，其余变淡，缺的段画成提示虚线，涉及的第三个节点（总线、端口定义模块）不在本层时在面板里给出定位；运行视角已有的「经由上层关系临时线」（D-6）同一手法。反向：结构视角选中一条束时高亮它承载的交互（K17 覆盖数的明细） |
| D5 | 面板：关系面板「承载」一节（档、各段与元素、缺段建议）；步骤面板包含链（D-25）从模块级改为元素级，「包含链 依赖 ✓」与「代码证据 无证据」的矛盾口径一并消除（第七轮遗留） |
| D6 | lint：`fact.unconfirmed` 增加缺段原因文本；不新增错误级别 |
| D7 | **交互束也按表面散开**（负责人 2026-10-25 追问「委托做任务一与任务二是两个通路」）：模型里 A → B 的每条交互独立（种类 + 接口），画布按种类成束是收起态；展开 B 的表面时，交互束按关系的 `interface` 散开到 B 的对应元素（声明接口 = 端口 / 操作元素），没写接口的交互接到模块本体。线条总是能打开，信息不丢；运行视角的步骤绑定到各自的交互，舞台高亮到元素 |
| D8 | 束内修饰（同步 / 异步、`via`）不一致时束上加「混合」记号，悬停列出；同一束内 ≥ 2 条交互都没写接口时给 info 提示「无法区分通路，建议写接口」（M22） |

## 理由

1. **心智模型按块与把手。** 架构师记住一个模块，记的是它做什么（职责）和别人怎么用它（把手），不是它内部怎么写（原则 SP1）。表面元素正是把手：入口导出的符号是代码事实上的把手，声明的接口是描述主张的把手。结构图展开到把手为止，回答「这条边到底依赖了什么」，又不越过模块边界去画内部。
2. **C4 模型的第四层（代码层）劝退。** 类图、调用图把模块内部摊开，节点数立刻超出带宽（原则 SP4），且随实现细节天天变，心智模型跟着抖。表面是模块边界上的东西，比内部稳定得多；它只在被选中或主动展开时出现，缺省只是一个角标数字。
3. **表面是交互 `via` 与依赖事实的交汇点。** 交互的 `interface` 指向声明的接口，`via: port:` 指向端口，依赖事实的导入名落在导出符号上——三者在表面元素上第一次对上。于是「这条委托经由哪个接口」与「这条依赖用了哪个符号」可以互证，包含链能落到元素级：交互的承载是元素级边组成的路径，不再只是「两模块之间有依赖」。
4. **三种信号把主张与事实的差集说出来。** 越过入口（事实绕开了边界）、热表面未声明（事实上的把手没有被描述承认）、声明无人用（描述的把手事实上没人握）。三者都是 info：它们指出边界不清，不是错误，存量项目里大量存在，进门禁只会制造噪声（原则 SP6）。
5. **叠加而不并排。** 承载与交互画在同一画布、同一位置上，选中一条交互时临时画出它的承载路径，其余变淡——这是运行视角「经由上层关系临时线」已验证的手法。并排两张图要求眼睛在两处对位，ADR-0031 已否决三栏并列；负责人本轮也搁置了结构图与交互图并排对照。
6. **每条交互必有承载，判定分档而不是二值。** 「已证实 / 未证实」把「有依赖但方向相反」「经端口少了组装」「经总线缺订阅」都压成同一种状态。按模板逐段判定，缺哪段说哪段，返工建议才具体；K5 的模块级证实保留为回退，不让元素匹配的盲区（默认导出、动态导入）把已证实的关系打回未证实。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 类图 / 函数调用图进画布（C4 第四层） | 越过模块边界，节点数超出带宽，随实现细节抖动（原则 SP3、SP4）；本工具的单位是模块，内部留给 IDE |
| 结构图与交互图并排对照 | 负责人搁置；对位靠眼睛，代价高；叠加（D4）在同一位置给出同样的对照 |
| 表面独立成图或结构视角独立布局 | 位置不动是对照的前提（V12）；展开表面只改该节点尺寸、本层重排，等同下钻 |
| 元素成为一种新的选中（URL `sel=el:`） | 选中种类已多；元素的问题都在其模块的面板里回答，单击元素 = 选中模块并定位（C9） |
| 数据结构单独成图 | 不做；数据元素作为表面的一类出现即可 |
| 承载判定为新的错误级别 | 存量项目缺段大量存在，进门禁制造噪声；只给 `fact.unconfirmed` 加缺段原因（D6） |
| 合并同一对模块之间的多条交互 | 两条委托是两个通路（D7），合并丢信息；收起成束、展开按接口散开 |

## 已知风险

1. **元素匹配的盲区**：默认导出、`export *` 到非 TS 文件、动态导入、`require` 拿不到名字，只能按「整模块」或越过入口计；承载判定在这些地方回退到 K5 的模块级证实（D3），不会误报，但元素级明细缺失。
2. **展开表面会重排本层**：节点尺寸变化带来位置变化，与「位置不动」的直觉冲突。缓解：只在选中或主动开关时展开，取消选中收起；切换视角不触发（V12 不变）。
3. **模板是推断**：经端口时「组装者组装 B」可能由框架或容器在描述之外完成，模板会报缺段。缓解：缺段只进原因文本、不升级别（D6）；架构师可在关系上写明承载元素覆盖推断（D2）。
4. **热表面阈值 3 未经实测**：本项目与 h5player 的命中数在 T4 实测后定。
