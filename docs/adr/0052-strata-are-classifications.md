# ADR-0052：层是分类，不是节点

- 状态：已采纳（负责人 2026-10-29 定方向「按彻底的做法处理」）；第十六轮 H4 实现中，新规则标「议」待裁（见末节）
- 日期：2026-10-29
- 决策人：项目负责人
- 取代：[ADR-0051](./0051-model-layer-four-strata.md) 第 7 条的表示法（四层声明为 `kind: layer` 的模块）；四层的划分本身保留并按本文重审
- 关联：[ADR-0038](./0038-tiers-by-dependency.md)（L28 降级为依赖深度）、[ADR-0042](./0042-principles-three-levels.md)（原则三级）、[ADR-0045](./0045-one-layer-grammar.md)（K22 扩到声明的层）、[ADR-0049](./0049-layer-conformance.md)（K24）；规则 O1、O2、O2a、U2、K22、K24、L28、Z2、Z4、X7、X9、X21、V2、M26、ST-1–ST-7

## 背景

ADR-0051 把模型层的四层（契约 / 描述 / 解释 / 交付）写成 `kind: layer` 的中间模块，凭空多出一级。审核发现的问题都由此而来：第二级模块变成第三级，确认范围（Z4）漏掉它们，只能全标 `core`；根草图（X21）无处安放第三级，135e629 只好把它们滤掉；带内折叠成 `+N`；门面 `model.api` 只能当成一个模块塞进带里，让 L30 压节点 3 → 12。

根本原因是把两种东西混成了一种：

| | 模块（module） | 层（stratum） |
|---|---|---|
| 是什么 | **边界**：拥有代码（`codeRefs` / `entry`）、有对外表面、可以被下钻 | **分类**：把一个父模块的子模块按原则分组，规定组间的依赖方向 |
| 回答 | 这块东西的里面是什么 | 这些兄弟之间谁能依赖谁、新来的放哪 |
| 占不占级 | 占（下钻一次进一级） | 不占（同一级兄弟的分组） |

## 裁决

1. **层是父模块对子模块的分类声明**。任何模块（含系统根）都可以声明 `strata`，它的直接子模块各属一层（层的 `members`，或子模块上写 `stratum`，两种写法归一）。模块树只反映边界，层只反映分类，两者正交；级数只按模块树算，层永远不占级。
2. **声明的位置**：草图（挂在父模块上，`strata: { <父模块>: [...] }`，根写 `root`）或约定文件 `intent/strata.yaml`（人拥有，同 `roles.yaml` 的地位；同一父模块草图写了的以草图为准）。层的字段：`id`（父模块内的局部 ID）、`name`、`order`（自上而下）、`asks`（回答的问题）、`admits`（归属判定问）、`abstraction`（原则正文）、`mayDependOn`（同一父模块的层 ID，不写等于 `[]`）、`singular`（单成员层的理由）、`members`。
3. **全有或全无**：父模块声明了分层，它的每个直接子模块恰好属于一层（ST-6）。共用件、总线也归层，在带内照旧上共用件架。
4. **根的四层是单成员层**：呈现 / 视图状态 / 接入 / 模型各自恰好就是一个边界模块（有目录、`entry`、访问面），所以根声明四个层、每层的成员是同名模块。拍平根层（第二级挂到根下、层只作分类）被否决：`model` 是真实的边界，拍平会把边界信息挪进层里，又把层变回模块。
5. **单成员层的带即成员**（O2）：带头用成员名，带内画成员的子模块——这就是今天根层的画面；多成员层的带是层自己的节点（`s:<父模块>/<层 ID>`），带内画成员。
6. **U2 推广到任意层级**：依赖 a → b 取最近公共祖先 P，P 声明了分层时两端在 P 下所属的层 sa、sb 必须 sa = sb 或 sb ∈ sa.`mayDependOn`。违规的「规则所在」是层的全局键（根的层为层 ID，其余为 `<父模块>/<层 ID>`），根的迁移层键即模块 ID，违规键与已有基线不变。
7. **算出的依赖深度（L28）只作证据**：只作用于未声明分层的层次，称「依赖深度」不称「层」；用来检查声明的方向、给分层草案提供原料。
8. **ST-1 分层判据**：子模块多于七个的父模块应当处理——能归纳出 2–5 个有原则的层就声明，归纳不出就保持平铺、记拆分信号。「有原则」= 可命名、可预测、方向成立、稳定性单调（ST-3）、粒度 2–5、加模块不改定义。
9. **迁移（M26）**：根下的 `kind: layer` 由 Loader 读作根的单成员层，非根层级的按无代码的分组层溶解（成员上提一级）。h5player、media-web-player 与全部历史设计版本靠它照常读出，不改它们的文件；违规与环度和迁移前逐项相同（第十六轮实测）。

## 实现要点

- 契约：`StratumDef` / `StratumEntity`；schema 的 `strata`（文件顶层与草图）与模块的 `stratum`；索引 `index.strata`（父模块 → 层，按 order）与 `index.stratumOf`（子模块 → 层）；只按 ID 查表的小谓词 `stratumKey` / `stratumByKey` / `mayDependOnOf` / `stratumNames` 在 `names.ts`（呈现层可直接用）。
- Loader：`migrateLayers` 在单文件格式检查前改写旧写法；`mergeStrata` 按父模块合并各文件的声明（草图为准；迁移层按层 ID 合并）。Validator：`checkStrata`（ST-6）。Indexer：子模块按层序排列。
- Projector：分层总览按 `strata` 出带；多成员层的成员在本层映射到带（`alias`），带间边、核心跨层边、共用件的边沿用原口径。
- 架构治理：U2 `layerJudgement`；K22 按带所属的层判；K24 对声明两层以上的父模块；ST-3–ST-5 在 `governance/strata.ts`，进治理报告（info）与返工清单「分层」；`arch strata` / `arch place` 与 MCP 同名工具；`arch tiers` 改称依赖深度。
- 确认：Z2 摘要加 `strata`（一层一行，没声明的不参与拼接，旧指纹不变）；根的分层进系统的指纹（Z7）。
- 草图：编辑与校验入口先 `migrateSketch`；根草图的层操作编辑 `strata.root`；草图校验与核验按 ST-6 口径；底稿复制层的结构字段（不复制 `asks` / `admits` / 原则）。
- 呈现：层面板（`sel=s:`）、导航树分组标题、模块面板的「分层」节与所属层徽标；撤掉 135e629 的根草图过滤。

## 设计歧义的处置（按「模块 = 边界，层 = 分类、不占级」自行决定，列入待裁）

| 编号 | 歧义 | 处置 | 理由 |
|---|---|---|---|
| Q1 | O2「单成员层带内按成员的核心 / 折叠规则」与 O2a「放得下就全显」对单成员层是否也全显 | 单成员层沿用今天根层：核心与 port / adapter 常显、其余 `+N`；O2a 只作用于多成员层 | 20 §1.1「画面与今天的根层一致」；实测若单成员层也全显，h5player 根层压节点 2 → 13、无代码事实 0 → 12 |
| Q2 | 新写法没写 `mayDependOn` 等于 `[]`，而迁移来的旧层没写时原本不约束 | 迁移层保留「不写不约束」（`migrated` 标记），新写法按 `[]` | 否则 h5player / media 的违规会变；新写法要求显式 |
| Q3 | 20 用 M5a–c 命名三条新校验，但 02 里 M5 已是「关系端点必须存在」 | 改编号为 ST-3–ST-5，ST 系列集中登记（ST-6 声明校验、ST-7 呈现） | 编号不复用、不冲突 |
| Q4 | 迁移来的旧层 `mayDependOn` 坏引用、混排是否升级为错误（新写法是 `stratum.unknown` / `stratum.missing` 错误） | 迁移来的保持旧严重度（提醒；混排时不按分层呈现） | 迁移只改表示，不改结论 |
| Q5 | 设计草图（如 sketch-v2 的根草图）只写了部分根层时与骨架怎么合并 | 迁移层按层 ID 合并；新写法的草图之间后者整份覆盖前者；设计草图改层序时先整份带上骨架的根分层 | 同 X1「草图之间后者覆盖前者」，迁移层不完整是旧写法的常态 |
| Q6 | 非根挂载点的草图画布按层画带、拖带改层、任意草图里的层操作（X9 / X21 推广） | 本轮只做到：非根草图可在文件里写 `strata`、校验与核验生效；画布按层画带与层操作列为后续 | 根草图的画面与操作不变即可交付；非根画布是新交互，单独评审更稳 |
| Q7 | 根的单成员层要不要写 `singular`（ST-4） | 写：理由为「边界模块：有目录、entry 与访问面」 | 规则不为根开例外 |

## 代价与未决

- 骨架、`intent/strata.yaml`、确认记录是人拥有的文件：本项目描述改新格式后报 `owned.changed`，由负责人执行 `arch own`（第十六轮报告列出命令）。
- 根的分层进系统指纹、模型层撤掉 `model.api`：相关确认记录一次性跌回需复核。
- `kind: layer` 在 schema 里保留一轮（`kind` 本是自由文本），同 `calls` 的做法；迁移提醒 `layer.migrated` 为 info、`layer.nested` 为提醒。
