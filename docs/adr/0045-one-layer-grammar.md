- 日期：2026-10-28
- 决策人：项目负责人（2026-10-28「按推荐定稿」：F8 含补充——K22 扩到声明的层、门槛以下的层次没有远景；状态记号带标题上写，出截图复核）；起草：第十四轮主线会话
- 关联：[ADR-0038](./0038-tiers-by-dependency.md)（K22、L29）、[ADR-0043](./0043-one-word-layer-and-node-marks.md)（L36 状态记号）、[ADR-0044](./0044-fold-and-tiers-orthogonal.md)（门槛按全集）、[ADR-0040](./0040-bundle-trunks.md)（已否决的第三套读法）

## 背景

根层用「带 + 带间聚合」，普通层次用「束 + 分轨」；第十三轮的干线曾是第三套，已否决。读者每下钻一级就要换一套读法；同一画法也不等于同一状态。

## 裁决

1. **一套读法**（定）：凡是画成层的层次——分层总览（声明的层）与画层带的普通层次（算出的层）——远景都是「层 + 违背现行分层的线 + 计数」；节点之间的线按 L1 骨架常显、可推出与环内退到计数（F9、F10）。来源只由状态记号区分（L36）。
2. **K22 扩到声明的层**（定）：分层总览里逆着分层的交互同样是「向上」——控制反转是应有之义，否则进返工清单（info）。带间边、核心跨层边与共用件的边都判定，返工清单只按带间边各报一条（不与核心跨层边重复）。**判法（负责人 2026-10-28 合入裁决，采用 ADR-0041 的判法）**：接收方的层可依赖发起方的层、反过来不可（`mayDependOn`）即为向上；两层都没写 `mayDependOn` 时退回层序；两个方向都不许的不算向上（那是违规）。层序与可依赖方向不一致不混进向上，交给 K24（ADR-0049）。按层序判时 media-web-player 的「管线族 Provider → 管线契约」（声明允许的直接调用）会误报 2 条；按可依赖方向判，合入后 h5player 的返工清单「向上非控制反转」共 5 条（普通层次 3、分层总览 2：Application → Infrastructure），media-web-player 0。
3. **门槛以下没有远景**（定）：不足 7 个节点或不足 3 层的普通层次不画层带，中景即全部，不另造远景。
4. **状态记号的位置**（议，出图复核）：声明的层在带标题旁；算出的层整组同一状态，写在画布角一次（L36；每条层带都写会改走线、违反 L30 只降不升）。

## 后果

- 「违背现行分层」只有一个定义：线的方向违背所在分层（位置）；交互视角 K22 两种层同一判定，结构视角的判定随 F10。
- 远景的「计数」在 F9（另直连）、F10（环内）落地后齐全。
