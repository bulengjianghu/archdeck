# ADR-0026：依赖是事实，关系是交互

- 状态：已采纳（已实现，第五轮 T1；口径修正，第五轮 T4）；关系四类被 [ADR-0029](./0029-interaction-kinds-and-via.md) 修订（`calls` 拆为 `queries` / `commands`，`implements` 降为端口事实）

- 决策人：项目负责人（2026-10-24 认可草案）
- 关联：修订 [ADR-0022](./0022-relation-semantics.md)（`depends` 不再是关系类型）、[ADR-0016](./0016-concept-submodules-and-type-deps.md)（K7 的口径）；原则 SP2、SP5、SP6（[ADR-0028](./0028-positioning-and-principles.md)）；规则 §1.1 关系、M11、M14、M15、L10、L11、S12、S19、K5、K6、K7、K9、K11、Q7、Q8、Q12、X14（02）；格式 [04 §3.4](../04-description-format.md#34-关系)；需求 C-7、D-6、GV-2

## 背景

ADR-0022 把运行时关系的箭头统一为控制流，并定下「import 是证据，`depends` / `implements` 是主张」。用了一轮后：

| 现象 | 根因 |
|---|---|
| 两个项目近 400 条 `depends`，h5player 关系总数 300+，结构图看不过来 | `depends` 记的是「谁知道谁」，代码事实（文件依赖、模块依赖，K1–K4）已经从源码精确算出；人或 AI 再写一遍是重复 |
| `depends` 写多少说不清：只引类型的可写可不写，值导入的「编译期另写 depends、运行时另写 calls」 | 同一事实两种写法，描述的完整性没有标准 |
| K7「未描述依赖」要求每条值导入都有关系覆盖 | 驱动 AI 为工具函数、标签常量补 `depends`，描述在「求全」而不是「求准」（原则 SP6） |
| 事件总线让 `notifies` 两端写成「发布者 → 总线」「总线 → 订阅者」 | 总线是传递机制不是参与者；真实的交互（谁通知谁）被隐藏 |

产品原则（ADR-0028）：关系表达**交互**，不表达**知识**；完整性只对代码事实要求。

## 裁决

1. **去掉 `depends` 关系类型**。关系只有四类：`calls`（命令，同步或异步）、`notifies`（通知）、`streams`（流）、`implements`（实现契约）。现有 `depends` 按代码事实一次性迁移（两个项目与设计版本各轮）：值导入且被调用 → `calls`；只引类型、只引类 → 删除，由事实承载。草图连线的类型选择器同步去掉 `depends`（M15）。
2. **K7 改为「未解释的交互」**：有值使用（导入的函数、类、变量被引用，K1 的 `uses`）的模块依赖未被 `calls` / `notifies` / `streams` / `implements` 覆盖才算；只引类型（含枚举）的不算。只呈现（info），不要求描述覆盖每条导入。
3. **`calls` 区分同步与异步**：异步命令（Promise、异步回调、postMessage、定时器回调）标异步。草案写作 `async: true`；描述格式里已有同义字段 `mode: async`（76 条在用），**沿用 `mode: async`，不另加字段**（实现者细化，见「保留意见」）。结构图的异步沿用时序图 D-6 的箭头（开放箭头）；场景的 `async` 消息绑定到异步的 `calls`（S19）。
4. **notifies 的总线规则**：总线模块（`role: bus`，ADR-0027 的角色字段）不能是 `notifies` 的端点——两端写真正的发布者与订阅者，可写 `via: bus` 留痕（K5b：经总线传递，两端之间没有导入，不判定）；生成时按事件名配对发布与订阅（M14、04 §3.4）。
5. **`mayDependOn` 对代码事实的导入图生效，不对关系生效**：U2、U3 本来就按模块依赖（K4）判定，核实后不改规则；草图里根草图的层依赖成环（X14）按 `mayDependOn` 图判断，同样与关系无关。

## 保留意见

- 工具函数的调用也是 `calls`：关系数不会因去掉 `depends` 减半太多，接受「`calls` 是最多的一类」，带宽问题交给分级与折叠（ADR-0027）。
- 结构图的线型已归「事实状态」（ADR-0018：虚线 = 未证实），D-6 的「异步虚线」不搬到结构图，异步只用开放箭头区分（L10 现状）；待负责人确认。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 保留 `depends`，只在呈现上默认隐藏 | 描述仍要写、仍要求全，重复劳动与不一致都在；隐藏不解决「该不该写」 |
| `depends` 自动从事实生成并写回描述 | 描述里出现机器算出的条目，人分不清哪些是主张、哪些是事实，违背「来源可区分」（原则 SP2） |
| 总线作为 `notifies` 的端点 | 图上所有事件都汇到总线，交互的真实两端看不见 |

## 后果

- 02：§1.1 关系类型四类，`depends` 从类型表删除；M11 措辞、M14（总线）、M15（`depends` 迁移期）、K5（异步证据）、K6（编译期一档只剩 `implements`）、K7（未解释的交互）、K9、K11、L10、L11、S12、S19、Q7、Q8、X14 改写或新增，Q12 登记 lint 方向「事实求全、描述求准、呈现求少」；全部「待实现」。
- 04 §3.4：类型表四类、`mode: async`、总线写法；§4 的「补关系」改为「补交互」。
- 面板「知识」一行只由代码事实给出（ADR-0022 实现细化 2 不变，不再有 `depends` 可引）；图例三句话加「命令可异步」。
- 实现（第五轮 T1）：schema 去 `depends`（迁移期按 M15 剔除并提醒）；一次性迁移脚本按代码事实 `uses` 迁移两个项目与设计各轮的 `depends`，跑完删除；h5player 违规基线不变（违规键不含关系类型）；重新生成两个项目的描述，关系计数前后对照写进报告。
- 实施结果（第五轮 T4，协调者 2026-10-24 裁决）：
  - **纯值读取不是交互**：K1 在 `uses` 之外记交互使用 `invokes`（调用、`new`、`extends`、成员调用、模板渲染，或把函数、类、组件作为值交出）；只读常量、枚举、只读值、只作成员读取的基、纯数据常量（字面量、数组、`Symbol`）是纯值读取，K7 不计，由事实承载；T1 为凑 K7 判成 `calls` 的 34 条逐条复核，19 条删除、15 条保留（路由组件、继承基类经 `super` 调用、类作为值登记、注入函数）并改写说明。
  - **再导出解析**：`import { X } from …; export { X }`（含默认导入）按再导出追到声明文件，依赖提取另追裸说明符（K3、G11）；为凑 K7 补的 MuKey / MediaType 假 `calls` 4 条删除。h5player 的事实因此更准：违规键换了落点（门面 → MediaUnit 基类 / 插件基类 23 条，原「错误链」14 条落到 Share 已允许），基线待负责人重新生成（U7）。
  - **F7、S19 修订**：`async` 写了显式 `return`（`await` 取回结果）时与 `call` 一样配对；T1 改成 `async` 的 27 个步骤中有显式返回的 6 个恢复配对，两个项目的配对总数回到 T1 之前（5 / 19）。
  - 迁移出的 `calls` 说明改写为交互口吻（「谁调谁做什么」）145 条。最终关系计数：h5p-arch-desk 407 条（calls 398、其中异步 8、notifies 4、streams 5），h5player 447 条（calls 333、其中异步 31，notifies 53、implements 30、streams 31）；两个项目未解释的交互 0。
- 已知限制：
  - 证据只来自导入图：经注入、回调、事件、路由传递的运行时调用，以及一端是归属冲突文件（K4 不提升）的调用，只能写成未证实的关系或写 `via`；h5player 未证实 105 条中有一批属于这类（14 个归属冲突文件，如 `framework/src/index.ts`、`pipelineController.ts`、`registry/index.ts`）。
  - 纯值读取按语法判定：类的静态 getter（如 `Feature.supportWorker`）在运行时会执行代码，按成员读取算作纯值读取；数据常量只认字面量、数组、不含函数的对象字面量、`Symbol(…)` 与 `new Map / Set(…)`。
  - 设计历史轮次（如 sketch-editor r1–r3）按冻结快照不改，新规则 S19 在其中的提醒（同步消息对应异步命令）保留。
