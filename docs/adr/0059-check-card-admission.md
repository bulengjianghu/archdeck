# ADR-0059：核对卡的准入三问——系统面板的结论、条目与清单归位

- 状态：已采纳（负责人 2026-11-02 第十八轮走查，五点裁决全按推荐）；已实现（走查分支 `round18/walkthrough`）；标「议」的细则待裁（见末节）
- 日期：2026-11-02
- 决策人：项目负责人
- 修订：[ADR-0053](./0053-panel-five-questions-and-contract.md)（PC-7、PC-10 的系统条目）；取代 GV-7 的根层「架构治理」一节与第十五轮 G12 的「健康度按对象分组」（V16 的系统部分）
- 关联：需求 GV-7、PC-10、§6.10、§6.39；规则 V15b、V15c（系统面板补执行）、PC-7（修订）、PC-10（系统改写）、V16（修订）、PC-12、PC-13（新增）；审核轮 2 B1（③ 的计数口径）；原则 C1、C5

## 背景

第十八轮走查第二条：系统面板的核对卡「第一时间不会细看，也找不到重点」。h5player 的核对卡缺省展开约 190 行（整个面板 208 行，理解卡只占 15 行）。对照核对卡的目的（V15b：「描述可信吗、健康吗」，读者先要结论、再要条目、最后才要证据），有五类问题：

1. **结论与证据矛盾**：「证实」行 ✓「代码里的交互都有描述」，下面却红字「未证实 104」——系统的证实行只数了未解释，没数未证实；模块面板两者都数（PC-6）。「治理」行主数字 164（含基线内已知 141），决定下一步的「新增 23」在第二屏。
2. **规则已定没执行**：V15c 定了清单一律折叠带计数，系统面板的「意图」「架构治理」「违规」「端口与查询副作用」「模块环」「疑似共用件」都是直接展开的节——第十七轮三卡改造时 `GovernanceSection` 的 detail 部分沿用了三卡之前的 GV-7 版式。
3. **讲解混进核对**：画布叠加的说明（图例与帮助已有，第三处复述）、草图校验的定义、治理行条目里 61 字的口径长文、端口问题每条 2–3 行的解释。
4. **库存数冒充健康度**：文件依赖 7684（两个括号）、模块依赖 863、端口 18 · 子类 23 · 组装 145——是规模不是问题；为 0 的项占 5 行。
5. **重复与不聚合**：「确认」出现三次（一次是 G12 分组时旧行没删的缺陷）；治理数字两处；「新增 23」里 18 行同一对端同一规则，列到 30 行后指去命令行。

## 结论

### 0. 核对卡准入三问与四层口径一致（PC-13）

一行要进核对卡，必须全过：

1. **这一行回答「可信吗 / 健康吗」吗？** 不回答的是规模、库存（文件依赖数、模块依赖数、端口数、子类、组装、外部依赖），进「规模与来源」。
2. **这个数字会改变读者下一步做什么吗？** 会的做结论或条目（新增违规、未证实、端口孤立、共用件反向依赖、可收紧基线）；不会的进悬停（存量、基线日期、环度趋势、阈值、口径说明）。为 0 的不写。
3. **这是结论、条目，还是证据 / 讲解？** 证据一律折叠带计数（V15c）；讲解进帮助或悬停。

不变式：**卡头 → 行 → 条目 → 清单四层口径一致**——行说 ✓ 时清单里不能有红字；条目的数字就是清单的计数。

### 1. 系统核对卡的三行（PC-10 改写、V15b 修订）

| 行 | 结论句 | 条目（按严重度，PC-7） |
|---|---|---|
| 证实 | 「N 条关系中 M 条未证实 · K 处未解释的交互」；全好时「N 条关系全部被代码证实」。**未证实 + 未解释，与模块同口径** | 未证实 M ›（清单「未证实的关系」）、未解释的交互 K ›、核心之间未分类 J（提示级，陈述） |
| 治理 | 「违规 新增 N · 存量 M · 模块环 K」；无基线时「违规 M（无基线）· 模块环 K」。新增在前（决定下一步），存量在后（审核轮 2 B1 的治理信号仍可见）；口径、基线日期与提交、环度绝对值与趋势在悬停 | 新增违规 N ›（无新增而有存量时为提示级「存量违规 M ›」）、模块环 K ›、共用件反向依赖 ›、端口无实现者 ›、端口无使用者（提示级）›、查询副作用（提示级）›、疑似共用件（提示级）›、共用件体量超阈值（提示级）›、已消除 R 条，可收紧基线（提示级）› |
| 确认 | 系统的确认徽标 · 「核心模块已确认 N / M」，需复核 > 0 时加「· 需复核 K」并为提示级；确认过期时为 ⚠「K 处改动 · …」 | 自上次确认以来 K 处改动 ›、核心模块需复核 K（提示级） |

条目只写信号与数字（PC-7 修订）：口径说明放条目的悬停（`PanelNotice.note` → `CheckItem.title`），结论句的口径放行的悬停（`CheckRow.title`）。没有清单可跳的条目只陈述、不像链接。

### 2. 清单全部折叠带计数、为 0 不出现、按严重度排（V15c 补执行）

违规 → 模块环 → 端口与查询副作用 → 共用件 → 未证实的关系 → 未解释的交互（`GovernanceSection`，只放证据）→ 意图（草图）→ 演化 → 规模与来源 → 拦截记录（agent 接口）→ 自上次确认以来的改动 → 确认。

- **违规按「规则 → 对端」分组（PC-12）**：新增 / 违规（无基线）/ 已知 / 已豁免四组内，同一规则、同一对端的多个来源合成一行「→ 对端 · 规则 · N 个来源 · M 处」，按处数降序，单击展开逐条（再单击一条展开理由、文件证据与「加例外」）；一条来源的直接写「来源 → 对端 · 规则 · M 处」。每组缺省列前 12 行、其余「+N」展开，不再指去命令行。h5player 的 164 条从 53 行加「另 111 条」收成 13 行。
- **端口与查询副作用**：一行一条「端口 · 问题词」，说明进悬停与行省略（CSS 一行省略）。
- **共用件**：反向依赖、体量（阈值在悬停）、入度最高（Q15）、反向依赖清单、疑似共用件与一键认可（U11，依据在标题悬停）。计数 = 共用件数 + 疑似数。
- **未证实的关系**：证实行的证据，每条「来源 → 对端 · 类型」，单击选中那条关系；前 30 条，其余「+N」。
- **规模与来源**：来源（仓库 / 提交 / 生成时间）、描述规模（层或顶层模块、模块、关系、接口、数据结构）、**代码事实规模**（文件依赖——未归属 / 冲突不计的条数在悬停、模块依赖、端口、子类、组装与组装根、外部依赖前 8）。

### 3. 删掉的

「架构治理」摘要节整节（确认并入确认行、关系证实并入证实行、治理子折叠并入治理行与悬停、库存数进规模与来源）；两段讲解（画布叠加说明——图例与帮助已有；草图定义——进「意图」清单的悬停）；条目里的口径长文；为 0 的项；重复的确认行；「另 N 条，见 npm run arch -- violations」；端口问题每条的多行解释。

### 4. 模块面板

模块的核对卡本就按 PC-6 六行、清单全折叠，不改结构；只随机制层同步：条目的口径进悬停、行可带悬停。

## 否决的方案

| 方案 | 为什么不 |
|---|---|
| 治理行只写「新增 N」、存量进悬停 | 审核轮 2 B1 定过 ③ 的计数是治理信号（含已知）；两个数都给、新增在前，既不违背 B1 又把决定下一步的数放前面 |
| 保留「架构治理」摘要节、只删重复行 | 三卡之后它与三行重复，一个数字只在一处；它的分组（G12）是三卡之前为旧面板设计的 |
| 违规清单只加分组标题、仍逐条列 | 18 行同一对端同一规则是同一件事，合成一行才是「少」 |
| 库存数留在核对卡里折叠 | 过不了准入第一问；读者看核对卡是为了找问题，不是看规模 |

## 后果

- h5player 系统面板从 208 行降到 45 行（核对卡约 25 行、清单全折叠），一屏放下；违规清单 164 条 → 13 个分组行。
- 组件：`SystemPanel.vue`（三行口径、清单次序、规模与来源、拦截记录）、`GovernanceSection.vue`（只剩证据清单：违规分组、模块环、端口、共用件、未证实、未解释）、`IntentSection.vue`（折叠带计数、讲解进悬停）、`panelCheck.ts`（`CheckItem.title`、`CheckRow.title`、`NoticeRowDef.text / title`）、`panelNotices.ts`（新信号键与严重度）、`CheckCard.vue`（渲染悬停、不可跳的条目不像链接）。
- 系统面板加载中的措辞与模块核对卡同文「代码事实读取中」（E2E 以它为代码事实就绪的屏障；`openCheckList` 撞上自动展开时重试）。
- 第一次看系统面板的人少了一屏统计数字，多了一步点开清单——以结论、条目与计数承接。

## 待裁（「议」规则）

- 违规分组每组缺省 12 行、未证实清单 30 条的上限。
- 共用件清单的计数口径（共用件数 + 疑似数）。
- 无新增而有存量违规时治理行记提示级 ⚠（而不是 ✓）——B1 的「治理信号」用警示色而非危险色表达。
- 核心之间未分类作证实行的提示级条目（不可跳，只陈述）。
