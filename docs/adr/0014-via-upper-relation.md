# ADR-0014：经由上层关系——是否建模由步骤自身的关系绑定决定

- 状态：已采纳（待实现）
- 日期：2026-10-21
- 决策人：项目负责人（方案 A，2026-10-21）；实现者提出的细化规则（来源「议」）列在下文，待负责人确认
- 关联：需求 D-5、D-6，验收标准 §6.9；领域模型 §1.3、§2（P5、P11、P15、P16、R15、S5a、S13）；ADR-0005（S5a、S13 的来源）

## 背景

运行视角下钻到模块内部（h5player 的 Infrastructure / Framework 机制内核、domain.services 等）时，大量消息被标「结构中未建模」（P11）。逐条核查 h5player 两个场景的全部层次与分支，共 30 处：

| 类别 | 数量 | 例子 | 原因 |
|---|---|---|---|
| 误报 | 26 | `app.solution.stage-swap → infra.framework.model-registry.registry`（`beginXxxModelSwitch()`），在 infra.framework 层 | 步骤已绑定关系（多为 S13 推断）`rel.solution.stage-swap-framework`（`app.solution.stage-swap → infra.framework`）。描述按格式只把关系端点写到 `infra.framework`，它正是当前层次本身；按投影规则（`mapEndpoint` 对当前父模块返回 skip），这条关系不属于本层，本层没有视图边，P11 就判成「未建模」 |
| 真实缺口 | 4 | 「命令执行」的 `pre / post hook`（`infra.framework.state-machine.engine → app.solution.lifecycle`）及其返回 `success / ErrorBase`，在 infra.framework 与 infra.framework.state-machine 两层各一次 | 描述里只有反方向的 `rel.solution.lifecycle-framework`（`app.solution.lifecycle → infra.framework`），没有 Framework 回调 lifecycle 钩子这个方向 |

根因：P11 用「本层有没有视图边」代替了「这一步有没有建模」。两者在关系端点都写到最深层时一致，但描述格式允许（也鼓励）把关系建在能表达清楚的层次上，下钻后两者就分开了。

## 选项

| 方案 | 做法 | 结论 |
|---|---|---|
| **A. 经由上层关系** | 是否建模由步骤自身的关系绑定决定（显式 `relation` 或 S13 推断，与层次无关，与校验器 S5a 的口径一致）；本层没有对应视图边的已绑定消息画成另一种临时线，标「经由上层关系」 | **采纳** |
| B. 端点写到最深层 | 要求 AI 把关系端点写到消息端点所在的最深模块，让每一层都有视图边 | 否决：关系数随下钻深度膨胀，同一条架构事实被拆成多条；与「能推出来的不让人写」相悖；上层视图的聚合边条数失真；描述格式与校验都要改 |
| C. 只改文案 | 保持判定，把「结构中未建模」改成更温和的说法 | 否决：误报与真实缺口仍然混在一起，负责人无法从图上找出真正缺的关系，等于取消了 P11 的价值 |

## 结论

### 1. 消息在本层的三种呈现

| 情况 | 落点 | 结构图 | 时序图 | 步骤面板 |
|---|---|---|---|---|
| 本层有对应视图边 | `edge`（不变） | 画在边上 | 照常 | 在本层：A → B |
| 步骤绑定了关系（显式或推断），但本层没有对应视图边——关系一端是当前层次本身或其祖先 | `upper`（新增，带 `relationId`） | 回放期间画临时线，按关系类型着色的实线，标「经由上层」，不参与布局；单击选中该关系 | 消息标「经由上层关系」，箭头照常着色 | 注明「对应关系建在上层」，可定位到那条关系（`revealRelation`） |
| 步骤没有绑定任何关系 | `unmodeled`（不变） | 红色虚线「未建模」 | 标「结构中未建模」 | 在本层：A → B（结构中未建模） |

- 判定依据是帧已有的关系绑定（`Frame.relation`，`planScenario` 打开场景时算一次），落点只多看这一个字段，不新增查询。
- 临时线不参与布局；合并规则 P5 不变（仍按两端节点合并，经由上层与未建模的帧落在同一对节点上时照常合并）。
- 不改描述格式，不要求 AI 把关系端点写到更深层；S5a 不变。

### 2. 细化规则（来源「议」，待负责人确认）

| # | 细化 | 理由 | 被否决的选项 |
|---|---|---|---|
| P16 | 合并后的一条可见消息里既有已绑定帧又有未绑定帧时，整条判为「结构中未建模」；全部已绑定时为「经由上层关系」，`relationId` 取第一帧的关系 | 「未建模」是要人去补的缺口，宁可多报也不能被合并掩盖；判「经由上层」需要这一步的每一帧都有依据 | 按第一帧判（缺口可能被前一帧掩盖）；把消息拆开（违背 P5「仍按两端节点合并」） |
| 实现细节 | 经由上层的临时线 ID 为 `upper:<from>|<to>`，与未建模 `unmodeled:<from>|<to>` 分开：同一对节点在不同消息中两种情况都出现时各画一条 | 两种线的含义与样式不同，混成一条会丢掉其中一种信息；实际很少同时出现 | 同一对节点只画一条、按「有未建模即红」着色（把已建模的消息也染红） |
| 实现细节 | 经由上层的临时线可单击，选中对应关系（运行视角下即该关系的运行信息）；未建模的临时线仍不可单击 | 「定位到那条关系」在结构图上也应可达；未建模的线没有可选中的对象 | 不可单击（结构图上无从得知是哪条关系） |

### 3. 不在本次范围（待负责人确认）

- **S5a 补严**：步骤未绑定关系、但两端（含祖先）之间存在反方向的运行时关系时，校验器也给出提醒（如「只有反方向关系 X，是否缺少 Y → X 这一方向」）。现状下这类步骤只有在两端之间结构上无任何关系时才提醒，本次的 4 处真实缺口都不会被报出。本次不做。

## 后果

- 下钻到 Framework 内部时，「方案切换事务」的 `beginXxxModelSwitch()` 等步骤显示为「经由上层关系」，不再误报；真正的缺口（如 Framework 回调 lifecycle 钩子）仍是红色虚线，图上一眼可分。
- 落点 `Landing` 多一种 `upper`；舞台叠加、画布场景、时序模型 / 时序图、步骤面板、图例随之调整。
- h5player 描述补上「Framework 回调 lifecycle 钩子」方向的关系，修复 4 处真实缺口。
