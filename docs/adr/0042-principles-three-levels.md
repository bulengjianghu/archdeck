# ADR-0042：原则三级同构——系统两句、模块一句话原则、原则进指纹

- 状态：已采纳，已实现（第十四轮 F15）
- 日期：2026-10-28
- 决策人：项目负责人（2026-10-28：第十四轮清单「按推荐定稿」，§6 第 12、13、16 项）；起草：第十四轮执行会话 r14-principles
- 关联：[ADR-0023](./0023-sketch-reviewed-and-evolution.md)（确认层 Z1–Z6）、[ADR-0025](./0025-sketch-as-thinking-medium.md)（草图内外归属 X10，本 ADR 修订）、[ADR-0028](./0028-positioning-and-principles.md)（定位与原则）；`docs/system/seeing.md` §2.3、§4；规则 M23、M24、Z7（新增），Z1–Z4、X10（修订）（02）；需求 01 §4 面板表、RV-2（修订）

## 背景

原则是心智模型的三要素之一（是什么 + 为什么这样分），三级各有毛病：

- **系统**：定位和原则混在 `system.description` 里，根层面板排第 4 位；确认层（Z 系列）只覆盖模块，系统的定位与原则永远停在「AI 的主张」。
- **模块**：对内原则 `abstraction` 只有层必填，非层模块只能由挂在它身上的草图写（X10），实际几乎没有；实现原理 `principle` 是长文、折叠在最后；指纹（Z2）不含 `abstraction`，连层的抽象原则改了都不需复核。

## 裁决

1. **系统写两句**：`system.description` 第一句定位（为谁解决什么、提供什么价值），第二句核心原则（按什么取舍、怎么分）；不是两句时 lint 给提示（M23）。根层面板「简介」置顶（只做置顶，不上画布，§6 第 13 项）。
2. **三级原则都能被确认**：层的面板也提供「确认」（层原来不在 Z4 范围里、没有按钮；原则进指纹后必须有确认路径），不计入健康度。**系统能被确认**：`reviewed.yaml` 允许以系统 ID 记一条确认，指纹只覆盖简介（Z7，§6 第 16 项）。按钮放在系统面板「简介」下；系统不计入确认范围与健康度（「核心模块已确认 a / b」的口径不变）。
3. **模块一句话原则**：任何模块都可在描述里写 `abstraction`（对内原则，一句话，AI 起草、人确认）；核心模块与第二级模块应写（没写时提示，M24），其余有子模块的模块建议写。X10 修订为「描述可写，草图写了以草图为准」——草图写了、描述写了不同的值仍是 `sketch-redefined`。
4. **面板首段合成「说明」**：模块面板第一节「说明」= 职责 + 原则一句（层同此，原「抽象原则」一节并入）；`principle` 仍折叠在后。
5. **原则进指纹**：Z2 纳入 `abstraction`，层与模块都算；没写原则时不参与拼接，所以没写原则的模块指纹不变，写了的一次性跌回需复核（§6 第 12 项：接受，发布说明列出数量）。

## 实现要点

- 指纹拼接在原有六项之后按需追加带标签的项（`['abstraction', …]`、`['description', …]`），空的不追加：未写原则的模块、已有的确认记录照旧有效。
- 系统在确认层里与模块同一套函数：`reviewSummary(index, rootId)` 只给 `description`；`reviewStates` 多出系统一项；Validator 的确认记录清理、写入端点 `appendReviewed` 都认系统 ID。
- 系统简介计句：在 `。！？` 与后跟空白或行尾的 `.!?` 处断句，没有句末标点的尾巴也算一句；版本号、文件名里的点不断句。

## 代价与未决

- 三个项目中写了 `abstraction` 且有确认记录的模块一次性变为需复核，数量见第十四轮报告 `C-08-report.md`。
- 系统是否计入健康度、计句口径是「议」，列入第十四轮 C-09 待裁。
