# ADR-0041：机制标签——交互的机制写在标签位，异常与机制分两段

## 背景

读一条交互线要读四样：种类（颜色）、方向（箭头与位置）、同步性（箭头实心或空心）、机制（`via`）。前三样有通道；机制只有两样看得见——经端口画插座（L12）、经回调写「回调」（L24）。经总线、经通道（注入、跨进程、路由、平台事件）在画布上与直接调用长得一样，只在面板里有徽标。分层（L28）之后，向上的线读得出「是控制反转」，读不出「怎么反转」。

## 判据：一个维度要不要常显文字（词表准入四问）

文字零学习成本，但只能逐个读，多了成墙、冲淡异常、占几何空间；图形要学，学会的代价按出现次数摊销——少见的符号永远学不会。

1. **别的通道已经表达了吗**——有就不写：种类看颜色，同步 / 异步看箭头，方向看位置。
2. **不写会怎样读错**——误读代价高才常显；低的放悬停与面板。
3. **出现频率**——低频用文字，高频用图形。
4. **缺省不写**——直接、同步不写。

另两条：**写机制、不写后果**（控制反转是后果；写出「端口」「总线」就解释了为什么能向上）；**异常与修饰分两级**。数量上限是**设计时的检查**，不是运行时开关——超了说明该换通道，不在某些层次藏起来。

## 裁决

| # | 内容 |
|---|---|
| 1 | **机制标签**：词表 回调、端口、总线、注入、跨进程、路由、事件、通道、拉取；中性色；聚合边带条数（全部都带时省略）；交互视角、运行视角、草图画布同义，结构视角不标；分层总览照写 |
| 2 | **插座与「端口」并存**：一个通道一个维度禁止的是一个通道承载两个维度，不禁止同一维度两个通道冗余；文字在中点说「经端口」，插座在入口说「哪一端可替换、落在哪个入口」 |
| 3 | **两段与上限**：一条边仍只有一个标签位，画成至多两段——异常段（含 ×N 与把手，警示色）在前，修饰段（机制、混合、经上层，中性色）在后；无异常时只有一段中性 pill。标签（不含 ×N 与把手）至多显示两个，按词表次序取前两个，其余写「+k」接在最后一段末尾、悬停列出 |
| 4 | **「混合」收窄**：只表示束内同步与异步不一致；机制不一致由带条数的机制标签表达 |
| 5 | **通道归类**：`callback` → 回调；`inject` → 注入；`router` → 路由；`http`、`https`、`ws`、`websocket`、`sse`、`postMessage`、`worker`、`hmr`、`ipc` → 跨进程；`event`、`dom`、`mediaSession` 与以 `change` 结尾的浏览器事件名 → 事件；其余 → 通道。不分大小写；`@<契约模块>` 不影响归类 |

**「向上」只有一个定义**：线的方向违背所在分层（位置）。交互视角的判定 = 一条交互朝上、又没有任何机制（K22 的 `tier.upward`；普通层次按算出的层号，分层总览按声明的可依赖方向 `mayDependOn`，没写时按层序——实现时发现 media-web-player 的「管线族 Provider」排在「管线契约与共用律」之下却可依赖它，按层序会把正常调用标成向上，议，待负责人确认）；结构视角的判定由 F10 的规则给出。加了机制标签后，向上的交互有机制就自带理由，没有机制的才写「向上」，排在异常段。

被否决：只写异常（现状，总线、注入、跨进程与直接调用无法区分）；去掉插座只留文字（失去入口定位）；按层次密度条件显示（同一关系处处不同样子）。

## 后果

- 机制从面板走到画布上；向上的线自带理由，「向上」只剩真正可疑的那些。
- 标签数量上升（media-web-player 最密层中位 2 个），由两段与上限、几何检查器（L30 ④标签互压只降不升）兜住。
- 描述作者写通道名时有了推荐词；归不进固定表的落在「通道」，在报告里列出、不改描述。
