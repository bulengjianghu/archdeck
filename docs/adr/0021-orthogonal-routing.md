# ADR-0021：普通层次的正交走线——端口方向、边界节点与参与者参与布局、跳线

- 状态：已采纳（已实现）
- 日期：2026-10-22
- 决策人：项目负责人（方向，2026-10-22）；elk 选项与跳线细节由实现者按效果取定
- 关联：规则 L4（改写）、L11（新增）、A7（普通层次的位置）；需求 C-6；[ADR-0018](./0018-edge-encoding.md)

## 背景

普通层次的图有三处读不清：

1. **曲线穿节点**：边界节点与参与者不进 elk，手工排在底部一行并画曲线（`linkRoute`），一把扇形线压在中间的模块上；
2. **进出不分**：elk 的边从节点任意一侧进出，同一节点的进边与出边混在一起，看不出流向；
3. **交叉无提示、被节点盖住**：交叉处看不出哪条线是哪条；悬停或选中时，相邻的边从别的节点下面穿过，被盖住。

## 结论

| 项 | 内容 |
|---|---|
| 端口 | 每条边在两端各有自己的端口，`elk.portConstraints: FIXED_SIDE`：内部节点进边在上（NORTH）、出边在下（SOUTH），自左向右布局时左进右出；第一行的用户只朝下，最后一行的边界节点、外部系统与时间只朝上；同一侧端口的先后由 elk 按减少交叉排（L11） |
| 全部节点进 elk | 边界节点与参与者同内部模块一起布局，边界边与参与者的边由 elk 正交绕行；边界边默认隐藏但照常布局（L4） |
| 行的约束 | 用户层约束 `FIRST`，边界节点与外部系统 `LAST`；最后一行的先后用 `crossingMinimization.semiInteractive` 的位置提示按视图顺序（层次顺序，P9）固定 |
| 跳线 | 画出来的折线关系边之间，水平段在与竖直段的交叉处起半径 4 px 的半圆小桥；同一对节点之间的边互不算交叉，离线段端点 16 px 内不跳；曲线与隐藏的边不参与（`layout/routing.ts`，纯函数） |
| 边的层级 | 与聚焦对象相邻、选中、回放经过的边 zIndex 1001（当前步骤 1002），高于 Vue Flow 选中节点的 1000；其余边在模块节点之下；步骤徽标、分支预览、「+N」占位块 1003 起 |
| 曲线的范围 | 只保留给分层总览的核心跨层边与参与者的边（O4、A7）、回放临时线（P11、P15）与代码依赖叠加线（K9）——它们不参与布局 |

## 取舍

1. **elk 端口 vs 自己算走线**：用 elk 的端口与正交路由。自算能完全控制，但要重写避障与交叉最小化；elk 已有，配置即可。
2. **分区（partitioning）vs 层约束**：负责人建议的分区在样本层次上会把边界节点排成两行（h5p-arch-desk `state.desk`、h5player `infra.framework`、`app.solution`），也不保证层次顺序；改用层约束 `FIRST` / `LAST` 加位置提示后，6 个样本层次都是一行、顺序正确，内部边的交叉数与分区相当（如 `state.desk` 2、`infra.framework` 4）。
3. **跳线约定**：水平跳竖直（与正交走线的主方向无关，读法统一）；平行边、往返边同属一对节点，交叉是走线并行造成的，不跳。
4. **A7 的变化（定）**：普通层次里外部系统与时间不再固定在右侧一列，而是随边界节点排在最后一行（自左向右布局时即右侧一列）——层约束只有首尾两端，没有「右侧」；分层总览不变。负责人已确认（见文末修订）。

## 后果

1. 隐藏的边界边也占走线通道，内部结构与边界节点行之间的空白比原来大。
2. 回到上层的边（目标在源的上方）按端口方向要绕到目标的上方进入，比原来长。
3. 布局缓存键带 `LAYOUT_VERSION`，选项再改时升版本。

## 修订：边界边按需走线、层框留白、A7 确认（2026-10-22）

负责人看过上面的实现后裁决：

| 裁决 | 内容 |
|---|---|
| 边界边不参与默认布局 | 隐藏的边界边占走线通道，内部图被撑大（`state.desk` 1999×822、h5player `infra` 1516×1343）。改为 elk 只布局内部边与参与者的边；边界节点仍作为无边节点交给 elk（`LAST_SEPARATE` 自成最后一行、位置提示定顺序，并关掉 `separateConnectedComponents`，否则无边节点被拆成独立分量摆到别处）；边界边要画时才按需走线。改后 `state.desk` 1275×497、`infra` 1117×1036 |
| 按需走线的做法 | 选在 `layout/routing.ts` 自算（`detour`）：出端口 → 短桩 → 横到竖直通道 → 竖直 → 横到目标短桩 → 自上而下进入目标；通道在起终点、节点间空隙中线与外框两侧中取三段都不穿节点（含两端自身）、最短的一条。没有复用 elk：elk 的 `fixed` 算法不避障，`INTERACTIVE` 分层与交互式摆放仍会挪动节点，都做不到「坐标固定、只算正交走线」 |
| 两级缓存 | 节点布局按 `cacheKey`（普通层次不含边界边，带 `LAYOUT_VERSION`）；边界边的走线按布局的节点表记忆，再按当前视图的边界边集合区分 |
| 层框留白 | 普通层次的父模块虚线框包住内部节点（留 28 px）与已布局的走线（留 12 px，参与者那一端的点除外），框线不再压在走线上，参与者与框之间至少隔开半条层间通道；分层总览的系统框留白 20 → 28，带内上下 18 → 24 |
| A7 | 定：普通层次中外部系统与时间随边界节点排在最后一行，分层总览不变（取舍 4 不再是待确认） |

## 修订：方位表示角色、框表示边界（2026-10-22）

背景：分层总览中外部系统在右侧，下钻到普通层次后却在最后一行；架构师在根层在系统框外，下钻后又像在某一层里（框的含义从「系统」变成了「当前父模块」）；分层总览里 AI 到核心模块的跨层边被画成贴着带边框的长横线，横穿右侧通道、没有跳线。

负责人确认的统一设计：

| 方位 | 放什么 |
|---|---|
| 上方，系统框外 | 用户（发起者） |
| 右侧，系统框外 | 外部系统与时间（协作方） |
| 下方，系统框内、父模块框外 | 边界节点（系统内的其他模块） |
| 中间，父模块框内 | 当前层的子模块 |

实现：

1. elk 只排父模块框内的子模块；框外的元素在布局后按方位摆放（`placeOutside`），方位固定在屏幕上，不随自上而下 / 自左向右改变。上一节的层约束（`FIRST_SEPARATE` / `LAST_SEPARATE`）与位置提示不再需要，删去。
2. 框外元素的边（参与者的边、边界边）全部正交走线：普通层次按需（`edgeRoute`），分层总览在排布时（`outsideRouter`，进出核心模块时先到带间空隙中线）。曲线只剩分层总览中核心模块之间的跨层边、回放临时线与代码依赖叠加线。
3. 两层框：根层只画系统框；下钻后外框为系统边界、内框为当前父模块，边界节点在两框之间。没有边界节点时两框重合，画布让外框外扩 16 px。外侧绕行通道离节点 50 px，落在两框之间，不压框线。
4. 规则：A7、L4 改写（来源定）。L11 中「第一行的用户只朝下，最后一行的边界节点、外部系统与时间只朝上」一句已不成立（框外元素不进 elk），应改为「框外元素的端口按方位：用户底边、外部系统左边、边界节点顶边」——本修订只改了 A7、L4 两行，L11 的文字留待关系语义的改动合入后同步。


## 修订：终点前留直段、横线走在两框之间（2026-10-22，负责人走查）

拐弯紧贴箭头：按需绕行的终点短桩只有 14 px，减去拐角圆角 8 后箭头前只剩约 6 px 直段，箭头底边压在拐弯上（h5p-arch-desk 与 h5player 两个项目共 172 条边的直段不足 16 px）。调整为：

1. 终点短桩 `ARRIVE` = 38（箭头最深约 14 + 圆角 8 + 余量），起点短桩仍为 14；elk 的 `edgeNodeBetweenLayers` 24 → 30。全部折线边箭头前的直段不少于 22 px。
2. 只加长短桩会让横线压到父模块框线与框标签上，于是让进内部节点的横线整段走在两框之间、只在靠近目标处竖直穿过父模块框一次：系统框留白 `SYSTEM_PAD` 28 → 44，外侧通道 `OUTSIDE` 42 → 50，边界节点行间距 `BOUNDARY_GAP` 40 → 72（放得下进边界节点的终点短桩）。离框线不足 6 px 的横线从 278 条降到 7 条。
3. 代价：下钻层次的系统框四周多出约 16 px 留白。

## 修订：可见框外边的轨道分配（2026-10-22）

现象：按需走线的框外边各自求路，同一走廊里共用一条线——视图状态层选中 Layout 时，到呈现层与模型层的几条边蓝线压灰线，两个「×2」标签叠在一起。

结论（负责人）：在按需走线这一遍里做通道分配，只对当前画出来的那组框外边（`outsideRoutes`）：组内先各自求路（端口错开只在组内算），再把走廊里重合的中间横段、竖段按边 ID 依次错开 `PARALLEL_GAP`（`allocateTracks`），标签沿各自的线挑不相碰的位置（`placeLabels`）；首末段不动，保持「进节点前留直段」与「绕行横线走在两框之间」两条约束；不回馈 elk，内部节点的位置不变；跳线按分配后的线段算。

被否决：**全量预分配**——对本层全部框外边（含默认隐藏的边界边）预先分轨，走廊要按全部边的条数撑开，平时只显示几条时线却散得很开。

## 修订：动静分左右端口（2026-10-22）

结论（负责人）：与上进下出正交，同一侧再按关系的动静分前后半——顶边左半为动态入（calls / notifies / streams）、右半为静态入（depends / implements），底边同理为出；自左向右布局时换成左右边的上下半（上动下静）。elk 用 `FIXED_ORDER`，按其顺时针端口序（上边从左到右、右边从上到下、下边从右到左、左边从下到上）给序号。

实现中发现：只给内部边排序、框外边按半边另放，两者在同一侧会交错（elk 把内部边的端口铺满整条边）。于是框外边在内部节点那一端也交给 elk 一个**不连线的占位端口**，一起排序，按需走线时直接取 elk 排出的位置。代价：缓存键含框外边（它们影响端口排布，不影响节点位置）。核对：两个项目全部 64 个普通层次、209 处同一侧兼有动静出入的节点侧，动态出入点都在静态之前。

被否决：**上动下静**（自上而下布局时把动态放在顶边、静态放在底边）——与「上进下出」冲突，进出就分不清了。

## 修订：分层总览带右边的进出分开（2026-10-26）

现象：media-web-player 的分层总览中，跨多层的侧边通道边两端都钉在带右边的中线附近（只按车道错开三档），带到右侧外部系统的边在带一端一律按「出」取右边、另按框外边一组错开；两套位置互不相知，同一条带的进线与出线、箭头叠在一起。L11 的进出分开只写了普通层次，带没有覆盖到。

结论（负责人，方案 A）：带右边的端口统一分配——通道边与带和右侧参与者的边一起排，上半进、下半出（O3a）。通道与参与者都在右侧，左右方位不动。

被否决：**带也上进下出**（方案 B）——与 L11 字面一致，但每条边要先到带间空隙中线再拐去右侧通道，横段穿过带间的层间竖线，拐弯与跳线都更多。

## 修订：分层总览核心跨层边的端口与跨多层走线（2026-10-26）

现象：悬停核心模块时出现的核心跨层边全部从节点水平中心出入，只有同一对节点的几条按 10 px 平移；不同对的边挤在同一点、进出混在一起，曲线两端都对着中心，彼此缠绕。跨多层的曲线直接穿过中间的带（O3 只约束了带之间的边）。

结论（负责人，方案 B1）：端口仍朝对端取顶边或底边，同一侧左半进、右半出，半边内按对端横向位置排（O3b）。上进下出在这里不适用：自下而上的边要从源的底边出、进目标的顶边，曲线得绕一圈。

跨多层的走法（实现给出，待负责人确认）：改为正交折线，经相邻带间空隙横到右侧通道外的核心车道，再到目标一侧的空隙进入——带横跨整个宽度，不穿带只能从侧面绕。核心车道按有共同端点的边不同车道分配，悬停一个节点时它的边各走各的车道；车道常留、计入框宽，不随悬停改变布局。

被否决：**B2 只按对端排序**——交叉最少，但进出交错，与进出分开不一致。**跨多层的曲线绕过中间带**——曲线没法既平滑又避开横跨全宽的带。**核心车道按悬停临时分配**——会让框宽、参与者位置随悬停跳动（V12 节点不动）。

## 修订：外部系统改在左侧、空隙里的横段各占一条轨道（2026-10-28）

见 [ADR-0039](./0039-line-clarity-and-actors-left.md)：外部系统与时间改在系统框左侧（A7），分层总览右侧只留侧边通道与核心车道；带与参与者的边从带的左边进出（O16，O3a 的右边只剩通道边）；跨多层核心边在空隙里的横段不再按车道上下错开 4 px，改为各占一条轨道、空隙按轨道数撑开（O14、O15）。本 ADR 上文「右侧，系统框外」「带右边与右侧参与者一起排」等写的是当时的做法。
