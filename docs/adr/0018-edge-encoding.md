# ADR-0018：关系线的信息表达策略

- 状态：已采纳（已实现）
- 日期：2026-10-22
- 决策人：项目负责人（四项裁决，2026-10-22）；实现细化（来源「议」）列在「实现细化」
- 关联：需求 C-7、C-8、D-6、GV-6、W-2；领域模型 L5、L10、K9、P5、P15、P17、R2、Y5；[workbench.md](../architecture/workbench.md)「边」「显示面板」；[projection.md](../architecture/projection.md) 第 4 步；ADR-0014（经由上层关系）、ADR-0017（显示面板）

## 背景

结构图上的边有 5 个视觉通道（色相、线型、线宽、标签、底色晕），却承载 9 个维度，且分配交叉：

| 问题 | 表现 |
|---|---|
| 一个维度占多个通道 | 关系类型同时占色相、线型（依赖 / 实现虚线、事件点线）、标签文字 |
| 一个通道表多个维度 | 线型还表同步 / 异步（点划线）；线宽同时表聚合条数、选中、走过 |
| 维度没有编码 | 直接边与聚合边形状相同 |
| 正常态也标记 | 证实状态是标签末尾一个字符（✓ ◐ ?），绝大多数边的 ✓ 只是噪声 |
| 相似对象同形 | 代码依赖叠加线的灰（`--text-3`）与依赖色几乎相同；运行视角「经由上层」临时线是类型色实线，与本层直接边同形 |

根因：没有信息层级——依赖占 h5player 449 条关系中的 153 条、arch-desk 272 条中的 143 条，是背景，却与控制流平权；通道按维度出现的先后而不是重要性分配；L5 合并丢信息；正常态也标记。

**L5（普通层次不论类型合并）的代价**（实测）：

| 项目 | 普通层次 | 合并后视图边 | 按类型分边 | 含多类型的边 | 被「多数类型」盖住的关系 |
|---|---|---|---|---|---|
| h5player | 45 | 591 | 698（+18%） | 88 | 194 |
| h5p-arch-desk | — | 303 | 352（+16%） | 49 | 103 |

最常见的组合是 depends ×1 + calls ×1 的平局，平局按 `RELATION_TYPES` 声明顺序（depends 在前）取胜，所以调用被系统性地画成了灰色虚线依赖。

## 结论

### 1. 信息层级

| 层级 | 回答 | 维度 | 呈现原则 |
|---|---|---|---|
| T1 | 谁驱动谁 / 谁知道谁 | 运行时（calls、dataflow、event）vs 编译期（depends、implements）；方向 | 一眼可见：运行时饱和、编译期降权；箭头 |
| T2 | 有多少 | 聚合条数；直接 / 聚合 | 线宽三档 + 聚合边的 `×N` |
| T3 | 可信吗 | 已证实 / 未证实 / 未描述 / 违规 | **只标异常**：已证实不标 |
| T4 | 细分 | 五种类型、同步 / 异步、接口 | 颜色 + 图例 + 悬停 + 属性面板，不进标签 |
| T5 | 回放 | 当前、走过、预览、经由上层、未建模 | 独立一套（强调色、序号、临时线），不复用上面的通道 |

### 2. 通道分配（一个通道只表一个维度，L10）

| 通道 | 表示 | 取值 |
|---|---|---|
| 色相 | 关系类型 | 五色；饱和度分两档：运行时三类饱和，编译期两类低饱和、明度接近背景 |
| 线型 | 事实状态 | 实线 = 已描述且已证实（或没有代码事实）；虚线 = 已描述但未证实（含部分证实）；点线 = 代码有、描述无（叠加线） |
| 箭头 | 同步 / 异步 / 实现 | 同步实心、异步空心（开放）、`implements` 空心三角；与时序图（D-6）一致 |
| 线宽 | 聚合条数 | 三档：1 / 2–4 / ≥5；编译期整体更细 |
| 标签 | 聚合条数与异常 | 聚合边的 `×N`（带边框 pill）；异常标记 `?`、叠加线「未描述 N · 违规 N」；不写类型名，不标 ✓ |
| 晕（边下的宽底色） | 违规 / 设计变更 / 选中 / 回放 | 违规红、设计变更色（违规优先）；选中为强调色窄晕；回放当前步骤为强调色宽晕 + 流动 |
| 透明度 | 聚焦 | 只表示「与聚焦对象无关而变淡」 |

放弃「虚线 = 依赖」的 UML 惯例：依赖已经由降权的颜色区分，虚线留给更需要被看见的「未证实」。

### 3. L5：同一对节点之间的不同类型关系

| 方案 | 做法 | 结论 |
|---|---|---|
| **A. 按类型分线** | 普通层次也按 `(from, to, type)` 分边，与分层总览一致；同类型内仍 `×N` 聚合（L2） | **采纳**：颜色与线型不再撒谎；平行线由布局错开，视图边只多 16–18% |
| B. 按大类合二 | 运行时一条、编译期一条 | 否决：运行时三类之间仍互相盖住（calls 与 dataflow 同对常见），且多出一个只在图上存在的「大类」概念 |
| C. 一条线多色 | 一条线画成分段或多股颜色 | 否决：线宽、线型、箭头都无法再按类型表达；SVG 实现与命中测试复杂，聚合条数无处表达 |

### 4. 回放

- 「经由上层」临时线改为**按关系类型着色的虚线**（保留「经由上层」标签），与本层直接边区分（P15）。
- 帧落到视图边时按帧绑定关系的类型选边（P17）；连续落在同一对节点之间（同方向）的帧仍合并为一条可见消息，不因类型不同而拆开（P5），单步数不变。
- 走过的边不再加粗（线宽只表条数），由步骤序号标注。

## 实现细化（来源「议」）

1. 一条视图边上的关系同步与异步混合（`mixed`）时画实心箭头，面板写「同步 + 异步」。
2. 一对节点之间同方向有多条视图边时，违规的红晕（K9）与本层环里「同方向视图边」（Y5）取关系类型声明顺序中的第一条（依赖优先），只标一条。
3. 平行边（同一对节点、不同类型）：elk 原生排开内部边；边界边、参与者的边、核心跨层边的曲线按序号横向错开 10px（L10）。
4. 线宽档位（px）：运行时 1.5 / 2.5 / 3.5，编译期 1 / 1.75 / 2.5。
5. 只由一条更深关系提升来的聚合边不标 `×1`，与直接边同形；在面板中写「聚合边」。

## 后果

- 视图边 ID 统一为 `<from>-><to>:<type>`；URL 中旧的 `sel=e:<from>-><to>` 失效（选中视图边不做存在性校验，面板提示「这条边在当前视图中已不存在」）。
- `ProjectOptions.mergeTypes` 与 `ViewEdge.types` 删除；属性面板的聚合边只显示单一类型与条数。
- 图上标签大幅减少，类型名改由图例、悬停与面板承担；不熟悉配色的读者第一次需要看图例（「显示」面板的「关系」组）。
- 有代码事实时，虚线的边就是要处理的边；没有代码事实（设计版本、源码不在本地、开关关闭）时全部为实线。
