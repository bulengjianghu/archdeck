# ADR-0040：束干线——已否决：静息态的线多，问题在「画什么」，不在「怎么画」

- 状态：**已否决**（第十三轮实现后评审否决，代码不合入主线；实现存档在分支 `round13/trunk` 的 `bb7f329`）
- 日期：2026-10-28
- 决策人：项目负责人（2026-10-28 先审核通过「边干线聚合」方案；同日看过评审与实测后，确认评审的处置建议：否决、回退、修正方向并入第十四轮）
- 关联：[ADR-0031](./0031-three-views-and-structure-view.md)（束 L21）、[ADR-0035](./0035-line-grammar.md)（线的语法）、[ADR-0038](./0038-tiers-by-dependency.md)（分层与环合组）、[ADR-0039](./0039-line-clarity-and-actors-left.md)（L30 几何检查器，本 ADR 修订它的覆盖范围）；规则 L30（修订）、L34（空号）（02）；验收 §6.27（空号）（01）

## 背景

第十二轮 B（ADR-0039）立了几何标准之后，残余的重合集中在大扇入节点（如本项目 `present.panel` 扇入 19）。负责人的要求是「线多了还是会有重复、看不清，需要整体梳理、依次处理掉」。

第十三轮的方案是**束干线**：同一被依赖方、依赖方在同一层带、都无异常、成员 ≥ 3 的束，中段合成一条（线宽按成员数，标签「×N」），两端保留各自的短桩与箭头（保留 ADR-0039 修订 1 方案 A）。几何在 elk 定位之后改写成员的走线。

## 裁决

1. **否决束干线。** 代码不进主线，L34 与验收 §6.27 留为空号。
2. **否决「值使用缺省收起」（保留第十三轮的这条结论）。** 三个项目全部普通层次的 514 条束中，值使用只有 28 条（5%）。缺省收起要多一层「折叠 + 计数 + 开关」，却几乎不减少线；开关 `invokesOnly` 维持原样，供查询用。
3. **L30 的覆盖范围扩到结构视角（修订 ADR-0039）。** 任何常显的线，都由它所在视角的几何检查器测量；结构视角的基线录于 `75ec65f` 的布局。
4. **修正方向并入第十四轮**，与 F1（全集分层）、F4（正名）一起裁决和落地：远景统一为分层总览的语法（层带 + 违背现行分层的线 + 带间计数，根层次与复杂模块同一套）；传递约简决定默认画哪些线；例外的口径统一并按组呈现环；线的四级与醒目度；线的语法收敛为一套，任何常显的线必须进布局与分轨。

## 否决理由

**一、修的层级不对。** 呈现可以分四级：①画什么 → ②节点放哪 → ③线怎么走 → ④线怎么画。线多的根源在①：静息态画了大量低信息的依赖对——在分层的画面上，方向已由位置表达；「被很多模块依赖」是节点属性（「入 N」、不稳定度 I）。干线在③④上处理，保留了每条成员的两端，读者要追的依赖对一条没少，降低的是墨水量，不是认知负担。

**二、不是更粗一级的聚合。** 干线保留全部端点，只是中景（束）的另一种画法，不是远景。根层次与复杂模块是同一套分层体系（第十四轮），远景应当是分层总览的语法；干线做的「同层带多个来源指向同一目标」是带间聚合的弱化版。

**三、实测：线对象少了，读图更难了**（三个项目全部普通层次，有代码事实，缺省显示偏好，产品同一份布局输入，`bb7f329`）：

| | h5p-arch-desk | h5player | media-web-player |
|---|---|---|---|
| 静息态线对象 | 223 → 188（−16%） | 296 → 285（−4%） | 不变 |
| 有干线的层次，线与线交叉 | 231 → 278（**+20%**） | 57 → 54 | — |
| 不同干线之间、干线与非成员线的重合 | **0 → 134** | 0 → 3 | — |
| 不同干线的汇入横段同高相撞 | 6（都在 `access`） | 0 | — |

`access` 层第 1 层三个入口节点底边下有一条横贯全宽的横线，5 条干线的汇入段压在同一高度，分不清哪个来源去哪条干线。原因是干线在 elk 之后改写走线、只登记竖向车道、汇入横段高度固定，不参与 L32 分轨。这正是第十四轮 F7 批评时间耦合波浪线的三条理由：不参与布局、走线器管不住、读者多记一种线。

**四、验收是自证的。** L30 当时只测交互视角，干线只出现在结构视角；回归口径「静息态结构边对象数」，一合并就必然下降。裁决 3 由此而来。

## 留下的结论

- **值使用只占 5%**（裁决 2）。
- **传递约简的口径与实测**（并入第十四轮 F9）：宇宙 = 本层全集的兄弟束（交互使用 + 值使用，两端都是内部节点、不连共用件、不是照画的异常束）；先求强连通分量，环组内互不约简，环组之间在缩点 DAG 上另有长度 ≥ 2 的路径即可推出。可推出的占宇宙 32%（h5p-arch-desk）、8%（h5player）、26%（media-web-player）。
- **照画的环束是 h5player 线多的主因**：画出来的 296 条束中有 214 条是环上的照画束，其中 170 条一端是边界节点，跨界折叠因此失效。环是一组节点的属性，却被逐条画成醒目的线，这和干线犯的是同一类错误。按组呈现环见第十四轮 F10。
- 「干线在新体系里没有位置」暂不作为定论：F9、F10 落地后，对残余的不可约大扇入复测（第十四轮 F13），需要汇合画法时，汇合点作为虚拟节点交给 elk，不在 elk 之后改写。
