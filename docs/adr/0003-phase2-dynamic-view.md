# ADR-0003：二期动态视角的架构

- 状态：已采纳（已实现，实现中的规则细化见 [ADR-0005](./0005-phase2-implementation-refinements.md)）
- 日期：2026-10-20
- 决策人：项目负责人
- 关联：需求文档 §4.4、领域模型 §2、架构总览与专题、设计版本 `model/h5p-arch-desk/designs/phase2-dynamic/`（r1–r4，r4 定稿）、ADR-0002

## 背景

二期在一期「看见结构」之上叠加「看见运行」（需求 §4.4）：场景、时序图、结构图上的回放。按 ADR-0002 的设计版本流程，先由 AI 在当前架构上出设计、经四轮评审定稿后再开发。各轮的评审意见与讨论都记在设计版本的 `design.yaml` 中，本 ADR 只记录定稿的结论。

## 结论

1. **不动一期骨架**。模型层新增核心模块「场景投影」，与 Projector 并列，两者共用同一个端点映射 `mapEndpoint`。这样结构图和时序图对「这一步在这一层是谁和谁」永远一致。场景投影分五个子模块：回放计划、回放路径、帧的层次投影、参与查询、时序模型。
2. **视图状态是一个值，会话规则是纯函数，协调者只有一个**。
   - DeskState 只负责三件事：持有视图状态、唯一写入口 `dispatch`、派生要画的数据。
   - 与外界的交互拆成四个同步适配器：路由、时钟、模型源、布局。
   - 不拆成多个有状态的 store：层次、选中、播放头、已选分支互相约束，是同一个事实。
3. **按知识划分层次**。判别法是：换一个前端（命令行、导出脚本、AI 查询），这条规则还需不需要？
   - 需要的，是关于被描述系统的知识，放模型层，作为架构查询。例如：最近仍存在 / 可见的祖先、本层的下一步、到达某一步需要的分支选择、谁参与了哪一步。
   - 只在交互浏览时有意义的，是会话规则，放视图状态层：视角、焦点、指针之间的关系、浏览器历史与 URL。
   - 这条判别法补进两层的抽象原则。
4. **视角与焦点**。
   - 视角分结构、运行两种，由是否打开场景决定，没有单独的开关。
   - 面板只显示唯一的焦点。运行视角下焦点要么跟随当前步骤，要么钉住用户指向的对象。不变式是「播放中 ⇒ 无选中」。
   - 用户指向任何对象即暂停并钉住。取消选中会回到跟随，但保持暂停。只有播放控制能恢复播放。
   - 指向某一步，等于把播放头前进或后退到这一步。
5. **场景模型**。
   - 每个场景只写一套最细的步骤，各层投影合并；单步按本层可见消息前进。
   - 步骤是运行时关系（calls / dataflow / event）的一次发生，可以没有对应关系。端点之间只有一条运行时关系时自动推断；本层找不到对应的边时，回放期间画「结构中未建模」虚线。
   - 到 alt 分支时停下，由用户选择分支。
   - 外部参与者在模块树之外单独声明，作为系统上下文常驻静态视图。
   - 场景文件放在 `scenarios/`，与 `modules/` 同级，YAML / JSON 都可以。
6. **领域规则清单**（设计版本 r4，共七组：V / N / S / A / F / P / R）是二期纯函数单测的穷举依据。每条规则都注明了来源和所在模块。

## 后果

1. 一期 DeskState 要重构一次：导航规则移进视图状态转移，定位类知识移进模型层的架构查询。行为不变，一期的 DeskState 测试作为回归。
2. 描述格式新增顶层键 `actors`、`scenario` / `scenarios`；接入层增加 `.json` 扩展名。
3. 二期实现完成、按代码重新生成当前版本后，设计版本状态改为 `implemented`，文档中的「待实现」标注随之更新。本 ADR 的结论已写入需求、领域模型与架构文档（ADR-0004）。
