# ADR-0011：钉住当前层次时按跟随突出；源码文件显示行数、超长标红

- 状态：已采纳
- 日期：2026-10-21
- 决策人：项目负责人
- 关联：需求 D-18、SR-9，验收标准 §6.4；领域模型 §2（R15、G19–G21）；描述格式 §3.7；ADR-0007、ADR-0008

## 背景

1. **切换层次后，时序图大片同时高亮**。原因是两条规则叠加：
   - 下钻会钉住被下钻的模块，也就是新的当前层次（V3）。
   - 钉住时突出它参与的全部消息（R15）。

   而本层可见的消息至少有一端在当前层次里，所以几乎全部都被突出，看起来像选中了多个步骤。
2. **希望在文件树上看到代码行数，超长的标红**，用来发现过大的文件、判断模块是否该拆，对应目标「支撑治理」。

## 结论

### 1. 钉住当前层次或其祖先时按跟随突出（改 R15）

- 钉住的对象是当前层次本身或它的祖先时，按跟随处理：突出当前可见消息与配对的调用或返回。
- 钉住其他模块、关系、视图边、参与者时不变，仍突出它参与的消息。
- 面板不受影响，仍显示钉住对象的运行信息。

### 2. 源码文件显示行数，超长标红（SR-9，新增 G19–G21）

- **行数**（G19）：
  - 只统计 TS / TSX / JS / JSX / MJS / CJS / Vue 文件，按物理行数计，不区分空行与注释。
  - 接入层在列文件清单时一并统计，按文件的修改时间与大小缓存。
- **阈值**（G20）：
  - 超过阈值的文件为「超长」，阈值默认 500 行。
  - 项目可在描述中用 `sourceLimits.maxLines` 覆盖，写在 `source-ignore.yaml` 中。
  - 只显示，不报警告（不进问题列表与 `lint:model`），避免噪音。
- **呈现**（G21）：
  - **文件树**：文件行显示行数（灰色、右对齐），超长的标红；目录显示子树内的行数合计与超长文件数。顶部新增「只看超长」筛选。
  - **模块面板「源代码」一节**：每个文件后显示行数，另给模块合计行数与超长文件数。
  - **文件面板**：显示行数与是否超长。

| 选项 | 结论 |
|---|---|
| 统计物理行数 | **采纳**：规则简单、结果可预期，与编辑器显示的行号一致 |
| 只统计代码行（去掉空行、注释） | 未选：需按语言解析，代价高，阈值也更难解释 |
| 超长报警告进 `lint:model` | 未选：行数是参考信号，不是描述的错误 |

## 后果

需求、领域模型、源码专题、工作台专题、描述格式与 Schema 按最终态改写。本项目的架构描述随代码更新。
