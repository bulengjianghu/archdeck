# ADR-0025：草图是思考的介质

- 状态：已采纳（已实现，2026-10-24）
- 日期：2026-10-23
- 决策人：项目负责人（方向与原则 P1–P8，2026-10-23）；原型发现的 20 点由协调者给出裁决建议，按负责人确认的方向并入
- 关联：修订 [ADR-0024](./0024-sketch-editor.md)（编辑画布、拖 = 移动、新建缺省空草图、撤销范围）、[ADR-0023](./0023-sketch-reviewed-and-evolution.md)（设计 = 草图 + 轮次：草图从一张变为按挂载点的若干张）；需求 SK-12–SK-21（01，SK-6–SK-11 已被替换）；规则 X4、X5、X7、X7a–X7i、B6 修订，X9–X20 新增（02）；格式 04 §3.10；设计版本 `model/h5p-arch-desk/designs/sketch-v2/`

## 背景

ADR-0024 的编辑态把草图加载成索引，**叠在模型画布（分层总览 + elk 自动布局）上编辑**。用了一轮后三个问题浮出来：

1. **画布不是思考的地方**。分层总览是为「看懂已有系统」设计的：整份草图一起画、自动布局、每次编辑后重排。架构师整理思路时要的是只看一个局部、几个节点、自己摆放位置；自动重排让刚摆好的思路每一步都被打乱。
2. **拖 = 改归属**。在分层总览上拖动模块到另一条带或父模块即移动（改父、级联改 ID）。拖动本是摆位置的手势，被绑定成结构修改，误操作的代价是 ID 级联；而摆位置这件事反而做不了（不保存坐标）。
3. **删除 611**（负责人看到的对比计数）。草图版本以当前版本为对比基线，草图没画的实体全部计为「删除」——局部草图对着整份模型，计数必然是几百条删除，真正的改动淹没其中。根因不在删除操作，而在**草图没有范围边界**：草图可以画层、也可以画任意深度的子树，对比与核验不知道它「只管哪一块」；复制骨架做底稿时整份 supersedes，改一处等于对整份负责。

这三点的共同根源是：二期把草图当成**模型的一个可编辑视图**，而草图应该是**架构师思路的延伸**——停留在局部，能对应到模型，产出能支撑 AI 生成下一版。

## 负责人裁决

### 原则（2026-10-23）

| # | 原则 | 落地规则 |
|---|---|---|
| P1 | 自由：不阻碍思路整理 | 编辑器只拒绝做不成的操作；校验分两级：格式错误拦保存，语义错误（层依赖成环、与持久草图矛盾、超七）只拦「交给 AI」与定稿 |
| P2 | 局部：一张草图一个挂载点、一个层次 | 草图有 `mount`（模块 ID 或根）；所有模块必须是挂载点的直接子节点；层是带不是层次，根挂载范围 = 层 + 第二级 = 现骨架；七为软限，超过提示归并 |
| P3 | 拆与合是设计动作 | 操作族新增合并（若干节点归入新概念、原节点降一层）、拆分；血缘字段 `from: [ids]`；变更清单、核验、交给 AI 的指令按血缘算 |
| P4 | 字段按内外归属 | 模块对外的一面（名称、职责、接口）属父草图；对内的一面（原则、子模块、子模块关系）属挂在它身上的草图；两张相邻草图字段不重叠，矛盾检查退化为「同挂载点」 |
| P5 | 自由布局，线只跟两端 | 坐标存草图 `layout` 节（按模块 / 关系 ID）；初始用一次自动布局，之后不再自动；「重新排列」由人触发；第一步直线无折点 |
| P6 | 完整描述从复制开始 | 新建草图按挂载点从当前版本复制：结构字段（ID、名称、closed、core、范围内关系与类型、跨边界关系的外部端点为只读引用），不复制职责文字；复制后核验应为 0 偏差 |
| P7 | 草图是证据 | 设计 = 若干张草图（目录 `designs/<ID>/sketches/<mount>.yaml`）；归档后草图原样可开，layout 随归档 |
| P8 | 两个对比 | 相对基线 = 我改了什么（变更清单、交给 AI）；相对当前版本 = 实现还差什么（偏差、归档门槛） |

P1 中「超七」拦交给 AI、P6 中「从当前版本复制」「0 偏差」被下表 #1、#2 细化。

### 原型发现的 20 点（2026-10-23）

可点原型走通全部手势后列出 20 个说不清或互相矛盾的点，裁决如下：

| # | 问题 | 裁决 |
|---|---|---|
| 1 | 超七拦不拦交给 AI | 不拦：超七只是画布角与面板的提示，不进「拦」那一级（骨架天然超七） |
| 2 | 底稿从哪复制、0 偏差何时成立 | 一律从 `base.commit` 复制，含下钻时新建的子草图；验收写成「复制后相对基线为 0」 |
| 3 | 职责的核验口径 | 职责只参与相对基线，不参与相对当前版本；子草图里父模块职责为空时显示基线文字并标注来源 |
| 4 | 跨层关系的复制 | 只复制显式写在本层的关系；子树间关系的聚合以浅色只读线显示，不写回、不计数 |
| 5 | 合并 / 降级后的 ID 前缀 | 级联改前缀：被收进去的模块及其子树换成新父前缀，记 `from: [旧 ID]`；变更清单里被「合并 / 移动」吸收，不另列 |
| 6 | `children` 记录 | 不单独存：合并 / 降级只写 `from`；下一层草图不存在时，底稿由「基线里的子树 + 血缘指向的模块」推出 |
| 7 | 降级 / 升级跨两张草图的撤销 | 设计级一条撤销栈，每步记录涉及哪几张草图；「每张独立撤销栈」作废 |
| 8 | 降级 / 升级的关系与计数 | 降级时关系重指向目标并去重（同合并）；升级时下一层关系不带上来，列为待重连；计数加一类「移动」（降级 / 升级 / 移入） |
| 9 | 计数里的「删除」 | 保留「删除（范围内主动删除）」；去掉的是旧口径「删除项 = 没画的」 |
| 10 | 拆分后未重连的关系 | 面板常驻「待重连 N 条」，算语义提示（拦交给 AI），清单里单列 |
| 11 | 无关系的引用节点 | 不保存：引用节点由关系派生；加进来没连线的，保存时丢弃并提示 |
| 12 | 改 ID 的血缘与子草图级联 | 改基线已有模块的 ID 记 `from: [旧 ID]`；子草图文件名、`mount`、子模块前缀级联 |
| 13 | 中文名转不出 ID | 新建 / 合并 / 拆分对话框都有 ID 字段，英文名自动填，中文名必填，不用拼音 |
| 14 | 名称出现两次 | 版本下拉选中后只显示名称，kind 用图标；信息条身份区保留 kind 标签 + 名称 |
| 15 | 两条面包屑 | 合为一条，在身份区，可点返回，也是升级落点；下钻后随当前草图变 |
| 16 | 保存 / 脏 / 交给 AI 的范围 | 按设计算；推出的子草图未改动不算脏、不写文件，改过的保存时作为新文件写出 |
| 17 | 两个核验数的范围 | 面板标「本张」，信息条与「说明」标「全设计」 |
| 18 | 非根草图的成环 | 非根草图检查本层 `depends` 成环；层依赖成环只在根草图 |
| 19 | 血缘链 | `from` 一律指向基线 ID，编辑器合并时展开闭包；全新节点没有基线来源 |
| 20 | 小问题 | 「交给 AI」改为「保存并交给 AI」一步；「退出」回到进入草图之前的版本；草图画布上不放「在此设计」，只有「进入下一层」；超七提示只留画布角与面板 |

### 被否决的选项

- **修补二期编辑态**（关掉自动重排、拖动改为只摆位置）：草图仍是整份、仍叠在模型布局上，局部与归属问题不解决；模型画布的布局与草图的布局互相牵制。
- **草图存 `children[]` 记录合并 / 降级的原节点**：与下一层草图形成两份真相（在子草图里删掉 A，父草图仍写着 A）（#6）。
- **`from` 记直接来源**：相对基线比对时要沿血缘链求闭包才能找到基线 ID，每个读者都要做一遍（#19）。
- **每张草图独立撤销**：降级 / 升级一步改两张，分开撤销必然出现两张不一致（#7）。
- **超七拦交给 AI**：骨架与很多真实模块天然超七，软限变成硬限（#1）。

## 结论

1. **草图格式 v2**（04 §3.10）：`mount`（模块 ID 或 `root`，不能是层）、`principle`（父模块原则；根挂载时用各层的 `abstraction` 等字段）、`modules[]`（必须是挂载点的直接子节点，可带 `from: [基线 ID]`，不嵌套 `children`）、`relations[]`（显式写在本层：两端都在本层，或一端为外部模块）、`layout`（`modules.<id>.{x,y}`、`relations.<id>.label.{x,y}`）。引用节点不单独存；没有 `layout` 的草图兼容（打开时自动布局一次，不写回）；没有 `mount` 的一期草图按一期口径读取（X9）。
2. **设计含多张草图**：`designs/<ID>/sketches/<mount>.yaml`（文件名 = 挂载点 ID，根为 `root.yaml`），每个挂载点至多一张；持久草图 `intent/<ID>.yaml` 也带 `mount`，骨架为 `mount: root`。一期的 `designs/<ID>/sketch.yaml` 照常读取。
3. **字段按内外归属**：名称、职责、接口、core、closed 属父草图；原则、子模块、子模块之间的关系属挂在该模块上的草图。矛盾检查只比同挂载点（X4、X10）。
4. **血缘与前缀级联**：`from` 一律指向基线 ID；合并、拆分、改 ID、移动（降级 / 升级 / 移入）按血缘表述；ID 变了整棵子树换前缀，设计里已有的下一层草图同一步改名（X11、X12）。
5. **两个对比**：相对基线（我改了什么：变更清单、交给 AI）与相对当前版本（实现还差什么：偏差、归档门槛），共用一个核验函数；相对当前版本只比结构，职责等文字只参与相对基线；计数六类：新增 / 修改 / 合并 / 拆分 / 移动 / 删除（X4、X17）。
6. **底稿从基线复制**：新建草图与推出的子草图都从 `base.commit` 复制本层结构与显式写在本层的关系，不带文字（X18）。
7. **两级校验**：格式错误拦保存；语义提示（层 / 本层依赖成环、同挂载点矛盾、待重连）拦「交给 AI」与定稿；超七只提示（X13、X14、X16）。
8. **设计级会话**：编辑会话按设计一份，一条撤销栈，每步记录涉及的草图；保存、脏、「保存并交给 AI」都按设计（X7g、X20）。
9. **替换呈现层的编辑画布**：新建独立的草图画布（`present.sketch`，自由布局、直线边、引用节点、合并 / 拆分 / 降级手势、双击下钻、面包屑）与草图面板（`present.panel.sketch`）；移除叠在分层总览上的编辑态（`present.canvas.edit.*`、`present.panel.edit.*`、`present.version.edit`）。模型层的 `applyEdit` 形态、级联改 ID、校验、核验、指纹门禁、冲突重放保留并扩展；新增一次性布局 `state.layout.sketch`。

## 后果

1. **修订 ADR-0024 的结论与裁决**：
   - 「编辑态的画布数据复用 `canvasScene`」→ 草图画布独立，不复用模型画布的投影与布局；草图有自己的坐标。
   - 「拖动模块到另一条带或父模块即移动」→ 拖动只摆位置；改归属只经降级（拖到节点上）、升级（拖到面包屑父级）、移入（根草图里拖到另一条层带），都是显式的设计动作并记血缘。
   - 「新建设计缺省空草图」（ADR-0024 待复核项）→ 撤销：底稿一律按挂载点从基线复制；「改骨架」= 根挂载的设计草图。
   - 「撤销 / 重做只在本张草图」→ 设计级一条撤销栈。
   - 「不保存坐标，编辑后自动布局」→ 坐标存 `layout`，只在初始与「重新排列」时自动布局。
2. **规则**（02）：X4 改为同挂载点矛盾、相对当前版本只比结构；X5 改为「移动 = 降级 / 升级 / 移入，只经草图，前缀级联」；X7、X7a–X7i 按新画布改写；B6 改为多草图路径、按设计写回；新增 X9–X20，来源「议」，汇总给负责人裁决。
3. **需求**（01）：新增 SK-12–SK-21；SK-6–SK-11 标「已替换（→ SK-12–SK-21）」。
4. **架构**（03 与专题）：新增 `present.sketch`、`present.panel.sketch`、`state.layout.sketch`；`model.intent.edit` 增合并 / 拆分 / 降级 / 升级 / 位置，`model.intent.validate` 两级；`present.canvas.edit.*`、`present.panel.edit.*`、`present.version.edit` 标「待移除」。
5. **迁移**：骨架加 `mount: root`（读取侧 schema 认 `mount` 后由实现会话加）；`designs/DeskState_temp` 删除（负责人 2026-10-23 裁决）；本轮作为设计 `sketch-v2` 登记，草图在一期读取侧支持 `sketches/` 之前以一期格式手写在 `sketch.yaml`。
6. **不做**：折点编辑、草图跨层次、场景草图、多人协作、把草图布局用于模型画布。
7. **实施结果**（2026-10-24，分支 `round4/sketch-v2`，提交 `0622479`–T3 收尾，基线 `5285286`）：
   - 文档与格式（T0）→ 信息条三区（T5）→ 模型层与接入层（T1：格式 v2、两级校验、设计级操作族、血缘与两个对比、按设计写回）→ 视图状态与草图画布（T2a：设计级会话、草图画布）→ 引用折叠、层带、草图面板、「在此设计」（T2b）→ 信息条接到设计级会话（T2c）→ 收尾（T3：小修、核验、重新生成描述、归档）。
   - 替换了什么：叠在分层总览上的二期编辑态（`present.canvas.edit.*`、`present.panel.edit.*`、`present.version.edit`、`EditBar` / `DesignBar` / `CommitBar`）整体移除；草图画布为第二级模块 `present.sketch`，草图面板为 `present.panel.sketch`，信息条拆为身份 / 动作 / 对比三区；一期草图格式迁移后不再读取（`intent/` 下的一期骨架例外，`sketch-legacy-mount`）；本轮自身的设计 `sketch-v2` 核验一致后归档，根草图连 `layout` 晋升替换骨架——自 v2 起骨架拥有第二级之间的关系。
   - 已知限制：保存期间继续编辑时的冲突判断偏保守（按读取时的指纹整次拒绝，T2a 裁决 8）；子树间关系的浅色只读聚合线未做（X18、SK-15）；「引用外部模块」挑到比折叠层更深的 ID 时，连线前单独显示，连上后才折叠（T2b 裁决 4）；草图画布线密时没有「隐藏外部引用」开关；切换版本、关闭页面时的「保存 / 放弃 / 取消」三选一（X7a，现为浏览器两选确认：`beforeunload` 只能两选，切换版本前可用信息条「退出」的三选）与表单改 ID 的影响预览（X7d，校验已即时报出前缀与重复错误）降为后续（第五轮）。拆分有下一层草图的模块前的二次确认（X7k）已在收尾后补上。
