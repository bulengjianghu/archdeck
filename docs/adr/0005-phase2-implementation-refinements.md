# ADR-0005：二期实现中的规则细化

- 状态：已采纳
- 日期：2026-10-20
- 决策人：实现者提出，项目负责人确认（2026-10-20）
- 关联：ADR-0003、领域模型 §2（L9、P5、P12、S5a、S5b、S13、V3、R14）、验收标准 §6.2

## 背景

二期按 ADR-0003 定稿的设计实现。落到代码时，几处定稿规则没有覆盖到的情况必须给出确定的行为，否则实现会不确定或与验收标准冲突。按「存疑的规则要说出来」，这些细化都登记为来源「议」的规则，并在这里记录理由与被否决的选项，供负责人逐条确认。

## 结论

| 规则 | 细化 | 理由 | 被否决的选项 |
|---|---|---|---|
| S5a、S13 | 关系两端分别是消息两端**自身或其祖先**即算「对得上」；推断时恰好连在两端上的关系优先，没有时再看连在祖先上的 | 描述规范要求跨区域时关系对端只写第二级模块，而消息写最深模块；只认端点完全相同，h5player 的迁移场景几乎每一步都会被误报「无关系」 | 只认端点完全相同（误报多）；任意深度都推断（多条候选时会误绑） |
| S5a | 引用的关系对不上时报 error，**去掉该引用、保留步骤** | 删掉步骤会改变流程本身；保留步骤、回放按未引用处理，错误仍让 `lint:model` 失败 | 按 M9 剔除整个步骤 |
| S5b（新增） | 消息端点不存在 → error 并剔除该步骤；引用不存在的关系 / 接口 / 数据结构 → 提醒并去掉坏引用 | 与 M5、M7 对关系的处理一致 | — |
| P5 | 合并要求**同一条边且方向相同**，并在同一组合框分支中；分支点与空分支断开合并 | 不要求同方向时，调用与它的显式返回总落在同一条边上而被合并，S10a「画显式 return」就永远看不到；不按组合框断开时，时序图上组合框会切开一条消息，且回放路径与时序图全貌的消息无法一一对应 | 只看「同一条视图边」 |
| P12（新增） | 运行视角的舞台补齐场景帧端点（含全部分支）在本层对应的边界节点与参与者，即使结构上没有关系 | 否则「结构中未建模」的消息与无入口关系的参与者在本层没有节点可画；按全部分支补齐，切换分支时布局不变（V5） | 只补当前路径（选分支时布局会跳动） |
| L9（新增） | 运行视角下舞台不受显示开关（关系类型、边界节点、只看现状）影响，开关置灰 | L8 已定「筛选不作用于回放」；若舞台随开关变化，被隐藏的边界节点 / 目标态模块上的帧既画不出也不该算不可见；默认开关下舞台与结构图完全相同，不违背「布局不变」 | 开关仍作用于舞台、被隐藏处按不可见处理（单步粒度随开关变化） |
| V3 | 运行视角下双击下钻：暂停，并钉住被下钻的模块（即新的当前父模块） | 验收 §6.2-2 要求「暂停并钉住」；结构视角的 N2（下钻清空选中）若照搬，焦点会回到跟随，与「钉住」矛盾 | 下钻后清空选中、只暂停 |
| R14（新增） | 单步时暂停；播放头在末尾时「播放」从头开始；停在未选分支的分支点时「播放」无效；退出场景进浏览器历史 | 定稿未说明这些边界情况；单步时继续自动播放会让「看清这一步」无法做到 | 单步不影响播放状态 |

## 后果

1. 以上规则已实现并按规则清单单测；需求、领域模型、架构文档已按最终态写入。
2. 负责人若推翻某条，按「规则改了 → 01 的规则列、专题、单测」修改，并在本 ADR 标注被哪条 ADR 取代。
