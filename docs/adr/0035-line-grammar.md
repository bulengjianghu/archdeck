# ADR-0035：线的语法——线型只分行为与依赖，异常写字

- 状态：已采纳（负责人 2026-10-27 审核通过），待实现
- 日期：2026-10-27
- 决策人：项目负责人（2026-10-27 第十一轮：「整个连线关系收敛成更清晰的方式，实线标识交互关系，虚线表示结构关系，此外没有其他线型，只有颜色和箭头的区分」；「代码事实的线型是否有必要……是否应该在标签位置直接说明【未证实】【违规】」；同日裁决 R3-1…R3-7 全部按推荐）；起草：第十一轮协调者
- 关联：修订 [ADR-0018](./0018-edge-encoding.md)（一个通道一个维度：原则不变，线型改表「行为 / 依赖」）、[ADR-0031](./0031-three-views-and-structure-view.md)（结构视图的 UML 编码与 L18 私有通道）；承接 [ADR-0034](./0034-callback-and-reading-lines.md)（回调写在标签位）、[ADR-0029](./0029-interaction-kinds-and-via.md)、[ADR-0032](./0032-module-surface-and-carrier-chain.md)（承载叠加）；规则见「影响」

## 背景

画布上的线型现在有 15 种用法。同一种虚线在不同地方意思不同：
- 交互视角：未证实；
- 运行视角：经由上层、未建模、分支预览；
- 结构视角：使用、端口实现。

另有点线（未解释的交互、违规叠加、允许依赖）、点划线（组装叠加）、波浪线（时间耦合）。ADR-0031 把线型定为各视图的**私有通道**（L18），单看一个视图时说得通。但第八轮起，交互与依赖越来越多地画在**同一张图**上：
- 选中交互时叠出承载段（L22）；
- 未解释的交互叠加线（K9）；
- 组装叠加（O12）；
- 结构视角反向画出交互（L22）。

叠加时同一种线型在一张图里同时有两三种意思，读者只能靠记图例。

另一层问题：交互视角的线型表「事实状态」（已证实 / 未证实）。「未证实」说的是**描述**与代码对不上，是地图的问题，不是领土的问题。它占了全图通用的线型通道，让架构师在读系统时一直被描述质量干扰。media-web-player 未证实 0 条，通道常年闲着；h5player 未证实 104 条，满图虚线。

## 裁决

### 1. 线型只回答一个问题：这是行为还是依赖

| 线型 | 意思 | 包括 |
|---|---|---|
| **实线** | 交互：描述里的行为主张（谁调谁做什么） | 关系边、聚合边、核心跨层边、运行视角临时线（经由上层、未建模、分支预览）、结构视角反向画出的交互 |
| **虚线** | 依赖：代码事实（谁导入 / 继承 / 实现 / 组装谁），或规则允许的依赖 | 结构边与元素级边、未解释的交互叠加线、违规叠加线、组装叠加、承载段、承载缺段、允许依赖 |
| **波浪线**（唯一例外） | 时间耦合：经常一起提交 | J5 |

线型从各视图的私有通道改为**共享通道**（L18）：三个视图同义。

### 2. 其余维度各占一个通道（不变或微调）

- **色相**：交互视角为四类交互（查询淡、委托、通知、流）；结构视角中性，档用明度（L16a）；违规为红（共享）。
- **箭头 / 端点记号**：交互为方向与同步 / 异步（实心 / 空心「V」）；依赖为形态（开口箭头 = 使用、空心三角 = 子类、**◇ = 端口实现**（见 3）、依赖方实心菱形 = 组装）。
- **线宽**：条数三档（不变）。
- **晕**：违规红晕、选中、设计变更（不变）。

### 3. 子类与端口实现改由端点记号区分

两者现在都是空心三角，靠实线、虚线区分；全改虚线后，端口实现改为被依赖方一端**空心菱形 ◇**。理由：◇ 已是本工具里「端口」的记号（端口元素，T2 裁决 5；端口实体 L13），读法一致。代价：与 UML「实现 = 虚线 + 空心三角」惯例不同，图例注明。

### 4. 异常与修饰一律写在标签位

标签位（线中点的 pill，与 ×N、把手同处）是唯一写字的地方，词表固定、每个 ≤ 3 字：

| 标签 | 何时 | 出现条件 | 原来 |
|---|---|---|---|
| 未证实 | 交互关系没有代码证据 | 「代码事实」开关开 | 虚线 + ? |
| 违规 | 关系或依赖违反规则（基线外） | 「代码事实」开关开 | 红晕 / 红点线（红晕保留） |
| 未解释 | 代码有依赖、描述无交互 | 「代码事实」开关开 | 点线 |
| 缺段 | 承载缺一段 | 选中交互时 | 警示色虚线（线型保留虚线，因为缺的是依赖） |
| 回调 | 经回调 | 常显 | ADR-0034 修订 |
| 混合 | 束内修饰不一致 | 常显 | 不变 |
| 经上层 | 运行视角经由上层 | 回放中 | 虚线 + 「经由上层」 |
| 未建模 | 运行视角未建模 | 回放中 | 红虚线（红色保留） |

合并规则：
- 聚合边只写一个 pill：`×N · <标签> M`（M 为束内带该标签的条数；全部都带时省略 M）。
- 多个标签用 ` · ` 连接，顺序：违规 > 未证实 > 未解释 > 回调 > 混合。
- **分层总览**只写 ×N 与计数，不逐条写字（R3-5）。
- 运行视角走过的边按现规则不标条数，标签照写。

### 5. 不做的

- 不走设计版本评审：这是画法，不是被描述系统的架构；设计版本画不出线型差别（R3-6）。
- 不为「未证实」保留任何线型或颜色：它进返工清单，画布只在打开「代码事实」时写字。

## 理由

- **一层一问**：读一条线先问「行为还是依赖」，再问「哪一类、往哪去」。线型只回答第一问，叠加时不必切换图例。
- **地图与领土分开**：未证实是描述质量，交给返工清单；违规是系统问题，红色加字点名。
- **异常写字**：异常少、需要注意，写字自解释；常态用通道，一眼区分。图形化地表达抽象关系（如回程钩）容易误读（ADR-0034 修订）。
- **一致性优先于惯例**：结构视角放弃「子类 = 实线」的 UML 惯例，换来全图一个语法；形态仍由端点记号区分，信息不丢。

## 被否决的选项

- **维持现状**（线型为各视图私有通道）：叠加越来越多，私有通道在同一张图上互相冲突。
- **线型表事实状态、另找通道表行为 / 依赖**（如粗细或颜色）：粗细已表条数，颜色已表种类；行为 / 依赖是最基本的区分，应占最直观的通道。
- **时间耦合也改虚线**：耦合不是依赖，画成虚线会误导「这里有导入」；保留波浪线，作为唯一例外写明。
