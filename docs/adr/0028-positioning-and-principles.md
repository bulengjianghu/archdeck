# ADR-0028：产品定位与原则

- 状态：已采纳
- 日期：2026-10-24
- 决策人：项目负责人（第四轮后与协调者四轮问答，2026-10-24 认可）
- 关联：[docs/system/README.md](../system/README.md)（正文）；[docs/README.md](../README.md) §1、§2；01 §1、§2；修订 [ADR-0020](./0020-local-workbench.md) 的定位叙事（「看见 · 对照 · 守住」保留为功能分组，产品目标以 docs/system 为准）；由本文引出 [ADR-0026](./0026-relations-are-interactions.md)、[ADR-0027](./0027-module-roles.md)；与 [ADR-0019](./0019-human-owned-writes.md)、[ADR-0022](./0022-relation-semantics.md)、[ADR-0023](./0023-sketch-reviewed-and-evolution.md)、[ADR-0025](./0025-sketch-as-thinking-medium.md) 的结论一致，原则上溯到本文

## 背景

第四轮（ADR-0025）做完后，负责人与协调者对产品定位做了一轮讨论，起因是几个看似局部的问题指向同一个缺口——没有一份可引用的「为什么这样取舍」：

| 现象 | 追问后的结论 |
|---|---|
| 关系数随生成越来越多（h5player 300+），图看不过来 | 「看」的本质是维持架构师的**心智模型**，不是把信息可视化；超出认知带宽的呈现等于没有呈现 |
| `depends` 写不写、写多少说不清 | 谁导入谁是**代码事实**，工具能算出来；人或 AI 再写一遍是重复，且永远写不全 |
| 下钻到第三级后没有分级，工具模块的线占满画布 | 事实不可隐藏，但可以**分类后折叠** |
| 场景只有现状 | 系统 = 结构 + 行为 + 原则，行为同样需要目标态与验收（已知缺口） |
| AI 生成越来越快，架构师逐条盖章 | 对抗认知卸载的机制是**确认层**：没有被人确认的描述只是主张，代码一变确认失效 |

讨论还确认了三个前提：来源不限（代码、AI、人都可以产出描述），但必须**可区分**；草图是思考的介质、模型是记录的载体（ADR-0025）；工具先在自身验证再推广（ADR-0023 的推进策略）。

## 裁决

1. **docs/system 为最高层真源**：[docs/system/README.md](../system/README.md) 回答「产品是什么、为谁、按什么原则取舍」——定位（外脑，不是替身）、三个目标（感知、对抗认知卸载、演化治理）、系统认知、九条原则 S1–S9、已知缺口。01–04 与 ADR 的结论都应能追溯到一条原则；与它冲突的规则以它为准，**改规则不改原则**，改原则须记 ADR。
2. **原则编号 S1–S9**，其他文档只引用编号、不复述；为与 02 的场景规则 S1–S18 区分，引用时写「原则 S<n>」。
3. **两份 ADR 由原则引出**：ADR-0026（依赖是事实，关系是交互）落实「关系表达交互，不表达知识」与原则 S6；ADR-0027（模块分级）落实原则 S4、S5。
4. **与原则冲突的规则逐条核对**：lint 的「全覆盖」导向（K7 要求每条值导入都有关系覆盖）改为「事实求全、描述求准、呈现求少」（原则 S6，规则 Q12，ADR-0026）；其余现行规则核对后未发现冲突。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 原则写进 01 §2 | 01 回答「做什么」，原则回答「按什么取舍」，后者约束 01–04 与 ADR 全部文档，放在其中一份里会被当成局部约定 |
| 原则只写在 CLAUDE.md 的工程原则里 | CLAUDE.md 是开发协作约定（怎么做），产品原则（做什么、不做什么）要对所有读者可见，且需要编号供规则引用 |

## 后果

- docs/README.md §1 加 docs/system 一行（读者所有人）、§2 加「定位与原则」的归属：其他文档只引用原则编号。
- 01 §1、§2 改为引用 docs/system 的定位、目标与原则，只保留 h5player 起点与功能目标分组（看见 · 对照 · 守住）。
- docs/system §4 每条原则的「落点」指向 02 的规则编号或文档位置；新增规则若找不到对应原则，先问它是否该做（原则 S1）。
- 已知缺口（docs/system §5）中「depends 仍是关系」「第二级以下无分级」由 ADR-0026、ADR-0027 解决；「决策不是一等对象」的第一步是模块 `adrs` 字段（规则 E9，需求 DV-13）；「行为没有目标态」不在第五轮范围。
