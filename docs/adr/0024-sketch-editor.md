## 背景

一期的草图只能手写 YAML。架构师要在画布上画：增删改层、模块、关系、接口，标核心与封闭，保存为人拥有的草图文件，画的时候就知道「实现后会有多少处偏差」。同时，这是**草图生命周期的第一个真实样本**：草图由协调者代架构师起草，AI 按草图展开 r1，评审两轮后定稿（r3）。

## 结论

1. **分层**：对草图定义的编辑与校验是关于被描述系统的知识（命令行同样需要），在模型层「意图」：`model.intent.edit`（`applyEdit`，按操作族分寻址、层、模块、移动、关系与接口、底稿）、`model.intent.validate`（`validateSketch`）、`model.intent.check`（一期的核验、生命周期与指纹比对，矛盾检查供校验共用）。撤销 / 重做、跟随、互斥是一次编辑会话的事，在视图状态层。
2. **编辑中的草图是一个值**：`EditSession`（目标、读取时的草图与指纹、草图、撤销栈、重做栈、stale），由纯函数改变；「脏」由草图与读取时的草图推出。编辑态下草图经 `loadModel` 成为 DeskState 的 `index`，导航树、画布、面板照常工作。
3. **画布与面板只发意图**：一个用户动作 = 一个 `EditOp` = 撤销的一步；文本字段一次提交为一步。
4. **写回只经一处**：`access.writer.sketch`——指纹比对 → 服务端校验（与页面同一函数）→ YAML 文档模型合并 → 更新指纹 → 拦截记录；文档的打开与保存与追加写入共用。
5. **设计的轮次从目录发现**：每轮说明在 AI 拥有的 `r<N>/revision.yaml`，design.yaml 只承载人拥有的目标、状态、基线、ADR、认可偏差与评审意见。
6. 新增规则 X7a–X7i、E8、Q11，修订 B2、细化 B6，来源均为「议」，实施结束后一次列给负责人裁决（ADR-0023 结论 6）。

1. 01 补需求 SK-6–SK-11、DV-12、AG-5；02 登记上述规则（待实现）；03 的意图、DeskState、视图状态转移、Layout、描述读取、描述写入、画布、属性面板、版本切换、应用外壳、agent 接口的职责更新；04 §1、§3.10、§5 改写；专题「工作台」「视图状态」「描述加载与版本」「架构治理」补编辑态。

3. 本设计的 r2、r3 说明暂放 `designs/sketch-editor/notes/`（读取侧尚不支持 `revision.yaml`）；r3 未在 design.yaml 登记条目，现有读取侧找不到 r3，正是 E8 要实现的缺口，实现后把 notes 迁成各轮的 `revision.yaml`。
