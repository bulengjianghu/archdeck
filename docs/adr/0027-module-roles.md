# ADR-0027：模块分级——核心、普通、共用件

- 状态：已采纳（待实现）
- 日期：2026-10-24
- 决策人：项目负责人（2026-10-24 认可草案；补充裁决：共用件在时序图里不画泳道，消息折叠为步骤上的角标）
- 关联：原则 S4、S5（[ADR-0028](./0028-positioning-and-principles.md)）；紧随 [ADR-0026](./0026-relations-are-interactions.md)；修订 [ADR-0023](./0023-sketch-reviewed-and-evolution.md) 的确认范围（Z4）与 [ADR-0025](./0025-sketch-as-thinking-medium.md) 的内外归属（X10）；规则 §1.1 角色、O2、O4、O6、O8–O11、P18、M16、Z4、X4、X7、X10、X18、U11、U12、Q13（02）；格式 04 §3.2、§3.10；需求 C-16、C-17、D-22、GV-12、GV-13、RV-3、SK-22

## 背景

| 现象 | 根因 |
|---|---|
| `core` 只允许在第二级、只影响根层的分层总览 | 分级只在一个层次上存在；下钻到第三级后所有子模块同等对待 |
| 下钻 DeskState 一屏十几个子模块，工具类模块（名称查询、标签常量、共用件）的线占满画布 | 被到处使用的模块每条关系都无信息量，却和真正的交互一样画出来 |
| 想「不显示工具模块」 | 违背「事实不可隐藏」（原则 S5）：隐藏会让人以为它不存在 |

机制因此是**分类后折叠**，不是不显示：每个模块属于一类，每一类有固定的呈现方式，折叠起来的东西始终有计数、可展开。

## 裁决

1. **模型字段 `role: core | shared`**（缺省为普通），可写在任意层次的模块上；迁移现有 `core: true`（M16）。`role` 属模块**对外的一面**，写在父草图（X10）。ADR-0026 的总线角色 `bus` 同在这个字段（M14）。
2. **核心**：大块常显；分层总览中跨层边默认隐藏、悬停或选中时显示（O4），推广到任意层次；进确认范围（Z4 推广到任意层次的核心）。
3. **普通**：常显；本层非核心的普通模块超过七个时自动折叠成「+N」，与分层总览同一手势（O6 推广，O8）。
4. **共用件**：收进本层框底部的「共用件」架，不画线；使用它的模块出「共用 ×N」角标，悬停或选中时才画线（O9、O10）。治理照跑环与违规；共用件反过来依赖普通或核心模块（反向依赖）单独报警（U12）。
5. **AI 建议共用件**：入度来自 ≥2 层或 ≥3 个兄弟模块、没有运行时出边、不在任何场景路径上、`kind` 为 `library` 或名称含 shared / util / labels；治理面板列「疑似共用件 N 个」，架构师一键认可写回草图（U11）。
6. **本层框常驻「共用件 N · 折叠 M」计数**（O11）；健康度加「共用件反向依赖」「共用件体量异常增长」两条提醒（Q13）。
7. **时序图里共用件不画泳道**（负责人补充裁决）：一端是共用件的消息折叠为另一端泳道上该步骤的角标（P18）。

顺序：紧随 ADR-0026——先把关系收成交互，再把共用件的交互收成角标。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 不显示共用件（按名称或 kind 过滤） | 事实不可隐藏（原则 S5）：折叠可以、隐藏不行 |
| 按入度自动分级，不写进描述 | 分级是架构师的判断（谁是核心、谁只是工具），工具只能建议；自动分级每次生成都可能变，心智模型跟着抖动 |
| 共用件在时序图里保留一条泳道 | 共用件被调用的次数多、信息量低，一条泳道会把所有消息拉到图的一侧；角标保留了「发生过」的事实 |
