# ADR-0007：源代码文件树与代码预览

- 状态：已采纳
- 日期：2026-10-20
- 决策人：项目负责人（需求与方向，见「结论」1–6；结论 3 于 2026-10-21 裁决）；实现者提出的细化规则（来源「议」）列在下文，待负责人确认
- 关联：需求 SR-1–SR-8、W-1、W-4、W-5、W-7，验收标准 §6.4；领域模型 §1.6、§2.13（G）；ADR-0006

## 背景

架构台只到模块为止。架构师看到一个模块后，常常还想知道三件事：它由哪些文件组成，对外从哪个文件导出什么，导出与描述里写的接口是否一致。反过来，看到一个文件时，也想知道它属于哪个模块、在图上的什么位置。描述里已经有 `codeRefs`，但目前只作为文字显示，没有和真实的源码对上。

## 结论

### 1. 源码直接读本地文件夹，不做快照

- 开发服务器按 `system.source.repo` 找到被描述项目的源码根目录，每次请求时实时列出文件清单（G1、G2）。
- 根目录的解析：先拼在工作区根目录后面，工作区根目录默认是本包往上三级（`work4/`），可以用环境变量 `ARCH_WORKSPACE_ROOT` 整体覆盖，也可以用 `ARCH_SOURCE_ROOT_<项目>` 单独覆盖某个项目。
- 源码不在本地时（如 media-web），页面提示「源码不在本地」以及尝试过的路径，不报错。
- **构建态不含源码**：静态站点只搬运描述，不搬运被描述项目的源码，所以文件页签提示「构建产物不含源码，请用 `npm run dev` 查看」。理由：源码体积大、可能涉密，而且一旦做成快照，就会和描述各自过时。

### 2. 文件按 codeRefs 归属到模块

- 规则（G3–G8）：
  - 上级模块的文件是子树文件的并集。
  - 祖先和后代同时匹配一个文件，属于包含关系：取最深的那个模块，不算冲突。
  - 两个互不包含的模块同时匹配一个文件，才算归属冲突，报警告。
  - 没有任何模块匹配、也不在忽略清单里的文件是未归属文件，报警告。
- 归属是关于被描述系统的知识，放在模型层的新子模块「源码归属」。接入层只给文件清单，不解释文件属于谁。
- 忽略清单写在描述里：`model/<项目>/source-ignore.yaml` 的顶层键 `sourceIgnore`（glob 列表）。它随描述一起校验、一起热更新。

### 3. 页面保持只读，不提供任何写忽略清单的操作

负责人在三个选项中选了 C（2026-10-21）：

| 选项 | 内容 | 结论 |
|---|---|---|
| A | 页面只读；未归属文件旁提供「复制忽略条目」，把 YAML 片段复制到剪贴板，由人或 AI 粘贴 | 未选 |
| B | 开发态提供「忽略」按钮，开发服务器开写端点，只追加忽略清单这一个文件 | 未选：开了写入口，且给以后其他写需求（如 C-12）开了先例 |
| **C** | 页面上不提供任何操作；未归属文件只在文件树、面板与 `lint:model` 中列出，由人或 AI 编辑忽略清单 | **采纳** |

理由：描述（含忽略清单）只由人或 AI 修改，是设计原则 1 的原意；处理未归属文件本来就是「补 `codeRefs`」或「写进忽略清单」二选一的判断，交给维护描述的人或 AI 一并做，页面只负责把问题列清楚。

### 4. 模块面板列出文件、入口与导出

- 入口文件按顺序取（G10）：描述里的 `entry` → 模块目录下的 `index.ts` → 模块目录下 `package.json` 的 `exports` 或 `main`。都没有时，就是没有入口。
- 导出由开发服务器用 TypeScript 编译器解析，只做语法分析，不做类型检查，给出名称与签名，并顺着相对路径的再导出往下找（G11）。
- 导出与 `provides` 按名称对应，对不上的分两组单独列出：「导出了但描述里没有」和「描述里有但入口没导出」（G12）。

### 5. 文件也是一种选中

- 选中多了一种对象：文件，URL 写成 `sel=f:<路径>`。运行视角下选中文件就是钉住（V3），无需新的焦点规则。
- 两个方向的联动：
  - 选中模块时，文件树高亮它的文件（G13）。
  - 选中文件时，把它的归属模块用 `mapEndpoint` 投影到当前层次，高亮画布上的对应节点，模块树也同步展开到归属模块（G14）。

### 6. 代码预览和时序图共用分屏右侧那一栏（副栏）

- 分屏的第二块从「时序图」泛化为**副栏**，栏顶有页签「时序图」「源代码」（G15、W-4）。
- 结构视角下，选中文件时副栏出现，只有「源代码」页签。
- 预览只读，用 Shiki 按扩展名做语法高亮，带行号；文件过大或是二进制时不预览。
- 导航树新增「文件」页签（T1 修订）。

## 实现者提出的细化（来源「议」，待负责人确认）

| 规则 | 细化 | 理由 | 被否决的选项 |
|---|---|---|---|
| G2 | 文件清单：在 git 仓库里就按 git 的忽略规则列出（已跟踪的文件，加上未跟踪也未忽略的文件）；不在 git 仓库里则排除 `node_modules`、`.git`、`dist` 等目录 | 构建产物、依赖目录、覆盖率报告都不是源码，会淹没真正的未归属文件 | 列出目录下的全部文件 |
| G3 | 不含通配符的 `codeRefs` 匹配同名文件，或者这个目录下的全部文件 | 描述里已经有写目录的情况；只认文件的话，这类模块会一个文件都没有 | 只认文件 |
| G6 | 冲突的文件同时列在每个冲突模块下，并标「归属冲突」；投影时所有冲突模块都高亮 | 随便挑一个模块会掩盖问题；同时列出，冲突在哪里一眼可见 | 取声明在先的模块 |
| G8 | 已被模块匹配的文件不受忽略清单影响（归属优先）；被忽略的文件仍然出现在文件树里，标为灰色 | 忽略的作用是「不再报警」，不是把文件藏起来；归属优先，能避免一条宽泛的忽略规则误吞源码 | 忽略的文件不出现在文件树里 |
| G9 | 归属警告只对当前版本报；`lint:model` 在源码在本地时一并报出，按警告计 | 设计版本不对应代码，报出的警告都是噪声；警告不影响「0 个错误」的门槛 | 设计版本也报 |
| G10 | 模块目录 = `codeRefs` 去掉通配符以后的公共目录；按约定找到的 `index.ts` 或包入口必须是本模块子树内的文件，`entry` 不受这条限制，但 `entry` 指向的文件不存在时报警告 | 公共目录可能是上级目录，那里的 `index.ts` 往往属于别的模块（如 `player-index`），不能误认成本模块的入口 | 只看第一条 `codeRefs` 的目录 |
| G11 | 导出解析只做语法分析，不做类型检查；顺着相对路径的 `export *` / `export … from` 最多追 5 层；签名取声明本身去掉函数体，最多 25 行 | 语法分析是毫秒级的，不需要整个工程的 tsconfig；签名长度与描述格式 §3.3 一致 | 用类型检查器推导签名（慢，还依赖工程配置） |
| G12 | 模块的接口取 `provides`，加上 `owner` 是本模块或其子孙的接口；名称对应：接口 `name` 去掉括号、泛型以后与导出名相同；默认导出不参与对应 | 描述格式里接口的 `owner` 就是提供方，不少描述只写 `owner` 不写 `provides`；入口通常把子模块的接口一起导出。描述里的接口名就是导出的标识符；默认导出没有名字可比 | 只认 `provides`；按签名相似度对应 |
| G14 | 归属模块就是当前父模块或它的祖先时，画布上不高亮任何节点，面板注明「属于当前层次本身」；分层总览里，带与路径上的核心模块一起高亮 | 与 `mapEndpoint` 的 `skip` 一致；分层总览只露出核心模块，只高亮带会丢掉定位信息 | 落在本层外时一律不高亮 |
| G15 | 副栏的页签跟着最近的指向：选中文件切到「源代码」，打开场景或移动播放头切到「时序图」；副栏保留最近预览的文件，直到关闭；结构视角下关闭源代码后副栏消失 | 与 T1「进入运行视角切到步骤页签」同理；改选其他对象时预览不跟着消失，便于对照「这个模块的文件」 | 预览只跟随当前选中（每次改选都会让副栏跳动） |
| T1 | 导航树页签改为「模块」「文件」「步骤」，选中文件时切到「文件」 | 与 G15 同理 | 页签不随选中变化 |

## 后果

1. 「页面只读」不变：页面不写任何文件，也不提供写忽略清单的操作（选项 C）。
2. 接入层新增「源码读取」，模型层新增「源码归属」，视图状态层新增同步适配器「源码同步」，呈现层新增文件树、源代码预览、文件面板，分屏第二块泛化为副栏。描述格式新增 `entry` 与 `sourceIgnore`。
3. 01 §2.2 的非目标从「不展示文件」改为「不在图上展示文件、函数、类等模块以下的结构」：源代码只以文件树和只读预览出现，不进画布。
4. 构建态的部署形态不变，仍然不依赖后端；源码相关的功能只在开发态可用。
