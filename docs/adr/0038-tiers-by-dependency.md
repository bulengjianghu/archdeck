# ADR-0038：普通层次按依赖分层，拆分信号

- 状态：已采纳，已实现（第十二轮 A）
- 日期：2026-10-28
- 决策人：项目负责人（2026-10-28：「越被依赖越在下层，依赖少的、流程起点的模块越在上层」；修订 1：大环照样分层；修订 2：「不改分层原则，不回退」，有交互、没依赖的层次是模块拆分不合理的信号；「模块拆分的最小单位是文件」）；起草：第十二轮执行会话 A
- 关联：[ADR-0021](./0021-orthogonal-routing.md)（正交走线，L11）、[ADR-0031](./0031-three-views-and-structure-view.md)（并集布局 L15、两个视角同一份布局 V12）、[ADR-0016](./0016-concept-submodules-and-type-deps.md)（概念子模块 K5a，本 ADR 把它改为拆分信号）、[ADR-0020](./0020-local-workbench.md)（环只按值依赖 Y1）；规则 L28、L29、K21、K22（新增），L15（注明上下由 L28 定）（02）；需求 C-35（新增）、C-6（修订）（01）；验收 01 §6.25

## 背景

子模块多的层次关系复杂，难以迅速建立心智模型。普通层次原来交给 elk 按交互边与结构边的并集排上下（L15），`notifies` 与依赖方向相反、由 elk 贪心破环，位置不可预测；同一层次里一条线朝上还是朝下没有含义，架构师只能逐条读箭头。

## 裁决

1. **用位置代替箭头**：普通层次按**本层值依赖**分层（与 Y4 同口径，只引类型不算）——被依赖的在下、本层没人依赖的（入口）在第 1 层、其余按到底部的最长依赖链排；强连通分量合为一组、整组同层，再大也照样分层（修订 1）；既不依赖别人也没人依赖的孤立节点不占层（L28）。交互边与只引类型的束不影响层号，只参与走线。
2. **向上的线只可能是控制反转**：依赖全部朝下时，向上的交互只能是通知、流、经端口 / 总线 / 通道（含回调）。不是控制反转却向上的给提示（info，不作违规）——多半是没标的回调或 postMessage，分层顺带暴露描述问题（K22）。
3. **作者声明的层优先**：子模块全是层时仍用分层总览（O1）；没有代码事实时不分层，按边排。
4. **分层是模型层的知识**：换成命令行也要，所以在 `governance/tiers.ts`（`levelTiers`），布局只消费层号；`arch tiers` 可查。
5. **不回退（修订 2）**：有交互、没依赖的层次不按交互另排，它本身就是信号；同样，子模块不占文件、两个模块共用文件、超长文件都指向「先拆文件」——**模块拆分的最小单位是文件**（K21）。K5a 的概念子模块（ADR-0016）从此是拆分信号，不再是常态。
6. **层带只在层多时画**（≥ 7 个节点且 ≥ 3 层），位置规则所有层次一样（L29）。

## 实现要点（细节，执行会话自定）

- elk 没有「指定层号」的可用选项（`layerChoiceConstraint` 在 0.11 不生效），改用 INTERACTIVE 破环与分层，按坐标定层：模型层的层号由 `elkLayers` 展开为 elk 层，同一层内有边相连的错开为子层（elk 的层内不能有边，否则会把节点往下推），孤立的单列在侧边，全部孤立时排成网格；不拆连通分量（否则没有边的节点被单独排到顶上）。
- elk 的中间边标签在分层前插入为无坐标的占位节点，会让 INTERACTIVE 分层压缩、打乱层号，所以分层时边的标签不交给 elk，由画布按走线中点放（会话 B 的线的清晰度梳理同时接手标签位）。
- 阈值：层带门槛 7 个节点 / 3 层沿用候选实测口径；超长文件沿用 G20（缺省 500 行），不另设阈值。
- 三个项目 62 个有依赖的普通层次全部层序正确（层与层不交叠），环组框全部画出。

## 代价与未决

- 同一层内的交互链（如 h5player「MUs 媒体单元」第 3 层：加载 → 解封装 → 缓冲 → 解码）会错开成子层，层带变高；这正是 K21③ 的信号，不另想办法压平。
- 不写 `via` 的回调、通知会显示为向上的委托并提示；写了 `via` 的一律算控制反转（议，见负责人清单）。
