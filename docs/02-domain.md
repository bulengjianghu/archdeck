# h5p-arch-desk 领域模型与规则

> 本文是**概念定义**与**领域规则**的唯一真源。需求按规则编号引用，架构说明规则在哪里实现，单元测试按本文的规则清单逐条穷举。
> 描述文件怎么写见 [04-description-format.md](./04-description-format.md)；字段的格式以 `schema/arch-file.schema.json` 为准，字段的含义以本文为准。
> 状态标注：**已实现**；**待实现**（已定稿未开发）。

## 1. 概念

### 1.1 架构描述：被描述的系统

**系统**（System）：一份描述的根。属性：`id`、`name`、`description`、`source { repo, commit, generatedAt }`（生成来源，对应被描述代码的版本；`repo` 同时决定源码根目录，G1）。

**模块**（Module）：承担一组明确职责的单元，可以包含子模块，形成树。

| 属性 | 必填 | 含义 |
|---|---|---|
| `id` | ✅ | 全局唯一、稳定，如 `kernel.state-machine` |
| `name` | ✅ | 显示名 |
| `responsibility` | ✅ | 职责：负责什么、不负责什么（缺失只提醒） |
| `kind` | | 类别，如 `layer` / `package` / `subsystem` / `component` |
| `principle` | | 实现原理（Markdown） |
| `provides` / `dataStructures` | | 对外接口、核心数据结构的 ID |
| `children` | | 子模块；也可在文件顶层用 `parent` 把模块挂到已有模块下 |
| `status` | | `current`（已落地，缺省）/ `target`（目标态，未落地）/ `deprecated` |
| `core` | | 核心模块，在上一级的分层总览中直接露出（§2.3） |
| `codeRefs` / `docRefs` | | 源码路径或 glob（相对源码根目录，§1.6）、设计文档链接 |
| `entry` | | 对外入口文件（相对源码根目录）；不写时按约定推出（G10） |
| `owner` / `tags` | | 负责人、标签 |
| `designNote` | | 仅设计版本：为什么这样设计 / 调整（Markdown），不参与版本对比 |

**层**（Layer）：`kind: layer` 的模块，额外有 `order`（层序，越小越靠上、越易变，必填）、`abstraction`（抽象原则，必填）、`includes` / `excludes`（应 / 不应包含什么）、`mayDependOn`（允许依赖的层；有代码事实时按默认拒绝校验，U2）。

**关系**（Relation）：两个端点之间的一条有向联系。属性：`id`、`from`、`to`（模块或外部参与者）、`type`、`interface`、`payload`（数据结构 ID，一个或多个）、`mode`（`sync` / `async`）、`pull`（只用于 `streams`：拉取型流）、`via`（经由，可选，见下表）、`description`。

一次运行时交互有五个互相独立的维度（ADR-0022）：**控制流**（谁发起）、**知识**（谁知道谁，编译期）、**语义**（命令 / 通知 / 流）、**同步性**（同步 / 异步）、**平面**（控制面 / 数据面）。控制流与知识可以相反（通知：控制流 发布者 → 订阅者，知识 订阅者 → 发布者）。运行时关系的箭头一律是**控制流方向**，与场景消息同向；知识方向是代码事实（K5、面板「知识」一行），不借箭头表达。

| type | 语义 | 方向（箭头） | 运行时关系 | 平面 |
|---|---|---|---|---|
| `depends` | 编译期知道：导入、引用类型或值 | 依赖方 → 被依赖方 | 否 | — |
| `implements` | 实现契约（端口、接口） | 实现方 → 契约所在模块 | 否 | — |
| `calls` | 命令：请求并期待结果，同步返回或异步回调 | 发起方 → 接收方 | 是 | 控制 |
| `notifies` | 通知：不期待结果、一对多、发布者不知道订阅者 | 发布者 → 订阅者 | 是 | 控制 |
| `streams` | 流：同一通道上连续的数据项，关注吞吐与背压；两端只知道端口、由第三方接线 | 推送方 → 接收方；`pull: true` 为拉取型流，箭头仍指数据去向 | 是 | 数据 |

旧名 `event`（= `notifies`，箭头为订阅方 → 发布方，加载时翻转两端）与 `dataflow`（= `streams`）是别名，加载时映射并提醒迁移（M12），一轮后删除。

**import 与 depends / implements**：一条导入是**证据**，`depends` / `implements` 是**主张**。知识有三级阶梯：只引数据类型 < 实现契约 < 使用实现。只导入 B 的数据类型是 `depends`（K7 不算未描述）；导入 B 声明的接口、或类的 `implements` / `extends` 指向 B，是 `implements`（K5 的证据）；导入 B 的函数、类等值来使用，是 `depends`（运行时另有 `calls` 等）。`implements` 的目标必须声明接口（M11）。

| `via`（经由） | 含义：经此传递，两端之间的静态导入在原理上证实不了；写了即不判定证实（K5b） |
|---|---|
| `http` / `hmr` / `inject` / `router` / `callback` / `port` | 跨进程的 HTTP 请求 / 开发服务器的 HMR 事件 / 经框架注入（provide / inject、依赖注入的端口）/ 经路由导航 / 经组装者注入的回调 / 经端口接线（两端只知道端口，由第三方组装，常见于 `streams`） |

**接口**（Interface）：模块对外暴露的能力，独立定义、可被多个模块和关系引用。属性：`id`、`name`、`owner`（提供方模块）、`signature`（TS 风格签名）、`description`、`semantics`（前置条件、副作用、错误）。

**数据结构**（DataStructure）：接口和关系中交换的数据。属性：`id`、`name`、`definition`（TS 类型）、`description`、`invariants`（不变量）。

**外部参与者**（Actor）：系统之外主动发起交互的实体，不进模块树。属性：`id`、`name`、`kind`（`user` 人的操作 / `system` 外部系统主动调用或推送 / `time` 定时与超时）、`description`。参与者与其入口关系构成**系统上下文**。

### 1.2 结构视图

| 概念 | 定义 |
|---|---|
| **层次**（Level） | 当前父模块（根层次的父模块是系统）。画布只呈现它的直接子模块及其间的关系 |
| **视图节点** | 本层的子模块；**边界节点**（系统内、本层外的模块，提升为最近公共祖先下它那一侧的子模块）；**参与者节点**（系统外） |
| **视图边** | 关系在本层的投影，同一对节点之间按关系类型各一条（L5）。**直接边**：两端恰为两个子模块的一条关系；**聚合边**：由更深的关系提升而来或含多条关系，标注条数；**边界边**：一端是边界节点 |
| **模块树** | 系统的完整模块层级（系统为根），工作台左侧导航树的「模块」页签按它列出，与层次和选中同步 |
| **层次顺序** | 模块之间的先后：从根起逐级比较两者的祖先，同一父模块下层按 `order`、其余按描述顺序；同一父模块的模块因此相邻，上层在前。时序图泳道与边界节点行都按它排（P9、L4） |
| **分层总览** | 当前父模块的子模块全是层时的呈现：每层一条**带**（层名与抽象原则、核心模块、`+N` 个非核心模块、可依赖的层），带间是层间聚合边；**核心跨层边**是核心模块的跨层关系，默认隐藏 |

### 1.3 场景与回放

| 概念 | 定义 |
|---|---|
| **场景**（Scenario） | 一条有名字的执行链路，如「首次 play」「方案切换事务」。属性：`id`、`name`、`description`、`cause`（触发原因文字）、`steps`。一切动态表达都基于场景 |
| **步骤**（Step） | 场景描述里的树。**消息步骤**是叶子：`call`（同步调用）、`async`（发出后不等待）、`return`（显式返回）；属性 `id`（可选，场景内唯一）、`from`、`to`（模块或参与者）、`label`、`relation`、`interface`、`payload`、`note`。**组合步骤**是容器：`alt`（条件分支，各分支有 `when`）、`loop`（`while`）、`par`（并行分支）、`ref`（引用另一个场景） |
| **步骤与关系** | 关系是静态的「会这样交互」；消息步骤是运行时关系的**一次发生**。一条关系可被多次经过；一个步骤最多对应一条关系，也可以没有 |
| **帧**（Frame） | 一条消息步骤展开后的一次出现，回放的最小单位，与层次无关 |
| **回放计划** | 展开后的帧树：`loop` 展开一遍、`par` 串行、`ref` 内联，只在 `alt` 处分叉为**分支点** |
| **回放路径** | 按已选分支从回放计划走出的线性帧序列，在未选分支的分支点处截止 |
| **路线** | 回放路径上依次经过的分支点及所选选项，加上截止处待选的分支点；回放控制条常驻显示（F6f） |
| **进度** | 场景走到哪一步，以帧 ID 记录（代码中的播放头 `frameId`）；为空表示在开头（尚未开始）。用于「下一步」、走过的边与进度条；只随用户选中步骤（单步、指向、拖动进度）移动，没有自动播放。是内部概念，用户看到的是选中的步骤（V7） |
| **可见消息** | 帧投影到当前层次后，连续落在同一对节点之间的视图边（同方向）或同一节点内部的帧合并成的一条消息，是本层单步的单位 |
| **配对返回** | 显式 `return` 与它回应的 `call` 互为配对（F7）；步骤的「输出」取配对返回携带的数据 |
| **内部活动** | 两端落在本层同一个子模块内的帧，只高亮该节点 |
| **经由上层关系** | 步骤绑定了关系（显式或推断，S13），但关系一端是当前层次本身或其祖先，本层没有它的视图边；消息照常可见，与「结构中未建模」（步骤没有绑定任何关系）区分（P11、P15） |
| **场景所在层次** | 所有帧端点的最近公共祖先，即最适合看这个场景的层次 |
| **触发者** | 第一条消息的发送方 |
| **步骤树** | 回放计划按组合框嵌套的全貌：`ref` 内联、`loop` 一遍、`par` 按书写顺序、`alt` 列出全部分支；导航树的「步骤」页签按它列出，与进度同步 |

### 1.4 视角与选中

| 概念 | 定义 |
|---|---|
| **视角** | **结构视角**回答「系统由什么组成、怎么连接」；**运行视角**回答「某个场景这一次怎么走」。由是否打开了场景决定 |
| **选中** | 唯一且排他的主语：用户指向的一个对象——模块、关系、视图边、参与者、文件，运行视角下另有**步骤**与**场景**；只能单选，选中新的即取消旧的。属性面板显示选中的对象（结构视角无选中时显示当前父模块）。运行视角下选中的步骤就是进度所在的一步；进度在开头时选中的「步骤」即场景本身（V2、V7） |
| **指向** | 用户以某个对象为目标的操作：单击、双击下钻、搜索跳转、导航树中的单击 / 双击、指向某一步。悬停不算 |
| **选中突出** | 运行视角下只有被选中的那一个对象用选中样式：选中步骤突出该消息，选中其他对象突出相关泳道（R15、R16） |
| **静态关系显示方式** | 运行视角下舞台对不参与本场景的节点与静态边的呈现：隐藏（默认）/ 淡显 / 全显（V8） |

已删除：焦点（跟随 / 钉住）、焦点突出，由「选中」与「选中突出」取代（ADR-0012）。

### 1.5 版本

| 概念 | 定义 |
|---|---|
| **当前版本** | 由 AI 按代码生成的描述，`source.commit` 对应代码版本 |
| **设计版本** | 迭代前由 AI 在当前版本上起草的描述，不对应代码；有状态 `draft` / `reviewing` / `accepted` / `implemented` / `abandoned`（ADR-0002） |
| **轮次** | 设计版本的一轮完整快照（r1、r2…），记录本轮说明、待确认问题、评审意见 |
| **对比基线** | 设计版本与之对比的描述：当前版本，或上一轮 |
| **差异** | 按 ID 对齐的新增 / 修改 / 删除；**涉及变更数**（△N）是某个模块子树与相关关系上的变更条数 |
| **归档** | 状态为 `implemented` 或 `abandoned` 的设计版本：迭代已结束，项目列表不再列出，仍可从版本切换打开 |
| **基线漂移** | 设计起草时的基线提交与当前版本的 `source.commit` 不一致 |
| **提交版本** | 描述在某个 git 提交时的快照（项目描述目录在该提交的全部描述文件），由开发服务器读 git 得到；与设计版本一样相对对比基线标出差异，用来「看见演化」（E5、E6） |

### 1.6 源代码

| 概念 | 定义 |
|---|---|
| **源码根目录** | 被描述项目的源码所在的本地文件夹，由 `system.source.repo` 解析（G1）；必须在本地（本工具是本地开发工具的前提） |
| **文件清单** | 源码根目录下的源码文件（相对路径），由开发服务器实时读取，不做快照（G2） |
| **归属** | 文件 → 模块：按模块的 `codeRefs` 匹配，祖先与后代同时匹配时取最深的（G3、G5）。一个文件的**归属模块**通常只有一个；模块的**文件**是子树内全部归属文件的并集（G4） |
| **未归属文件** | 没有任何模块匹配、也不在忽略清单中的文件（G7） |
| **归属冲突** | 一个文件被两个及以上互不包含的模块匹配（G6） |
| **行数 / 超长** | 源码文件的物理行数（只统计 TS / JS / Vue 等，G19）；超过阈值 `sourceLimits.maxLines`（缺省 500）的为超长（G20） |
| **忽略清单** | 描述中的 `sourceIgnore`：一组 glob，命中的未归属文件不再报警（G8） |
| **入口文件** | 模块对外的 index 文件，可以没有（G10） |
| **导出** | 入口文件导出的符号：名称、类别、签名（G11）；按名称与 `provides` 对应（G12） |
| **副栏** | 画布区分屏的第二块，页签「时序图」「源代码」；**预览文件**是副栏「源代码」页签正在显示的文件（G15） |

### 1.7 架构治理

| 概念 | 定义 |
|---|---|
| **代码事实** | 从源码确定性提取的依赖，与 AI 生成的描述相对照；只对当前版本存在（K8） |
| **文件依赖** | 一个源码文件对另一个的编译期依赖（K1）：**依赖方**文件与行号、**目标**（声明被引用符号的文件）、**经由**（直接导入的文件，如 barrel 入口，K3）、种类（`value` / `type`） |
| **外部依赖** | 解析不到源码清单内文件的导入（三方库、Node 内建），按包名计数，不进事实（K2） |
| **模块依赖** | 文件依赖按归属提升到模块：依赖方模块 → 被依赖方模块，带全部文件证据；一端未归属、已忽略或归属冲突的不提升（K4） |
| **已证实 / 未证实** | 描述的关系在模块依赖中有 / 没有对应（K5）；未证实的编译期关系、以及两端之间没有任何依赖的运行时关系报警告（K6） |
| **结构性实现** | `implements` 关系有对应的模块依赖，代码只引了目标模块的数据类型（类型、枚举），没有引用它声明的接口，也没有类 `implements` / `extends` 它：TS 不要求写 implements 子句，契约由结构满足，代码未显式声明（K5、ADR-0022） |
| **证据像 depends** | `implements` 关系有对应的模块依赖，代码引用了目标模块的函数、类或变量，却没有引用它声明的接口、也没有类 `implements` / `extends` 它：代码看起来是「使用实现」而不是「实现契约」（K5、ADR-0022） |
| **端口三角** | 一个声明了接口的模块的三方：定义（它的接口）· 实现者（`implements` 它的模块）· 使用者（`depends` / `calls` / `streams` 它的模块）（K11） |
| **宿主** | 模块自身或最近的、有直接归属文件的祖先；没有自己文件的子模块（概念子模块）以宿主的文件承载，两端宿主相同的关系不判定（K5a） |
| **未描述依赖** | 有值导入、却没有被任何关系覆盖的模块依赖；只引类型的不算（K7） |
| **架构规则** | 架构师的意图，写在描述的 `rules`（`rules.yaml`）：层规则、依赖白名单 `mayDependOn`、访问面 `exposes`、例外 `allow`、环的容忍 `cycles`（U1–U5、Y3）。默认拒绝：写了白名单即只许这些 |
| **访问面** | 模块子树外只能经由哪些文件访问它，相当于 Sonargraph 的 interface；`entry` 表示模块的入口文件（G10） |
| **违规** | 违反架构规则的模块依赖，一条对应（规则种类、规则所在、两端模块），带文件证据；按基线分**新增 / 已知**，命中例外的为**已豁免**（U6、U8） |
| **模块环 / 文件环** | 只按值依赖：模块依赖图 / 文件依赖图去掉只引类型的依赖后，规模 ≥ 2 的强连通分量（Y1）；**本层的环**是投影到当前层次后的强连通分量（Y4） |
| **环度** | 各环规模的平方和：一个 10 节点的环为 100，两个 5 节点的环为 50（Y2） |
| **基线** | 某一时刻的违规键与环度，存于 `governance/baseline.json`，由人生成并提交（U7） |
| **门禁（棘轮）** | 基线之外的新增违规、环度上升为错误；基线之内只提醒，存量可以逐步偿还但不许变坏（U8） |
| **写前判定** | agent 写一条依赖之前询问是否允许：允许 / 拒绝 / 无约束，附环影响与目标模块的语义（Q2） |
| **拦截记录** | agent 接口每次判定与重新扫描追加的一行记录，`governance/ledger.jsonl`（Q4） |
| **返工清单** | 当前版本里交给人或 AI 修正的全部问题，**按根因聚合**为**返工项**：每项带严重度、规则编号、根因所在的描述位置、受影响的文件或步骤（文件:行）与建议动作（补 codeRefs / 补关系 / 加例外 / 加忽略 / 补步骤 relation 等，附可粘贴的 YAML 片段）（Q7–Q9） |

## 2. 规则清单

**编号**：前缀表示领域，编号不复用；删除的规则保留空号并在组末注明。
**来源**：**定**＝项目负责人决定或确认（原「议」规则于 2026-10-22 由负责人批量确认，ADR-0020）；**推**＝由其他规则直接推出；**议**＝设计提出、待负责人确认（新增时先标议，列给负责人裁决）。
**所在**：实现与单测的位置（模块名见 [03-architecture.md §3](./03-architecture.md)）。模型层的规则是「架构查询」，视图状态层的是「会话规则」。
