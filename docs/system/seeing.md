# 看：在有限带宽内建立心智模型

> 本文是「看」（[README](./README.md) §2 目标「感知」）的体系框架：从认知事实推出设计定律，再落到看什么、怎么看、怎么动、守哪些纪律。它只组织框架、引用编号，不复述规则——规则内容以 [02](../02-domain.md) 为准，理由以 ADR 为准。状态：负责人 2026-10-28 审核确认；第十四轮（F1、F3–F5、F7–F16）已实现，理由见 ADR-0041–0049；F2 提炼已裁决（方案甲：草案是一张草图）、与 F6 一起移到第十五轮——声明 → 校验 → 守住的闭环尚未闭合（§7）。第十三轮束干线 [ADR-0040](../adr/0040-bundle-trunks.md) 已否决。
>
> 「对照」（描述与代码互证）与「守住」（意图、确认、门禁）不在本文；本文只写「看」给它们留的接口（§6）。

## 0. 一句话

**看 = 让架构师在不超过认知带宽的画面上，快速建立并维持正确的「结构 + 行为 + 原则」心智模型。** 目标是懂，不是全：把全部信息摆出来让人自己过滤，等于没有呈现。

## 1. 第一性原理：四条认知事实 → 四条设计定律

| 认知事实 | 设计定律 | 一句话 | 原则 | 落点（举例） |
|---|---|---|---|---|
| 人一眼只能持有七个左右的主体 | **少**：按距离与信息量分级 | 远景看主干、近景看细节；节点超出折叠不缩小，线按信息量分级（§3 手段 4）；折叠必有计数；文字也由远及近——先一句话，再维度，再证据 | SP4、SP5 | O8–O11、L21；面板排序（01 §4 面板表、V6、V13、D-5）；线的分级（第十四轮 F9–F11） |
| 读图靠位置记忆，位置一跳就要重建地图 | **稳**：位置不动 | 节点位置只由层次与收起态决定；切视角、选中、悬停、展开、回放都只加不挪 | — | V12、L20、L27、V5；[ADR-0036](../adr/0036-stable-selection-surface-dots.md) |
| 视觉通道前注意可读，但每个通道只装得下一个维度 | **清**：一个通道一个维度 | 位置 = 方向，线型 = 交互还是依赖，颜色 = 交互种类，端点 = 形态，线宽 = 条数，标签位 = 异常与机制；醒目度跟信息量走，不跟条数走 | — | L10、L16、L18、L26、L28；[ADR-0018](../adr/0018-edge-encoding.md)、[ADR-0035](../adr/0035-line-grammar.md) |
| 分不清「算出来的」与「说出来的」，就哪条线都不敢信 | **真**：事实与主张分开画 | 依赖事实与交互主张分图；声明的层与算出的层同一画法、状态记号区分；追不到代码的标在线上，不藏 | SP2、SP5 | [ADR-0031](../adr/0031-three-views-and-structure-view.md)、L26；层的状态记号（第十四轮 F8） |

四条定律互相牵制：**少**与**真**是一对刻意保留的张力（少看 vs 不藏），解法是「折叠必计数、展开一键可取、例外照画（逐条的逐条画，成组的按组画并带计数）」；**稳**约束**少**的手段——折叠、展开、聚焦、约简只能改可见性，不能改位置。

## 2. 看什么：心智模型的三个对象

| 对象 | 回答 | 载体 | 画在哪 |
|---|---|---|---|
| **结构** | 由什么组成、谁知道谁、谁对谁做什么 | 模块（职责、表面、子模块、角色）+ 两种关系（§2.1） | 结构视角、交互视角 |
| **行为** | 这一次怎么走 | 场景 → 步骤 → 帧 | 运行视角（舞台 + 时序图） |
| **原则** | 为什么这样分 | 系统、层、模块三级（§2.3） | 带的抽象原则、面板 |

三者画在**同一套层次与节点位置**上（三视图一套层次，V11、V12），并构成包含链 **场景步 ⊂ 交互 ⊂ 依赖**：往上加语义，往下做证据（README §3）。

### 2.1 结构：模块 + 两种关系

模块是可递归的「提供某种能力的系统」：每一级都有职责（一句话）、对外**表面**（入口导出 + 声明接口，K18）、子模块（可下钻）与角色（核心 / 普通 / 共用件 / 端口 / 适配器，[ADR-0027](../adr/0027-module-roles.md)）。类、函数体、私有结构永不进画布。

模块之间只有两种关系，分别画在两张图上：

| | **依赖**（静态） | **交互**（动态） |
|---|---|---|
| 回答 | 谁知道谁——改它牵动谁 | 谁对谁做什么——后果归谁 |
| 身份 | 代码事实，工具从 import 算出 | 主张，AI 写、人确认核心之间的线 |
| 分类 | **形态**：使用、子类、端口实现、组装（K14）；**档**：交互使用 > 值使用 > 只引类型 | **三问**：查询、委托、通知、流；**修饰**：经什么连（直接 / 端口 / 总线 / 通道）、同步异步、拉取（[ADR-0029](../adr/0029-interaction-kinds-and-via.md)） |
| 画法 | 虚线；形态靠端点记号 | 实线；种类靠颜色，同步异步靠箭头，机制写进标签（L35，[ADR-0041](../adr/0041-mechanism-labels.md)），经端口另画插座 |
| 视角 | 结构视角 | 交互视角 |

### 2.2 行为：场景穿过结构

- **场景**是一次端到端的经过（主流程 / 异常 / 维护，R17）；**步骤**组成树（调用、异步、返回、分支、循环、并行、引用，S2）；**帧**是回放的最小单位。
- 绑定了关系的步骤是一条交互的一次发生（S13）——行为由此钉在结构上。
- 每个场景只写一套最细步骤，各层由投影合并（S3、P 系列）。

### 2.3 原则：三级同构，每一级都是「是什么 + 为什么这样分」

| 级 | 是什么 | 为什么这样分（原则） | 怎么看 |
|---|---|---|---|
| **系统** | `system.description` 第一句：定位——为谁解决什么、提供什么价值 | 第二句：核心原则——按什么取舍、怎么分 | 根层面板「简介」置顶；系统可确认，指纹只覆盖这两句（M23、Z7，[ADR-0042](../adr/0042-principles-three-levels.md)，已实现） |
| **层** | 名称 + 包含 / 不包含 | `abstraction`（抽象原则，必填）、`mayDependOn` | 分层总览每条带常显（O2，已实现） |
| **模块** | `responsibility`（职责，一句话） | `abstraction`（对内原则，一句话，AI 起草、人确认）；`principle` 是实现原理长文，折叠在后 | 面板首段合成「说明」= 职责 + 原则一句；核心与第二级模块应写（M24，ADR-0042，已实现） |

- 定位与原则分两句写：定位随产品演进而变，原则要稳定、能被检查（`mayDependOn`、F3）。
- 原则要进确认范围：确认指纹（Z2）纳入 `abstraction`，层与模块都算；系统以系统 ID 确认，指纹覆盖简介两句（Z7，ADR-0042，已实现）。
- **算出的分层不是原则，是原则的证据。** 普通层次按值依赖算出的层带（L28）是「实际上怎么分」；声明的层是「说出来的为什么」。两者画法相同、带标题上的状态记号区分（算出 / 待确认 / 已确认，第十四轮 F8）；经「提炼」起草为层、人确认后成为原则，再由「符合性校验」盯着它是否还成立（第十四轮 F2、F3）。

## 3. 怎么看：五种手段

| # | 手段 | 解决什么 | 要点 | 规则 |
|---|---|---|---|---|
| 1 | **分层：位置即方向** | 不用逐条读箭头就知道方向 | 根层次与复杂模块同一套：声明的层（按 `order`）与算出的层带（按本层值依赖：环合组、被依赖的贴底、入口置顶）画法相同，状态记号区分（F8）。依赖只朝下；违背现行分层的线是例外——已确认的层写「违规」，算出的层写「向上」（F10）；向上的交互只可能是控制反转，否则提示并在线上写「向上」（K22、ADR-0041；分层总览按声明的可依赖方向判定） | O1–O3、L28、L29、K22；F8、F10 |
| 2 | **分级折叠：先看谁** | 主体不超带宽 | 核心直出；普通超七个折为「+N」；共用件上架、用「共用 ×N」角标代替线；端口与适配器贴框、永不折叠；本层没核心时不折叠、提示标核心；框角常驻「共用件 N · 折叠 M」 | O8–O11、O13、L14 |
| 3 | **下钻：细节在哪** | 一次只看一个层次 | 层次 = 当前父模块，画布只画它的直接子模块；面包屑与 Backspace 返回并选中刚离开的模块；结构展开到模块表面为止 | N1–N13、L20 |
| 4 | **关系分级：两条轴** | 线多仍读得出主干 | 轴一按聚合粒度分远中近；轴二按信息量分 L0–L3。醒目度与信息量成正比，不与条数成正比；线也有预算，与 SP4 对等（F11） | L21、L20、L23、L23b；F8–F11 |
| 5 | **编码：一个通道一个维度** | 一眼读出线与节点的含义 | 见编码表 | L10、L16、L18、L26 |

**轴一：聚合粒度（远中近三景）**

| 景 | 依赖（结构视角） | 交互（交互视角） | 回答 | 状态 |
|---|---|---|---|---|
| 远 | **分层总览语法**：层 + 违背现行分层的线 + 计数（L41）；门槛以下的层次没有远景 | 带间聚合边，角标「×N · M 把手」（L23b） | 方向与主干是什么 | 根层与复杂模块同一语法（F8，已实现；计数随 F9、F10） |
| 中 | **束**：一对节点同方向一条，线宽 = 元素级边条数，取最强形态与档（L21） | **交互束**：一对节点同方向同种类一条，线宽 = 关系条数（L5） | 谁连谁、有多粗 | 已实现 |
| 近 | **元素级边**：展开被依赖方表面，落到定尺寸端口点阵（L20） | 展开接收方表面，按接口散开到把手（L23） | 打到对方哪个插座 | 已实现 |

远景不是「更粗的线」。束干线（ADR-0040）保留全部端点，只是中景的另一种画法，实测线对象 −16%、交叉 +20%，已否决。**残余大扇入已复测（第十四轮 F13）：不需要汇合画法。** F9、F10 落地后，结构视角静息态进同一节点 ≥ 5 条线的节点 h5p 7 → 1、h5player 14 → 4、media 0 → 0，最大扇入 15 → 9、12 → 8、3 → 4；剩下的两类都不该靠画法收拢——逐条的例外（h5player app.plugins 进框外 infra 的 8 条违规，合并会抹掉每条例外的身份）与工具性的被依赖方（h5p 的 present.panel.content 9 条、h5player 的 infra.framework.utils 6 条，是标共用件（O9）的候选，属于描述，不属于画法）。把手的三个高度与三景同构（[ADR-0033](../adr/0033-handles.md)）：总览答「几个把手」，普通层次答「落在哪几个」，下钻答「哪块接住了」。

**轴二：信息量（L0–L3，第十四轮 F9–F11，已实现：K23、L42、L43）**

| 级 | 是什么 | 怎么画 |
|---|---|---|
| L0 逐条例外 | 违规、向上（违背现行分层）、逆稳定、未解释 | 常显，最醒目，不受条数影响 |
| L1 骨架 | 不可约的依赖（传递约简后剩下的，F9） | 常显，安静（中性、细）；线宽只在骨架内部表示量级 |
| L2 可推出与环内 | 可由别的路径推出的线（F9）；环内的线（F10） | 不画，计数（「另直连 N」「环内 N 条」），聚焦时出现 |
| L3 元素级 | 表面展开后的元素级边 | 展开时出现 |

**例外分两类**（F10，K23、L42）：逐条的例外（违规、向上、逆稳定、未解释）逐条常显（只是未解释、另一端在框外的仍折叠计数）；**环是组的属性**，按组呈现——环编号 + 「环内 N 条」计数，单击环编号选中环组或聚焦成员时才画环内的边。传递约简的口径钉死在第十三轮 91 §2：宇宙 = 本层兄弟束（交互使用 + 值使用，非异常），先求强连通分量，环组内互不约简，组间在缩点 DAG 上有长度 ≥ 2 的路径即可推出；与偏好、折叠、聚焦无关，只用于结构视角的静息态。

**编码表**（手段 5）：

| 通道 | 只表这一个维度 | 范围 |
|---|---|---|
| 纵向位置 | 依赖方向（上依赖下） | 分层的层次 |
| 方位 | 角色：用户在上，外部系统、时间与适配器在左，端口贴上边（A7、L14、O16） | 全部 |
| 框 | 边界：系统框、父模块框、带 | 全部 |
| 线型 | 交互（实线）还是依赖（虚线） | 三视图共享（L18） |
| 线宽 | 合了几条（1 / 2–4 / ≥5） | 三视图共享 |
| 标签位 | 唯一写字处：「×N」、把手；异常词（违规、向上、未证实、未解释、缺段、未建模，警示色）；修饰词（机制九词——回调、端口、总线、注入、跨进程、路由、事件、通道、拉取（L35）——与混合、经上层，中性色）。至多两段：异常段在前、修饰段在后，至多两个标签、其余写「+k」（[ADR-0041](../adr/0041-mechanism-labels.md)）。「向上」只有一个定义：**线的方向违背所在分层**；判定条件分两种——**声明的层看可依赖方向**（接收方的层可依赖发起方的层、反过来不可即为向上；层序只是它的影子，两层都没写 `mayDependOn` 时才退回层序；两个方向都不许的是违规，不是向上），**算出的层看层号**（依赖方或发起方的层号更大）；层序与可依赖方向不一致的，由 F3（K24）报，不混进向上。结构视角：依赖违背算出的层写「向上」，声明的层由规则判、写「违规」（K23）；交互视角：交互逆着分层、又没有任何机制写「向上」（K22） | 三视图共享（L26） |
| 颜色 | 交互种类：查询淡、委托实、通知、流 | 交互视图私有（L10） |
| 箭头 | 控制流方向；同步实心、异步空心 | 交互视图私有 |
| 插座 | 经端口、接收方可替换（落在哪个入口）；与「端口」标签并存，各司其职（ADR-0041 裁决 2） | 交互视图私有（L12） |
| 端点记号 | 形态：使用 → 、子类 △、端口实现 ◇、组装 ◆ | 结构视图私有（L16） |
| 醒目度 | 信息量：例外深色加宽、骨架安静中灰（L43）；档改用点线（只引类型），交互使用与值使用画布上不区分；对比度（透明度）只留给聚焦变淡 | 结构视图私有 |
| 角标 | 节点上的计数与指标，按位置表落位、每槽一个维度（L37）：名称行 = 身份（角色、环编号），上边左 = 状态，上边右 = 端口，下边左 = 量（入 · 出 · 表面），下边右 = 没画出来的线（共用、另直连），外侧 = 界外；写字的静息态最多 3 个 | 节点（L17、L37、J5、O10、O11） |

**图例即开关**（L45，ADR-0056）：画布右上角的图例里，有开关的记号行单击即切换，关着的行淡色常列；没有记号的设置在工具栏「显示 ▾」（L49）；悬停线时提示末尾附该记号的图例释义（L50）。

**图例按上下文**（L47）：图例的每一组只列当前视角 + 当前层次静息态画面**出现的记号**（出现集合在状态层一处派生）；组结构与行序按固定词表、行只显隐不重排；聚焦 / 悬停 / 回放才出现的临时记号归各组尾部固定的「临时可见」小节常列。

**词表准入四问**（L26、[ADR-0041](../adr/0041-mechanism-labels.md)）：一个维度要不要常显文字——别的通道已经表达了吗（有就不写）？不写会怎样读错（代价高才常显）？出现频率（低频用文字，高频用图形）？缺省值（不写）？写机制、不写后果：写出「端口」「总线」就解释了线为什么能向上。

## 4. 怎么动：选中、联动与面板

**选中**

- 选中是唯一且排他的主语；悬停不算指向（V2、V3）。
- 选中只聚焦一跳，悬停在其上叠加；影响面 / 依赖面是面板里的显式查询，不绑在选中上（L27、K15，[ADR-0037](../adr/0037-select-focus-and-impact-query.md)）。
- 悬停只看不改：衬边、加粗、看清两端，不挪位置、不换选中（L25）。

**三视图联动**（节点位置不动，只换边与角标，V12）

| 从 | 选中 | 另一张图上显形 | 规则 |
|---|---|---|---|
| 交互 → 结构 | 一条交互 | 承载它的依赖路径临时画出（虚线 + 端点记号），缺一段标「缺段」 | L22 |
| 结构 → 交互 | 一条束 | 以它为承载的交互（实线），单击切到交互视角 | L22 |
| 运行 → 交互 | 一步 | 时序图与交互图停在同一帧；走过、当前、预览的边按回放态呈现；关系建在上层的画「经上层」临时线 | R3、V5、P15 |
| 运行 → 结构 | 模块 / 关系 | 时序图突出对应泳道 | R15 |

回放只由人逐步驱动，没有自动播放；分支由人选（R1、F6，[ADR-0006](../adr/0006-workbench-navigation.md)）。

**面板：近景的另一半，先答做什么**

## 5. 不变式：「看」的纪律

1. 任何视图在任何层次默认不超过七个左右的主体；线也有预算（SP4；线的预算第十四轮 F11）。
2. 折叠可以、隐藏不行：折叠必有计数；逐条的例外（违规、向上、逆稳定）不论折叠照画，成组的例外（环）按组照画并带计数（SP5、O11、L21②、L42）。
3. 节点位置只由层次与收起态决定：视角、选中、悬停、展开、回放、约简都不挪节点（V12、L20、V5）。
4. 一个通道只表一个维度；线型只答「交互还是依赖」；醒目度跟信息量走（L10、L18；F11）。
5. 一条线只有一个写字的地方（L26）。
6. 回放只由人驱动（R1）。
7. 先答做什么，再给细节（§4 面板）。
8. 肉眼守不住的几何纪律交给机器守：线不重合、箭头不叠、不压节点与文字、标签不互压、不贴框，由几何检查器在**交互、结构两个视角**计数守回归（L30；结构视角基线 `tests/layout/clarity/clarity.test.ts` 的 `STRUCTURE`，第十三轮修复）；任何常显的线都必须进入布局与分轨，并在它出现的视角里被 L30 测量，否则只能临时出现（第十四轮 F12）。

## 6. 给「对照」与「守住」留的接口

- **对照**：事实与主张分图（§2.1）+ 标签位词表（§3 编码表）= 对照结果的显示面；包含链让选中一条交互即可看到它的证据（§4 联动）。
- **守住**：层的原则常显（§2.3）+ 算出的层带与状态记号（§3 手段 1）= 符合性校验的前提；折叠的计数与「+N」的跨度是组织判断的信号（第十四轮 F5）。
