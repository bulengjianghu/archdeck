# h5p-arch-desk 需求

> 本文回答**做什么、为什么、做到什么程度**。概念与规则的定义在 [02-domain.md](./02-domain.md)，本文只按编号引用；实现方式见 [03-architecture.md](./03-architecture.md)。
> 状态：**已实现** / **待实现**（已定稿未开发）/ **后续**（不在当前范围）。
> 位置：`h5player-demo/packages/h5p-arch-desk`；服务对象：h5player 等项目的架构师与核心工程师。

## 0. 一句话

**本地架构工作台：看见 · 对照 · 守住。** 看见——AI 把代码压缩成模块级的架构描述，工具按层次画出结构、叠加场景回放运行、用设计版本先评审再开发；对照——描述与本地源码互相印证（归属、导出、关系是否被代码证实、未描述的依赖），问题汇总成可交给人或 AI 的返工清单；守住——架构规则、环与棘轮门禁让结构只许变好，coding agent 写代码前先问。它是本地开发工具：被描述项目的源码在本地，开发服务器读源码、跑 TypeScript 解析、读 git。

## 1. 背景

h5player 的架构信息分散在几处：

| 来源 | 内容 | 问题 |
|---|---|---|
| `h5player/docs/arch/blueprint.md` | 四层分层、依赖矩阵、数据面 / 控制面运行流（mermaid） | 静态图，不能下钻，不能点开看某个模块的接口 |
| `h5player/docs/system/module-map.md` / `.yaml` | 13 个业务板块、模块 ID（`M-ARC-1` 等）与源码 glob | 面向覆盖率统计，只有归属，没有模块间关系 |
| `h5player/docs/design/0-kernel … 9-foundation` | 各模块设计文档 | 按文档组织，看不到全局 |
| `h5player/.dependency-cruiser.cjs` | 包级依赖门禁 | 只管 4 个包，粒度太粗 |

架构师要回答「这个模块负责什么、对外暴露什么、和谁通过什么接口交换什么数据、一次播放请求依次经过哪些模块」时，需要在多份文档和代码之间来回翻。h5p-arch-desk 把这些信息收拢成**一张可以下钻、可以点选查看属性、可以回放执行链路的模块关系图**，并让架构迭代先在图上设计、评审，再投入开发。

## 2. 目标与非目标

### 2.1 目标

| 组 | 目标 | 含义 | 状态 |
|---|---|---|---|
| 看见 | 看见结构 | 以模块为基本单元，分层次呈现模块与模块间关系 | 已实现 |
| 看见 | 看见运行 | 在静态结构上叠加场景：依次、分支、循环、异步地调用了哪些模块 | 已实现 |
| 看见 | 先设计后开发 | 在当前架构上出设计版本，多轮评审定稿后再开发 | 已实现 |
| 看见 | 看见演化 | 对比任意两个 git 提交之间模块、关系、接口、数据结构的增删改，在图上标色（DV-8） | 已实现（时间轴回看为后续） |
| 对照 | 对上源码 | 模块与真实源码文件互相定位：模块由哪些文件组成、从哪里导出什么、与描述的接口是否一致 | 已实现 |
| 对照 | 描述对代码 | 从代码提取依赖事实与描述比对：关系是否被证实、有没有未描述的依赖；问题按根因汇总成返工清单，带位置、规则与建议动作，交给人或 AI 修正（GV-10、AG-4） | 已实现 |
| 守住 | 支撑治理 | 按架构规则校验，环度与违规只许变好（棘轮门禁，存量封存进基线）；把规则与语义交给 AI agent，在写代码前判定（ADR-0015） | 已实现 |

### 2.2 非目标

- 不在图上展示文件、函数、类等模块以下的结构；源代码只以导航树的文件树与只读预览出现，不进画布（ADR-0007）。
- 不做画布内的图形化编辑；AI 生成的描述（模块、关系、场景）以文本文件维护，由人或 AI 修改，页面不写；页面只追加人拥有的三类内容——评审意见、例外、忽略项（B1，ADR-0019）。
- 不替代设计文档；面板可链接到设计文档，但不搬运全文。
- 不考虑构建部署：本工具是本地开发工具，只在本地开发服务器上运行，被描述项目的源码必须在本地（ADR-0007 修订）。

## 3. 核心概念

架构 = **模块 + 模块间关系，按层次抽象**；价值在「模块各司其职 + 通过接口交换信息和控制权」的执行链路上产生。描述由 AI 根据代码生成，工具按层次呈现。

| 概念组 | 包含 | 定义 |
|---|---|---|
| 架构描述 | 系统、模块、层、关系、接口、数据结构、外部参与者 | [02-domain.md §1.1](./02-domain.md#11-架构描述被描述的系统) |
| 结构视图 | 层次、视图节点与视图边、模块树、分层总览 | [§1.2](./02-domain.md#12-结构视图) |
| 场景与回放 | 场景、步骤、帧、回放路径、进度、可见消息、步骤树 | [§1.3](./02-domain.md#13-场景与回放) |
| 视角与选中 | 结构 / 运行视角、选中、指向、选中突出 | [§1.4](./02-domain.md#14-视角与选中) |
| 版本 | 当前版本、设计版本、轮次、差异 | [§1.5](./02-domain.md#15-版本) |
| 源代码 | 源码根目录、文件清单、归属、未归属、归属冲突、忽略清单、入口文件、导出 | [§1.6](./02-domain.md#16-源代码) |
| 架构治理 | 代码事实、文件 / 模块依赖、已证实 / 未证实、未描述依赖、架构规则、访问面、违规、环与环度、基线、门禁、写前判定、拦截记录 | [§1.7](./02-domain.md#17-架构治理) |

2. **治理的演化与交互**：按提交回看违规与环度的趋势；设计版本里 `rules` 的差异；拆环建议（最便宜的切口）在画布上呈现（ADR-0015 后果 5）。
3. **AI 协作**：在面板上就选中对象向 AI 提问，让 AI 起草或补全描述；架构查询（模型层）可直接供 AI 使用。
4. **画布内编辑**：在画布上增删模块和关系，写回描述文件（C-12）。
5. **自由分屏**：由固定的左右 / 上下两块演化为可自由拖拽停靠的布局（W-4）。
