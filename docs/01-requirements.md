# h5p-arch-desk 需求

> 本文回答**做什么、为什么、做到什么程度**。概念与规则的定义在 [02-domain.md](./02-domain.md)，本文只按编号引用；实现方式见 [03-architecture.md](./03-architecture.md)。
> 状态：**已实现** / **待实现**（已定稿未开发）/ **后续**（不在当前范围）。
> 位置：`h5player-demo/packages/h5p-arch-desk`；服务对象：h5player 等项目的架构师与核心工程师。

## 1. 背景

h5player 的架构信息分散在几处：

| 来源 | 内容 | 问题 |
|---|---|---|
| `h5player/docs/arch/blueprint.md` | 四层分层、依赖矩阵、数据面 / 控制面运行流（mermaid） | 静态图，不能下钻，不能点开看某个模块的接口 |
| `h5player/docs/system/module-map.md` / `.yaml` | 13 个业务板块、模块 ID（`M-ARC-1` 等）与源码 glob | 面向覆盖率统计，只有归属，没有模块间关系 |
| `h5player/docs/design/0-kernel … 9-foundation` | 各模块设计文档 | 按文档组织，看不到全局 |
| `h5player/.dependency-cruiser.cjs` | 包级依赖门禁 | 只管 4 个包，粒度太粗 |

架构师要回答「这个模块负责什么、对外暴露什么、和谁通过什么接口交换什么数据、一次播放请求依次经过哪些模块」时，需要在多份文档和代码之间来回翻。h5p-arch-desk 把这些信息收拢成**一张可以下钻、可以点选查看属性、可以回放执行链路的模块关系图**，并让架构迭代先在图上设计、评审，再投入开发。

## 2. 目标与非目标

### 2.1 目标

| 目标 | 含义 | 状态 |
|---|---|---|
| 看见结构 | 以模块为基本单元，分层次呈现模块与模块间关系 | 已实现 |
| 先设计后开发 | 在当前架构上出设计版本，多轮评审定稿后再开发 | 已实现 |
| 看见运行 | 在静态结构上叠加场景：依次、分支、循环、异步地调用了哪些模块 | 已实现 |
| 看见演化 | 对比任意两个 git 版本之间模块和关系的增删改 | 后续（设计版本与基线的对比已实现） |
| 支撑治理 | 架构描述与真实代码依赖比对，发现偏航 | 后续 |

### 2.2 非目标

- 不展示文件、函数、类等模块以下的代码细节。
- 不做画布内的图形化编辑；描述以文本文件维护，由人或 AI 修改，页面只读。
- 不替代设计文档；面板可链接到设计文档，但不搬运全文。

## 3. 核心概念

架构 = **模块 + 模块间关系，按层次抽象**；价值在「模块各司其职 + 通过接口交换信息和控制权」的执行链路上产生。描述由 AI 根据代码生成，工具按层次呈现。

| 概念组 | 包含 | 定义 |
|---|---|---|
| 架构描述 | 系统、模块、层、关系、接口、数据结构、外部参与者 | [02-domain.md §1.1](./02-domain.md#11-架构描述被描述的系统) |
| 结构视图 | 层次、视图节点与视图边、分层总览 | [§1.2](./02-domain.md#12-结构视图) |
| 场景与回放 | 场景、步骤、帧、回放路径、可见消息 | [§1.3](./02-domain.md#13-场景与回放) |
| 视角与焦点 | 结构 / 运行视角、焦点、指向 | [§1.4](./02-domain.md#14-视角与焦点) |

| 项 | 要求 |

| 可测性 | 领域规则清单逐条有单元测试：模型层的架构查询与视图状态层的会话规则都是纯函数，按清单穷举；同步适配器用假路由 / 假时钟测试 |

## 6. 验收标准

### 6.1 结构视角与版本（已通过）

1. 打开 h5player 看到分层总览：4 条带自上而下，每条带显示抽象原则、核心模块和可依赖的层，带间有层间依赖及条数；能平移、缩放、适应画布。
2. 点击任意模块或边，面板显示 §4.3 规定的内容。
3. 双击 Infrastructure 看到其子模块，再双击 Framework 看到第三层；面包屑可逐级返回。
4. 第二层能看到由更深层关系提升出的聚合边，选中后列出原始关系并能跳转。
5. 在描述中引用不存在的模块 ID，页面与 `npm run lint:model` 都报出明确错误。
6. 修改某模块的职责文字，页面自动更新，层次与选中保持不变。
7. 首页列出全部项目；进入任一项目后，面包屑「项目」回首页，浏览器后退回到原项目的原层次。
8. 打开一个设计版本：图上标出新增 / 修改与涉及变更数，根层面板有变更清单；切换到当前版本时层次与选中保持。

### 6.2 运行视角（已通过）

以 h5p-arch-desk 自身的场景与 h5player 迁移的两个场景验收（自动化验收：`tests/acceptance/run-perspective.test.ts`，以真实的 `model/` 描述逐条验证）：

1. 在根层通过「运行」选一个场景：进入运行视角、层次不变、自动播放；结构图只突出参与者与走过的边，下方出现时序图；参与者泳道在最左。
2. 播放中双击下钻：暂停并钉住，播放头仍是同一帧；时序图泳道变细、可见消息变多，单步粒度变细。
3. 播放到 `alt`：自动暂停并展开全部选项；选一支后继续；退回分支点之前再前进沿用已选分支；在分支点改选后其后的选择被丢弃。
4. 在时序图上点一条之前的消息：播放头后退到这一步并暂停，已走过的边与「从头播放到这一步」完全一致；面板显示该步骤，推断的关系有「推断」标记。
5. 钉住一个模块时面板先显示它在本场景中参与的步骤；取消选中回到当前步骤但不恢复播放；点播放后恢复跟随。
6. 写与结构不一致的步骤（端点与引用关系不符；两端结构上无任何关系；引用 `depends` 关系）：页面与 `lint:model` 分别报出错误 / 提醒；无关系的那一步回放时画出「结构中未建模」虚线。
7. 复制运行视角下的地址到新标签打开：回到同一场景、同一步骤、同一分支选择，处于暂停。
8. 退出场景：回到结构视角，层次与选中保留，分屏消失。

## 7. 后续方向

1. **演化**：选两个 git 版本，对比模块、关系、接口的增删改并在图上标色，时间轴回看；复用设计版本的差异计算（E1、E2）。
2. **治理比对**：用 `codeRefs` 与 dependency-cruiser 扫描结果比对描述中的依赖与代码中的真实依赖，列出缺失或越界的边。
3. **AI 协作**：在面板上就选中对象向 AI 提问，让 AI 起草或补全描述；架构查询（模型层）可直接供 AI 使用。
4. **画布内编辑**：在画布上增删模块和关系，写回描述文件（C-12）。
5. **自由分屏**：由上下分屏演化为可自由拖拽停靠的布局（W-4）。
