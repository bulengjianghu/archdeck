# h5p-arch-desk 需求

> 本文回答**做什么、为什么、做到什么程度**。概念与规则的定义在 [02-domain.md](./02-domain.md)，本文只按编号引用；实现方式见 [03-architecture.md](./03-architecture.md)。
> 状态：**已实现** / **待实现**（已定稿未开发）/ **后续**（不在当前范围）。
> 位置：`h5player-demo/packages/h5p-arch-desk`；服务对象：h5player 等项目的架构师与核心工程师。

## 1. 背景

h5player 的架构信息分散在几处：

| 来源 | 内容 | 问题 |
|---|---|---|
| `h5player/docs/arch/blueprint.md` | 四层分层、依赖矩阵、数据面 / 控制面运行流（mermaid） | 静态图，不能下钻，不能点开看某个模块的接口 |
| `h5player/docs/system/module-map.md` / `.yaml` | 13 个业务板块、模块 ID（`M-ARC-1` 等）与源码 glob | 面向覆盖率统计，只有归属，没有模块间关系 |
| `h5player/docs/design/0-kernel … 9-foundation` | 各模块设计文档 | 按文档组织，看不到全局 |
| `h5player/.dependency-cruiser.cjs` | 包级依赖门禁 | 只管 4 个包，粒度太粗 |

架构师要回答「这个模块负责什么、对外暴露什么、和谁通过什么接口交换什么数据、一次播放请求依次经过哪些模块」时，需要在多份文档和代码之间来回翻。h5p-arch-desk 把这些信息收拢成**一张可以下钻、可以点选查看属性、可以回放执行链路的模块关系图**，并让架构迭代先在图上设计、评审，再投入开发。

## 2. 目标与非目标

### 2.1 目标

| 目标 | 含义 | 状态 |
|---|---|---|
| 看见结构 | 以模块为基本单元，分层次呈现模块与模块间关系 | 已实现 |
| 先设计后开发 | 在当前架构上出设计版本，多轮评审定稿后再开发 | 已实现 |
| 看见运行 | 在静态结构上叠加场景：依次、分支、循环、异步地调用了哪些模块 | 已实现 |
| 对上源码 | 模块与真实源码文件互相定位：模块由哪些文件组成、从哪里导出什么、与描述的接口是否一致 | 已实现 |
| 看见演化 | 对比任意两个 git 版本之间模块和关系的增删改 | 后续（设计版本与基线的对比已实现） |
| 支撑治理 | 架构描述与真实代码依赖比对，发现偏航 | 后续 |

### 2.2 非目标

- 不在图上展示文件、函数、类等模块以下的结构；源代码只以导航树的文件树与只读预览出现，不进画布（ADR-0007）。
- 不做画布内的图形化编辑；描述以文本文件维护，由人或 AI 修改，页面只读。
- 不替代设计文档；面板可链接到设计文档，但不搬运全文。

## 3. 核心概念

架构 = **模块 + 模块间关系，按层次抽象**；价值在「模块各司其职 + 通过接口交换信息和控制权」的执行链路上产生。描述由 AI 根据代码生成，工具按层次呈现。

| 概念组 | 包含 | 定义 |
|---|---|---|
| 架构描述 | 系统、模块、层、关系、接口、数据结构、外部参与者 | [02-domain.md §1.1](./02-domain.md#11-架构描述被描述的系统) |
| 结构视图 | 层次、视图节点与视图边、模块树、分层总览 | [§1.2](./02-domain.md#12-结构视图) |
| 场景与回放 | 场景、步骤、帧、回放路径、播放头、可见消息、步骤树 | [§1.3](./02-domain.md#13-场景与回放) |
| 视角与焦点 | 结构 / 运行视角、焦点、指向 | [§1.4](./02-domain.md#14-视角与焦点) |
| 版本 | 当前版本、设计版本、轮次、差异 | [§1.5](./02-domain.md#15-版本) |
| 源代码 | 源码根目录、文件清单、归属、未归属、归属冲突、忽略清单、入口文件、导出 | [§1.6](./02-domain.md#16-源代码) |

### 4.7 初始内容

- h5player：四层（Share / Domain / Application / Infrastructure）及层间依赖、各层抽象原则与核心模块；第二层全部子模块与关系；至少一条下钻到第三层的完整示例。（已实现）
- h5p-arch-desk 自身、media-web 的架构描述。（已实现）
- 场景：h5p-arch-desk 自身「打开场景并回放」（含 `loop`、`alt` 与外部参与者）；h5player 迁移两个场景「命令执行」「方案切换事务」（D-8，含 `alt`、`loop`、`ref` 与外部参与者）。（已实现）
- 忽略清单：h5p-arch-desk 与 h5player 各一份 `source-ignore.yaml`，忽略文档、测试、配置等不属于任何模块的文件，使未归属警告只指向真正漏写的源码。（已实现）

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 规模 | 单层次 ≤ 50 节点、≤ 150 边时交互流畅（平移缩放 ≥ 50fps）；全模型 ≤ 1000 模块时首屏加载 < 2s；单个场景 ≤ 200 帧时单步、跳转、切换层次的响应 < 100ms；源码 ≤ 5000 个文件时文件清单与归属计算 < 500ms，单个入口的导出解析 < 200ms |
| 运行方式 | `npm run dev` 本地查看；`npm run build` 产出静态站点部署到内网；不依赖后端服务（构建态不含源码，源代码功能只在开发态可用，ADR-0007） |
| 浏览器 | 最新版 Chrome / Edge / Safari 桌面端 |
| 只读 | 页面不写文件（含忽略清单，ADR-0007） |
| 可测性 | 领域规则清单逐条有单元测试：模型层的架构查询与视图状态层的会话规则都是纯函数，按清单穷举；同步适配器用假路由、假模型源测试 |

## 6. 验收标准

### 6.1 结构视角与版本（已通过）

1. 打开 h5player 看到分层总览：4 条带自上而下，每条带显示抽象原则、核心模块和可依赖的层，带间有层间依赖及条数；能平移、缩放、适应画布。
2. 点击任意模块或边，面板显示 §4.3 规定的内容。
3. 双击 Infrastructure 看到其子模块，再双击 Framework 看到第三层；面包屑可逐级返回。
4. 第二层能看到由更深层关系提升出的聚合边，选中后列出原始关系并能跳转。
5. 在描述中引用不存在的模块 ID，页面与 `npm run lint:model` 都报出明确错误。
6. 修改某模块的职责文字，页面自动更新，层次与选中保持不变。
7. 首页列出全部项目；进入任一项目后，面包屑「项目」回首页，浏览器后退回到原项目的原层次。
8. 打开一个设计版本：图上标出新增 / 修改与涉及变更数，根层面板有变更清单；切换到当前版本时层次与选中保持。

### 6.2 运行视角（已通过）

以 h5p-arch-desk 自身的场景与 h5player 迁移的两个场景验收（自动化验收：`tests/acceptance/run-perspective.test.ts`，以真实的 `model/` 描述逐条验证）：

1. 在根层通过「运行」选一个场景：进入运行视角、层次不变、停在开头，面板显示场景；按「下一步」逐条前进，结构图只突出参与者与走过的边，旁边出现时序图；参与者泳道在最左。
2. 回放中双击下钻：钉住被下钻的模块，播放头仍是同一帧；时序图泳道变细、可见消息不少于上一层，单步粒度变细。
3. 单步到 `alt`：展开全部选项，未选时不能再前进；选一支后继续；退回分支点之前再前进沿用已选分支；在分支点改选后其后的选择被丢弃。
4. 在时序图上点一条之前的消息：播放头后退到这一步，已走过的边与「从头单步到这一步」完全一致；面板显示该步骤，推断的关系有「推断」标记。
5. 钉住一个模块时面板先显示它在本场景中参与的步骤；取消选中，或单步、指向某一步，面板回到当前步骤（跟随）。
6. 写与结构不一致的步骤（端点与引用关系不符；两端结构上无任何关系；引用 `depends` 关系）：页面与 `lint:model` 分别报出错误 / 提醒；无关系的那一步回放时画出「结构中未建模」虚线。
7. 复制运行视角下的地址到新标签打开：回到同一场景、同一步骤、同一分支选择。
8. 退出场景：回到结构视角，层次与选中保留，分屏消失。

### 6.3 导航树与分屏（已通过）

自动化验收：`tests/acceptance/navigation-tree.test.ts`，以真实的 `model/` 描述验证。

1. 打开 h5player：左侧模块树展开到当前层次并标出它；在画布上下钻或选中，树同步展开并高亮；单击树中的深层模块，画布跳到它所在的层次并选中它；双击有子模块的模块即下钻；在当前层次内单击模块不新增浏览器历史。
2. 结构视角下开启「只看现状」，模块树不再列出目标态模块。
3. 打开场景：导航树切到「步骤」页签，按组合框嵌套列出全部步骤，`alt` 列出全部分支与条件；单步时当前步骤在步骤树、时序图、结构图上同步高亮，序号一致；单击树中未选分支上的一步，切到该分支并定位到它。
4. 运行视角下模块树标出参与模块；单击其中一个即钉住，面板显示它在本场景中的运行信息。
5. 运行视角下结构图与时序图默认左右排列；切换为上下后刷新页面仍保持；左右排列时收起时序图，它缩成一条竖栏。

### 6.4 源代码（已通过）

自动化验收：`tests/acceptance/source-files.test.ts`，以真实的 `model/` 描述与本机源码目录验证（h5player 源码不在本机时跳过对应用例）。

1. 打开 h5p-arch-desk：导航树「文件」页签列出本包的源码文件树；打开 media-web：提示「源码不在本地」及尝试的路径，页面其余功能正常。
2. 在模块树中选中「导航树」模块：面板列出它的文件，文件树高亮这些文件；选中其上级「呈现层」：文件是子树文件的并集。
3. 选中一个文件：URL 带 `sel=f:<路径>`，文件面板显示归属模块；画布上当前层次中包含它的模块高亮（根层为所在的层），模块树展开到归属模块；副栏出现并显示带语法高亮的只读源码；刷新页面后仍选中该文件。
4. 选中「模型层 / 加载流水线」：面板显示入口与导出，`loadModel` 与描述的接口对上，对不上的分组列出。
5. 追加一个只在某模块 `codeRefs` 之外的文件模式、或两个互不包含的模块写同一文件：页面与 `lint:model` 分别报出未归属 / 归属冲突警告；把它加入 `source-ignore.yaml` 后未归属警告消失。
6. 运行视角下选中文件：钉住，副栏切到「源代码」页签；单步后回到跟随，副栏切回「时序图」，「源代码」页签仍可切回。

### 6.5 运行视角聚焦（已通过）

自动化验收：`tests/acceptance/run-focus.test.ts`，以真实的 `model/` 描述验证。

1. 打开 h5player 的「命令执行」，下钻到 Infrastructure / Framework：泳道按层次顺序排列——同属 Infrastructure（第 1 层）的 PlayerIndex 在前，Framework 的子模块相邻并有分组框标出「Framework 机制内核」，Application（第 2 层）的边界节点在其后；结构图边界节点行的顺序与泳道一致。
2. 单步到一条有显式返回的调用：时序图上它与配对的返回一起突出，其余消息变灰；面板依次显示作用、输入、输出（返回的数据）；钉住一个模块后，突出的是它参与的消息。
3. 在时序图上单击未选分支的条件：路线改走该支，回放控制条的路线总览同步；播放头原在旧分支内时退到分支点之前，「下一步」进入新分支；在路线总览中改选靠前的分支点，提示丢弃了其后的选择。
4. 运行视角下结构图只显示参与本场景的节点与走过的边；切到「淡显」后其余内容淡化出现，刷新后保持；在步骤面板展开「结构关系」并「在画布上显示」，当前步骤两端的静态边出现，单步后收回。
5. 「专注」收起导航树与面板，再按一次恢复；刷新后收起状态保持。

### 6.6 时序图可读性（已通过）

1. 打开 h5p-arch-desk 的「打开场景并回放」停在根层（分层总览）：「transition(openScenario)」画成 DeskState → 视图状态转移的箭头，不再是「视图状态层」上的激活条；没有一条泳道是另一条泳道的祖先；层内非核心模块的消息落在「<层名> · 其他」泳道，它在该层的分组框里。
2. 消息很多时向下滚动：泳道头始终在顶部，底部也有一份；横向滚动时头尾跟着移动。
3. 滚动查看时悬停消息、切换选中，时序图不再滚回当前步骤；按「下一步」或单击一条消息，当前步骤滚到中间；「定位」把当前步骤滚到中间。
4. 单步到「openScenario(id)」：输入显示 `openScenario(id: string)` 一行；没写数据的步骤显示取自关系的数据，并标「取自关系」。
5. 悬停结构图节点、时序图泳道头与消息都没有弹出；属性面板没有浮动切换。

### 6.7 副栏与悬停（已通过）

1. 上下布局打开场景：顶部泳道头、消息区生命线、底部泳道头的横坐标一致。
2. 副栏只有一栏：时序图页签下有层次名与「定位」，切到源代码页签时不显示「定位」。
3. 静态关系「隐藏」时悬停一个参与的模块：它的静态边与对端节点淡显出现，移开即消失；「淡显」时悬停，它的静态边变为正常显示。

## 7. 后续方向

1. **演化**：选两个 git 版本，对比模块、关系、接口的增删改并在图上标色，时间轴回看；复用设计版本的差异计算（E1、E2）。
2. **治理比对**：用 `codeRefs` 与 dependency-cruiser 扫描结果比对描述中的依赖与代码中的真实依赖，列出缺失或越界的边。
3. **AI 协作**：在面板上就选中对象向 AI 提问，让 AI 起草或补全描述；架构查询（模型层）可直接供 AI 使用。
4. **画布内编辑**：在画布上增删模块和关系，写回描述文件（C-12）。
5. **自由分屏**：由固定的左右 / 上下两块演化为可自由拖拽停靠的布局（W-4）。
