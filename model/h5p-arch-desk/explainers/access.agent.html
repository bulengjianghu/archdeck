给 AI 的双窗口

这一层是 agent 接口：。命令行与 MCP 两个外壳、一个查询核心——同一输入同一答案。

它凭什么快

每次查询前先对指纹：描述、源码清单、基线任何一个变了才重建索引——所以长驻的 AI 助手新建文件、新加依赖之后，不用重扫就能立刻得到判定。判定之外还附目标模块的职责与访问面，让助手知道该走哪里，而不只是被拒绝。

第三个窗口朝里开：辅助栏的「对话」由 agent 子进程 接待——开发服务器起一个只读的 claude，把上下文包递进去、把薄协议的输出流回页面；它能用的查询就是这里 MCP 外壳里不写记录的那几件。

判定的规则引擎是 架构治理，拦截记录落在 治理存储——效果可量化：这个月拦了多少次、拦在哪些门。
