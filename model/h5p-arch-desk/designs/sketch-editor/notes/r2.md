### 疑问的答复

6. **present.panel.edit 拆 5 个子模块是否过细**：层表单与模块表单的字段如下。
   - 交集 4 项：名称、ID、职责、封闭（外加「删除」操作）。
   - 层独有 4 项：抽象原则、包含、不包含、可依赖的层。层的排序在画布上拖动，不在表单里。
   - 模块独有 5 项：kind、核心（仅第二级）、代码落点、所属父（即移动）、对外接口（增删改）。

   交集占并集 13 项中的 4 项，占层表单 8 项的一半，占模块表单 9 项的不到一半，**不过半，维持分开**。共有的 4 项做成两张表单共用的字段段，只是组件复用，不单设子模块。5 个子模块在 04 §3.2 建议的 3~9 个之内。答复写在 `present.panel.edit` 的 designNote。

7. **撤销粒度与文本字段（写进 X7g）**：
   - 一个编辑操作（EditOp）是一步。
   - 文本字段从获得焦点到失焦或回车是一次提交，产生一个 `updateModule` / `updateRelation`，即一步；其间的多次击键不进撤销栈。
   - 值未变时不提交；Esc 还原字段，不提交。
   - 同一字段的连续两次提交是两步，不合并：可预测优先于省步数。

   **改 ID 与移动的关系（写进 X7d）**：模块表单的 ID 字段只改短名，父 ID 前缀只读。提交即 `renameModule`，等价于「父不变的移动」：同一个级联（后代、关系两端、接口 owner、closed、mayDependOn），关系与接口自身的 ID 不变；同一个 IdImpact 确认，有后代或当前版本里有引用时弹出。要换父只能用「所属父」下拉或画布拖动。

### 规则草案（来源均为「议」，定稿前盘点；相对 r1 改了 X7d、X7g）

- **X7a**：编辑态只在草图版本（设计的草图、持久草图）上开启，与运行视角、文件选中互斥，不进 URL。
- **X7b**：编辑操作是纯函数，只拒绝不成立的操作（目标不存在、ID 冲突、前缀不符、同一对同类型关系已有、连祖先与后代、设计草图移动持久草图的模块），其余交给校验。
- **X7c**：ID 生成规则：
  - 模块 = 父 ID + kebab-case 短名；
  - 关系 = `rel.<from 短名>-<to 短名>`；
  - 接口 = `if.<owner 短路径>.<名称>`。
- **X7d**：移动 = 改父 + 改 ID，级联后代、关系两端、接口 owner、closed、mayDependOn；关系与接口自身的 ID 不变；移动前预览影响并确认。表单改 ID 只改短名，即父不变的移动，同一级联与确认。
- **X7e**：删除级联子树、两端落在子树内的关系、owner 在子树内的接口，以及 closed / mayDependOn 中的引用；有级联时确认。
- **X7f**：校验的引用范围为本草图 ∪ 持久草图；error 拒绝保存；页面与写入端点同一函数；矛盾检查与核验同一份。
- **X7g**：撤销 / 重做只在本次未保存的编辑内。一个操作一步；文本字段一次提交（失焦或回车）一步，击键不计，值未变不提交，连续提交不合并；保存即清空。
- **X7h**：编辑后的跟随：改名换成新 ID，删除退到最近仍存在的祖先，新建即选中。
- **X7i（新）**：保存冲突时可重新加载并重放本次操作；有失败时列出失败的操作，可放弃本次改动。
- **B6 细化**：整份写回的顺序是指纹比对 → 校验 → 文档合并（注释只在未改动的节点保留）→ 更新指纹 → 拦截记录一行。
- **DV（新，议）**：每轮说明在 AI 拥有的 `r<N>/revision.yaml`，`design.yaml` 只放人拥有的内容。
