### 意见的落实

1. **轮次从目录发现（意见 1）**：
   - 设计目录下含 `system.yaml` 的 `r<N>/` 即一轮，按 N 的数字排序（r10 在 r9 之后）。
   - date、summary、questions 都在该轮的 `revision.yaml` 里；没有它的轮次照常可以打开，只是说明为空。
   - `design.yaml` 的 `revisions[]` 不再是轮次清单，只承载人拥有的 `feedback`，按 id 对上发现的轮次。条目由页面「记录评审意见」的写入端点按需建立：找不到该轮就新建 `{ id, feedback }`。
   - `revisions[]` 里有、目录里没有的 id，记一条 problem。
   - 旧设计按兼容规则合并：phase2-dynamic 的说明只在 design.yaml 里。
   - 落在：描述读取（`listRevisionDirs`、`readRevisionNote` 带 date、`readDesignInfo`）、追加写入（B2 按需建条目）、`ds.DesignInfo` 的来源说明；04 §1、§5 已改（见文档）。
2. **关系 ID 冲突（意见 2）**：
   - 关系 ID 生成为 `rel.<from 短名>-<to 短名>`。
   - 这个 ID 已被占用时，加类型后缀 `rel.<from 短名>-<to 短名>-<type>`：同一对模块允许不同类型各有一条关系（L5）。
   - 仍冲突时再加序号。
   - 写进 X7c 与 `model.intent.edit.locate`。
3. **疑问 6、7 的答复**：已被接受，与 r2 相同。

### 疑问 4 的答复：校验（X7f）与核验（X4）的 error 项

两者回答不同的问题。
- **校验**问「这份草图本身对不对，能不能保存」，输入只有草图与持久草图。
- **核验**问「某个版本符不符合这份草图」，输入是草图与一个版本的索引。

只有矛盾检查两边都有，是同一个函数（`sketchContradictions`，在 `model.intent.check`），同一个稳定键。其余各项只在一边，不存在同一问题两处口径。

| 问题 | 校验 X7f（草图本身） | 核验 X4（版本对草图） | 说明 |
|---|---|---|---|
| 格式不对（schema） | error `sketch.schema` | — | 版本文件的格式由 Loader 报（M1） |
| ID 格式、重复 | error `sketch.id`、`sketch.id-dup` | — | 版本里由 Validator 报（M 组） |
| 子模块 ID 不以父 ID 为前缀 | error `sketch.id-prefix` | — | X5 对草图本身的要求 |
| 引用不存在（parent、关系两端、接口 owner、经由接口、closed、mayDependOn 的元素） | error `sketch.ref`（范围：本草图 ∪ 持久草图） | — | 版本里由 Validator 报 |
| 关系连祖先与后代 | error `sketch.ancestor` | — | M6 |
| 层依赖成环 | error `sketch.layer-cycle` | — | 只是草图本身的性质，版本照抄 mayDependOn |
| 与持久草图矛盾（同一模块的 kind / core / mayDependOn / 父模块不一致；往持久草图封闭的子树下加直接子模块） | error `sketch.contradiction` | error `sketch.contradiction` | **同一函数** `sketchContradictions`，键 `contradiction:<实体 ID>`；声明 supersedes 时两边都跳过 |
| 草图的模块在版本里不存在 | — | error `sketch.missing-module` | 要有版本才能判 |
| 封闭子树下版本多出直接子模块 | — | error `sketch.extra-child` | 草图自己的封闭子树不会「多出」，因为它就是定义 |
| 父模块、kind、core、mayDependOn 与版本不一致 | — | error `sketch.field` | 同上，要有版本 |
| 关系没有对应；接口不存在或 owner 不同 | — | warning `sketch.missing-relation` / `missing-interface` / `interface-owner` | 可认可（X4） |
| 模块没写职责 | warning `sketch.empty` | — | 只提示，不拦保存 |

结论：保存只看左列的 error，归档与 `lint:model` 只看右列。

### 规则清单（定稿，来源均为「议」）

共 15 条：X7、X7a–X7i（10 条）、B2 修订、B6 细化、E8、Q11、DV 读取缺口。登记到 02 时，X7 由「后续」改为总述，X7a–X7i 标「待实现」。

| # | 规则 | 来源 | 所在 |
|---|---|---|---|
| X7 | 编辑态：只对草图开启，只改草图自身的内容（层、模块、关系、接口、closed、core、mayDependOn、文字字段）；不编辑数据结构、场景、参与者，不保存坐标；细则见 X7a–X7i | 议（ADR-0023、ADR-0024） | 编辑规则 · 草图编辑 · 画布 · 属性面板 |
| X7a | 编辑态只在草图版本上开启：设计的草图 `/d/<设计>/sketch`、持久草图 `/i/<ID>`。与运行视角、文件选中互斥：进入时关闭场景、清掉文件选中，编辑态下打开场景、选中文件无效。Esc 只取消选中。编辑态不进 URL。有未保存改动时，离开（切换版本、退出编辑、关闭页面）要确认 | 议 | 编辑规则 |
| X7b | 编辑操作是纯函数 `applyEdit(草图, 操作, 上下文) → 新草图 + 影响 \| 拒绝原因`，不修改输入。只拒绝不成立的操作：目标不存在、新 ID 已占用、显式 ID 不以父 ID 为前缀、同一对模块同类型关系已有、连祖先与后代、设计草图移动持久草图的模块。其余结构问题照常应用，交给校验（X7f）。新模块跟随父模块的写法（嵌套或平铺），其余条目的顺序与形状不动 | 议 | 草图编辑 |
| X7c | ID 生成：<br>- 模块 = 父 ID + 名称的 kebab-case 短名，无可转写时为 m1、m2…，可改。<br>- 关系 = `rel.<from 短名>-<to 短名>`，已被占用时加类型后缀 `-<type>`，仍冲突再加序号。<br>- 接口 = `if.<owner 短路径>.<名称>`。<br>同样的草图得到同样的 ID | 议（r2 评审改） | 草图编辑（寻址） |
| X7d | 移动 = 改父 + 改 ID，一个操作。新 ID 缺省为新父 ID + 原短名。级联改写后代 ID、关系两端、接口 owner、closed 与 mayDependOn 中的引用；关系与接口自身的 ID 不变。移动前预览影响 IdImpact（草图内改写条数、当前版本里引用旧 ID 的条数），有影响时二次确认。表单改 ID 只改短名，即父不变的移动，同一级联与确认；换父只能用「所属父」或拖动 | 议（r2 评审补） | 草图编辑（移动） |

| X7f | 校验 `validateSketch`：格式、ID 格式与唯一、前缀（X5）、引用完整（范围为本草图 ∪ 持久草图）、不连祖先与后代、层依赖无环、与持久草图矛盾（与 X4 共用 `sketchContradictions`）。error 拒绝保存，warning 只提示。编辑态每次操作后、保存前与写入端点调用同一函数。与 X4 的分工见上表 | 议 | 草图校验 · 描述写入 |
