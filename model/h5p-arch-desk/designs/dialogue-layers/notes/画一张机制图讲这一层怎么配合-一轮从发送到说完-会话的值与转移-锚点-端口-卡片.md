# 画一张机制图讲这一层怎么配合：一轮从发送到说完，会话的值与转移、锚点、端口、卡片

> 目标态 · 未实现 · 模块 state.desk.edit.dialogue.state · 2026-11-06T01:06:29.130Z

一轮的协调者只有一个：挂载点本身（createDialogue 的 dispatch）。其他框都不主动做事——值与转移只回答“下一个值是什么”，锚点只回答“挂在哪”，端口只声明边界，卡片派生只算显示数据，agent 通道只搬运。
> 对话会话：对话会话（DA-1、DA-2、DA-11，DL-12）：DialogueState 一个值——转录（每条带当时的锚点：用户、回答、错误、已停止）、锚点、视角、运行状态（空闲 / 运行中的轮次与流式片段）、排队的输入、草稿、模式（问 / 重讲）、会话编号；
只经纯转移函数 dialogueTransition 改变：发送（空闲开一轮，运行中进队列）、停止（这一轮不落，排队的退回草稿）、换锚点与换视角（转录不变）、agent 事件（片段累加、说完落一条并接着发队首、出错记错误卡、超时视同停止，别的轮次与停止后的迟到事件不认）；重讲只对模块，锚点不是模块时按「问」发；
协调（createDialogue）：选中 / 视角 → 换锚点；进入新的运行轮次 → 经注入的 AgentTransport 发一轮，停止 → 通知子进程；推送的事件 → 转移；给呈现层派生引用原文、梳理卡与锚点文字。当前版本上的会话只在内存。
机制图（DL-41–DL-43）：一轮说完时检查回答里的图块（当前版本上查描述，草图里查当前张），结果随条目留下、之后不重判；给呈现层派生图的显示数据与引用原文、存为设计说明的围栏块、设计说明正文的文字段与图段。

（推断）准备：创建会话时，协调者经端口 AgentTransport 调用通道的 subscribe(project)，从此推送都会变成 dispatch(event)。选中、步骤或当前张变了，协调者先用锚点的 anchorOf 推出新锚点，再发出 setAnchor。dialogueTransition 用 sameAnchor 判断锚点有没有变，没变就原样返回。
> agent 通道同步：同步适配器（DA-11）：AgentTransport 的 HTTP 实现——POST /agent/<项目>/turn 起一轮、/agent/<项目>/stop 停止；订阅开发服务器的推送 `arch-agent:event`，只把本项目的事件交回对话会话。只搬运，不改会话。

（推断）发送和流式输出：对话标签调用 send(input)。dialogueTransition 在空闲时开一轮，正在运行时把输入放进队列；modeFor 规定重讲只对模块有效。协调者发现进入了新的运行轮次，就经端口发 turn(AgentTurnRequest)。草图里还会经 DialogueSketchPort 带上设计与当前张。通道收到后 POST /agent/<项目>/turn。开发服务器推送 arch-agent:event，通道只把本项目的事件交回，dispatch(event) 再由转移把片段累加进 live。

（推断）说完（done，且轮次对得上）：先调用卡片派生的 checkDiagrams 检查图块。在当前版本上查描述，在草图里查当前张，结果随条目留下。草图里“改”的一轮再经 DialogueSketchPort.apply 把改动应用到编辑会话。之后转移落下一条，如果队列里还有输入，就取出队首重新进入发送那一步。停止时这一轮不落，排队的输入退回草稿，协调者再经端口发 stop(turn)。

（推断）呈现：对话标签只读会话，并通过协调者返回的函数取显示数据。citeViews、digest 和 diagram 由卡片派生向对话的模型（model.review.dialogue）要原文、梳理卡和图的检查结果；锚点条的文字来自 anchorText。对话的模型不在当前张上，所以图里只用文字写出，没有画成框。
